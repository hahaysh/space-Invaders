# 구현 계획 — 개선 릴리스

## 현재 작업: CHG-01

기준은 최초 로컬 체크포인트 `0162756`이며 아래의 M1~M3 기록은 과거 최초 작업이다.
개선판은 추적된 21개 원본 파일만 복사했다. 의존성·빌드·테스트 보고서는 복사하지 않았다.
변경 요청 → 영향 문서 → A 규칙 → B 입력·표시 → 전체 검증 순으로 진행한다.
이는 사용자 허용 범위의 자동 산출물 리허설이며 단계별 인간 승인·커밋은 수행하지 않는다.

| 작업 | 기준·의존 | 변경 파일 | 검증·완료 기준 | 상태 |
|---|---|---|---|---|
| A 상태·시간 | AC1/2/4/5, 문서 이후 | game.js, Node 테스트 | 35개 기존 검사 유지, paused 전체 값·쿨다운·키·반복 P 검사 | 완료 |
| B 입력·안내 | AC3~6, A 이후 | main.js, index.html, E2E | 정지 안내, 긴 정지 동결·재개 첫 프레임·10회 전환·blur | 완료 |
| 전체 회귀 | AC7, A/B 이후 | TEST_RESULTS, check-build, README | Node → E2E → build → 개선 하위 경로 검사 | 완료 |

새 폴더에 의존성이 없으므로 잠금 파일 기준 `npm ci`를 한 번 실행한다.
브라우저는 기존 설치를 사용하고 누락 실패일 때만 설치한다.
E2E 포트 충돌 시 다른 서버를 종료하지 않는다. 완료 후 상위 작업자의 검토·커밋을 기다린다.

## 최초 작업 기록

## 적용 방식

문서 → 구현 → 자동 검사 → 실패 수정·회귀 → 결과 기록 순으로 진행한다.
일반 워크숍은 작업마다 참가자 승인·커밋을 요구한다. 이번에는 사용자가 허용한
산출물 리허설 범위에서 이어서 실행하며 중간 인간 승인·검증·커밋을 꾸며내지 않는다.

| 작업 | REQ | 의존 | 변경 파일 | 완료 기준·검증 | 최초 상태 |
|---|---|---|---|---|---|
| M1 첫 조작 화면 | 01~03, 08 일부 | 문서 설계 | HTML, game/main/styles, 패키지·Vite·Playwright 설정 | title 시작, 이동 경계, 첫 발·간격, DOM; 관련 Node/E2E | 미착수 |
| M2 적·충돌 | 04~05 | M1 | game/main, 규칙 검사 | 24개, 경계 하강, 탄환 단일 명중·중복 점수 없음 | 미착수 |
| M3 종료·재시작 | 06~08 | M2 | game/main, 규칙·브라우저 검사 | 승패, 동결, 완전한 초기화, 회귀·빌드 | 미착수 |
| QA | 01~08 | M3 | TEST_PLAN, 테스트, TEST_RESULTS | `npm test`, `npm run test:e2e`, `npm run build` 실제 실행 | 미착수 |
| CI 예제 | 08 | QA | `.github/workflows/pages.yml` | guide 06-02와 경로·권한·의존성 대조, 원격 실행 제외 | 미착수 |

M1/M2/M3의 최종 코드를 한 샘플에 누적한다. 각 중간 버전별 실행 성공은 최종 검증으로 대신 주장하지 않는다.
작성 당시 상태는 위와 같으며 실제 진행·완료 증거는 아래에 나중에 기록한다.

각 중간 버전의 참가자 확인이나 커밋 완료를 뜻하지 않는다.

구현 전 문서·계획을 작성한 뒤 game/main/스타일·설정, 규칙·브라우저 검사 순으로 만들었다.
M1~M3 중간 버전을 따로 저장하거나 실행하지 않고 완성본을 검증했다.
QA에서 접근성 상태 선택자 모호성을 수정하고 정상 키 조작 승리·패배 및 빌드 하위 경로 검사를 보강했다.
위 최초 작업은 이후 `0162756`으로 커밋되었다. 현재 개선 완료 상태와 혼동하지 않는다.

## 개선 실제 진행

처음 문서를 작성할 때 작업 상태는 미착수였다. 실제 진행 뒤 위 표를 갱신했다.

1. CHANGE_REQUEST를 먼저 작성하고 최초 추적 파일 21개·별도 결과 기록만 복사했다.
2. PRD·TRD·계획·테스트 계획과 필요한 지침 경계를 코드보다 먼저 갱신했다.
3. A에서 P 전환 3줄과 순수 검사 7개를 추가했다. 새 폴더의 의존성을 `npm ci`로 복원한 뒤 **42/42** 통과.
4. B에서 P 입력 허용·정지 문구·조작 안내와 E2E 3개를 추가했다. 기존 자연 승패 검사에도 P 무시·종료 문구 확인을 덧붙였다.
5. 전체를 **Node 42/42 → Chromium 13/13 → 빌드 → 개선 하위 경로 검사** 순서로 실행해 통과했다.
6. 기존 35개 Node 테스트 본문, ideation·의존성·잠금·스타일·Vite·Playwright·workflow의 바이트 동일성을 확인했다.
7. paused PNG를 생성했고 테스트 서버 종료를 확인했다. 상세 결과와 미확인은 TEST_RESULTS에 기록했다.

별도 참가자 승인·중간 A/B 커밋은 만들지 않았다. 상위 작업자의 검토·개선 체크포인트 커밋 대기에서 멈춘다.
