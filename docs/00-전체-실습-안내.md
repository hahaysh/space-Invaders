## 참가자 저장소와 도구

안내 저장소를 복제하거나 샘플을 복사하지 않습니다.
참가자 자신의 빈 Public 저장소를 App 프로젝트로 연결합니다.
초기 메타데이터나 기준 커밋은 App이 만들 수 있으며, 기존 파일·커밋을 지우지 않습니다.
GitHub 계정·App 사용 권한, Git, 지원 중인 Node.js LTS, 브라우저가 필요합니다.
HTML/CSS/ES Modules와 Canvas 2D, Vite, Node 내장 테스트, Playwright를 사용합니다.
버전은 실제 환경과 호환되는 안정판을 선택하고 manifest와 lockfile로 고정합니다.
## 매 실습의 경계

1. App **Plan**에서 문서·계획을 검토합니다. 계획 확인 전에는 변경하지 않습니다.
2. 승인 후 App UI를 **Interactive**로 바꾸고 정해진 범위를 실행합니다.
3. diff·실행 결과·게임 화면을 사람이 확인합니다. 모두 맞으면 보완 프롬프트는 생략합니다.
4. 커밋·푸시·PR·병합·공개는 각 단계의 경계에서 검토 후 승인합니다.

프롬프트에 모드 이름을 적는 것만으로 App 모드가 바뀌지는 않습니다.
App 버전별 버튼 위치는 다를 수 있으므로 현재 화면의 기능명과 공식 문서를 확인합니다.
권한 요청은 대상과 명령을 읽고 필요한 범위만 허용합니다. 무조건적인 도구 사전 승인은 하지 않습니다.
GitHub 웹은 저장소·PR·Actions·Pages의 확인과 필요한 사람 승인을 위해 사용합니다.
허용된 App 도구/API가 도와도 **사람 UI 확인과 API 확인을 따로 기록**합니다.

## 작업의 연결

| 이슈 | 시작 기준 | 작업 범위와 종료 |
|---|---|---|
| 문서 준비는 이슈 없이 가능 | origin/main과 공통 이력이 있는 문서 브랜치 | 03-01 문서 PR을 먼저 main에 병합 |
| 기본 게임 | 문서가 병합된 최신 main | 한 이슈·세션에서 M1/M2/M3, 04-03 코드 PR |
| 검증과 첫 배포 | 기본 게임이 병합된 최신 main | 05~06 한 세션, 공개 확인 후 이슈 종료 |
| 일시정지 | 첫 배포가 끝난 최신 main | 07 설계·구현·검증·PR·재배포 |
| 난이도 / 목숨 확장 | 각각 직전 기능이 병합된 최신 main | 08 / 09마다 별도 이슈·새 기능 브랜치 |

이슈 본문은 목표·범위·완료 점검·관련 문서 링크면 충분합니다.
M1마다 이슈를 만들거나 세션을 갈아타지 않습니다. 실제 결함만 별도 버그 이슈로 만들 수 있습니다.
새 세션에서는 선택된 base, 현재 브랜치, 문서와 직전 기능의 존재를 확인합니다.
App 관리 기능 브랜치를 사용하며 이름 접두사는 App이 붙일 수 있습니다.
원격 main을 강제 덮어쓰기, 무작정 브랜치 이름 변경, 다른 worktree로 강제 전환하지 않습니다.

## 최소 산출물과 커스터마이징

`AGENTS.md`는 안전한 작업 규칙, `ideation.md`는 이유, `PRD.md`는 제품의 기준,
`TRD.md`는 기술 선택을 맡습니다. 같은 규칙을 여러 파일에 복사하지 않습니다.
참가자 저장소의 설명 문서와 `AGENTS.md`는 한국어 작성을 기본으로 하며,
코드 식별자·명령어·파일명·frontmatter 고정 키워드는 영어 원문을 유지합니다.
`IMPLEMENTATION_PLAN.md`의 짧은 표와 `TEST_PLAN.md`·`TEST_RESULTS.md`를 이어 사용합니다.
개선 요청·승인·공개 증거는 이슈에 남기고, 요구·설계가 달라지는 문서만 갱신합니다.

Pages workflow를 제외한 `.github` 실습은 **정확히 두 개**입니다.
04-03의 `github-app.yml`은 수동 실행 버튼, 05-01의 `skills/game-check/SKILL.md`는 검증 절차 재사용입니다.
Instruction·Prompt file·Custom agent·MCP·Hook·이슈/PR template 설치는 하지 않습니다.
AGENTS 파일의 존재나 명시적 읽기는 자동 지침 로딩의 증거가 아닙니다.
Skill 역시 App의 인식과 실제 호출을 확인해야 합니다.

## 기록과 막혔을 때

- 성공은 실제 실행만 기록합니다. 미실행·실패·환경 대기는 구분합니다.
- 서버는 시작한 세션이 PID·포트·URL을 관리합니다. 5173은 dev/E2E, 4173은 preview입니다.
- 포트 충돌은 소유자를 확인합니다. 모르는 프로세스를 종료하거나 전체 Node 프로세스를 죽이지 않습니다.
- 오래 멈춘 테스트는 로그·실행 환경을 남기고 해당 실행만 종료합니다. 호스트 원인을 단정하지 않습니다.
- 실패가 없으면 일부러 고장 내거나 가상의 버그 이슈를 만들 필요가 없습니다.

배포마다 공개 URL·커밋·Actions 링크·실제 확인 결과를 **먼저 원격 이슈 댓글**에 남깁니다.
로컬 문서에만 쓴 내용은 원격에 보존됐다고 말하지 않습니다.
06-03의 첫 배포 사이클 끝에서 README 실제 URL과 결과 요약을 **한 번의 기록 PR**로 모읍니다.
이후 기능 설명·직전 공개 근거는 다음 기능 PR에 함께 반영하고 최종 공개 근거는 이슈 댓글에 보존합니다.
그 PR이 재배포를 일으키면 같은 게임 코드의 공개 응답을 다시 확인하고 이슈 댓글만 갱신합니다.
다시 기록 PR을 만드는 무한 순환은 하지 않습니다. 종료 때 원격 반영분·남은 로컬 변경을 명시합니다.
