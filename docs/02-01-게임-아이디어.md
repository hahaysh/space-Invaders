# 02-01. 게임 아이디어

[이전](01-02-개발-문서와-작업-규칙.md) · [전체 목차](00-전체-실습-안내.md) · [다음: 요구사항 작성](02-02-요구사항-작성.md)

## 이번 실습

‘Space Invaders 스타일’을 짧게 즐길 수 있는 **우주 방어**라는 게임으로 좁힙니다.
후보를 비교하고 선택 이유를 남기면 구현 중 불필요하게 범위가 커지는 일을 막을 수 있습니다.
테마는 바꿀 수 있지만 뒤 실습에서 확인할 공통 기능은 유지합니다.

## 시작 전

- 문서 세션의 `AGENTS.md`를 확인했습니다.
- 문서 역할에 합의했고 아직 게임 코드는 없습니다.
- App **Plan**으로 아이디어를 논의합니다.

## 아이디어 제안

```text
AGENTS.md와 합의한 문서 역할을 확인해 줘.
초보자가 브라우저에서 짧게 즐기는 '우주 방어' 아이디어를 제안해 줘.
플레이어는 좌우로 움직이고 위로 발사해 내려오는 적 편대를 막아.
도형만으로 만드는 테마 후보 2개와 각각의 장단점을 간단히 비교해 줘.
기본 추천은 우주 방어이며 목표·핵심 재미·한 판 흐름·제외 범위를 정리해 줘.
적 탄환, 외부 이미지/CDN, 로그인, 사운드, 모바일 조작은 제외해 줘.
일시정지·난이도·목숨은 후속 개선으로만 구분하고 파일 생성 전에 멈춰 줘.
```

추천안으로 진행하면 다른 참가자와 수용 기준을 비교하기 쉽습니다.
제목이나 색상 선택은 게임 규칙 확장과 다릅니다.
여기서 구현할 기능 목록을 끝없이 늘리지 않습니다.

## 선택 후 작성

App을 **Interactive**로 전환합니다.

```text
추천한 '우주 방어'를 선택해. ideation.md를 짧게 작성해 줘.
대상 사용자·선택 이유·한 판 흐름·필수 경험·제외 범위를 남겨 줘.
처음 배포할 버전과 뒤에 추가할 개선을 구분하고 아직 코드는 만들지 마.
```

다음 내용이 자연스러운 한 판으로 이어지는지 읽어 봅니다.

| 순서 | 플레이 경험 |
|---|---|
| 시작 전 | 제목과 조작 안내를 보고 시작 |
| 진행 | 좌우 이동·발사, 적 이동·하강, 충돌·점수 |
| 종료 | 모두 제거하면 승리, 방어선 도달이면 패배 |
| 다시 하기 | 재시작하면 초기 상태의 새 게임 |

처음에는 일시정지가 없어도 괜찮습니다. 07에서 사용자의 개선 요청으로 추가합니다.
난이도와 목숨도 처음부터 미리 넣지 않습니다.
외부 샘플의 역사적 제목을 참가자의 새 게임 이름으로 바꿀 필요는 없습니다.

## 눈으로 확인

- [ ] 제목의 기본값은 `우주 방어`입니다.
- [ ] 대상 사용자와 선택 이유가 한두 문장으로 이해됩니다.
- [ ] 시작·진행·종료·재시작 흐름이 이어집니다.
- [ ] 적 탄환과 외부 자산 없이 도형으로 구현할 수 있습니다.
- [ ] 최초 버전과 선택 확장의 경계가 구분됐습니다.

## 필요할 때만 보완

```text
ideation.md에서 첫 버전에 불필요한 기능을 후속 후보로 옮겨 줘.
우주 방어의 한 판 흐름이 빠짐없이 이어지도록 설명만 보완해 줘.
```

전부 충족하면 다른 후보를 추가로 만드는 반복은 생략합니다.

## 완료

`ideation.md`를 검토했고 아이디어를 선택했습니다.
다음 단계에서 이 경험을 확인 가능한 요구사항으로 바꿉니다.
