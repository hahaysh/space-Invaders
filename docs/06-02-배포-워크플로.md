# 06-02. 배포 워크플로

[이전](06-01-Pages-배포-준비.md) · [전체 목차](00-전체-실습-안내.md) · [다음: PR과 첫 배포](06-03-PR과-첫-배포.md)

## 이번 실습

저장소의 실제 명령으로 검사·빌드한 결과만 Pages에 배포하게 합니다.
Copilot이 현재 프로젝트에 맞는 YAML을 만들며 긴 템플릿을 복사하지 않습니다.
PR은 검사만, 승인해 병합한 main은 배포까지라는 경계를 지킵니다.

## 시작 전

- 같은 검증·배포 세션에서 작업합니다.
- Pages source와 main 전용 환경 정책을 확인했습니다.
- manifest·lockfile과 실제 테스트·빌드 scripts가 있습니다.
- App **Plan**에서 워크플로를 설계합니다.

## 설계 프롬프트

```text
현재 package scripts·lockfile·TRD를 읽고 Pages workflow를 제안해 줘.
PR은 검사/빌드만, main push 또는 승인한 main workflow_dispatch만 배포하게 해 줘.
build에서 npm ci, 필요한 Chromium 준비, 실제 Node/E2E 검사와 build를 실행해 줘.
검증된 dist만 upload하고 deploy는 build 성공에 needs로 의존하게 해 줘.
deploy의 main/event 조건과 github-pages 환경을 명시해 줘.
기본 contents: read, 배포 job에만 pages: write와 id-token: write를 부여해 줘.
공식 action의 호환 안정 릴리스를 확인해 불변 전체 commit SHA로 고정해 줘.
출처 URL·버전·확인한 SHA 근거를 보여 주고 추측한 해시는 쓰지 마.
deploy job만 concurrency로 직렬화하고 cancel-in-progress: false로 해 줘.
아직 파일 생성·푸시·배포는 하지 말고 검토할 구조를 알려 줘.
```

Actions의 브랜치 조건은 실행 이벤트까지 함께 확인합니다.
PR 검사에서 배포 토큰 권한이나 환경 승인을 요구하지 않아야 합니다.
PR에서는 Pages 아티팩트 업로드/배포도 생략하고, 배포 가능한 main 실행에서만 업로드합니다.
`workflow_dispatch`는 다른 ref를 선택할 수도 있으므로 deploy의 main 조건이 별도로 필요합니다.
배포 환경의 main 전용 제한도 유지해 두 겹으로 잘못된 ref를 막습니다.

## 승인 후 작성

App을 **Interactive**로 전환합니다.

```text
검토한 설계를 승인해. .github/workflows/pages.yml을 작성해 줘.
공식 action SHA를 실제 조회해 검증하고 근거를 이슈 또는 PR 설명에 남겨 줘.
YAML/명령/권한/event 조건을 점검하고 로컬 검사·빌드를 실행해 줘.
원격 Actions에서 아직 실행하지 않은 항목은 미확인으로 보고하고 멈춰 줘.
```

SHA 고정은 공급망 변경 위험을 줄이지만 잘못된 SHA를 쓰면 실행되지 않습니다.
공식 저장소의 해당 릴리스가 가리키는 전체 commit을 확인하고 주석에 버전을 남길 수 있습니다.
조회가 막히면 추정값으로 진행하지 말고 확인 가능한 출처가 확보될 때까지 보류합니다.

## 검토할 구조

| 항목 | 확인할 내용 |
|---|---|
| 이벤트 | pull_request 검사, main push 배포, main 수동 실행만 배포 |
| build | lockfile 기반 설치 → 테스트 → 빌드 → main일 때 dist 업로드 |
| deploy | build 성공 의존, main/event 조건, github-pages 환경 |
| 권한 | 읽기는 기본, Pages/OIDC 쓰기는 deploy만 |
| 동시 실행 | deploy 전용 고정 그룹, 취소하지 않고 순서대로 처리 |

workflow 전체에 취소 가능한 concurrency를 두어 진행 중 배포를 끊지 않습니다.
`pull_request_target`으로 PR 코드를 높은 권한에서 실행하지 않습니다.
환경 승인 대기는 실패도 성공도 아니며, 필요한 사람이 승인할 때까지 기다립니다.
잠금 파일은 커밋하고 CI 설치에는 `npm ci`를 사용합니다.

## 눈으로 확인

- [ ] 실제 scripts가 실행되고 실패하면 build/배포가 중단됩니다.
- [ ] PR은 배포하지 않으며 main 이벤트에만 upload/deploy 경로가 열립니다.
- [ ] 공식 action의 전체 SHA를 실제 검증한 근거가 있습니다.
- [ ] dist만 게시하고 최소 권한·needs·main 환경 제한이 유지됩니다.
- [ ] 배포만 직렬화하며 실행 중 배포를 취소하지 않습니다.

## 필요할 때만 보완

```text
지적한 workflow 조건이나 권한만 최소 수정해 줘.
PR과 main push/수동 실행 각각의 경로를 다시 설명하고 검증해 줘.
환경 보호를 제거하거나 action SHA를 추정하지 마.
```

## 완료

검토한 workflow와 관련 문서를 같은 브랜치에 커밋합니다.
실제 원격 CI와 공개 게임 확인은 다음 실습에서 수행합니다.
