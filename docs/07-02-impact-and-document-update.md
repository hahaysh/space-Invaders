# 07-02. 영향 분석과 필요한 문서 수정

**7. 개선 사이클 · 변경 설계**

이전: [07-01 변경 요청](07-01-change-request.md) · [전체 목차](00-overview.md) · 다음: [07-03 변경 구현](07-03-change-implementation.md)

## 1. 설명

P 키 한 개를 추가해도 상태 전환, 입력, 프레임 시간과 테스트가 영향을 받습니다.
코드부터 바꾸지 않고 **CHG-01 → 문서 → 코드 → 검증**의 영향을 먼저 추적합니다.
모든 문서를 의무적으로 수정하는 것이 목표는 아닙니다.
책임이 달라진 문서만 고치고 수정 불필요 판단도 근거와 함께 남깁니다.

`ideation.md`는 초기 선택 배경, `AGENTS.md`는 작업 지침입니다.
이번 요청이 게임의 방향이나 작업 규칙을 바꾸지 않으면 그대로 둡니다.
파일을 읽고 참조한 것과 파일을 수정한 것을 구분합니다.

## 2. 시작 상태

- [ ] CHG-01 수용 기준이 승인되었고 `CHANGE_REQUEST.md`에 있다.
- [ ] 최신 `main`을 기반으로 개선 작업 브랜치가 준비되었다.
- [ ] 기존 문서·코드·최초 테스트 결과가 보존되어 있다.
- [ ] **Plan** 모드이며 아직 P 기능 구현은 시작하지 않는다.

## 3. 실행: 영향 분석

```text
AGENTS.md, ideation.md, PRD.md, TRD.md, IMPLEMENTATION_PLAN.md,
TEST_PLAN.md, TEST_RESULTS.md, CHANGE_REQUEST.md와 관련 코드를 읽어줘.
CHG-01의 영향 분석만 수행한다. 파일 수정·설치·커밋은 하지 마.

수용 기준 ID별로 현재 구조, 필요한 변경, 영향 파일, 검증 방법을 연결해줘.
상태 전환, 키 입력, blur, RAF와 dt, 발사 쿨다운, 렌더링을 빠뜨리지 마.
문서별 '수정 필요 / 수정 불필요 / 추가 확인'과 이유를 표로 제시해줘.
PRD는 제품 동작, TRD는 구현 설계, 계획은 작업 순서,
테스트 계획은 확인 절차, 결과는 실제 실행 증거를 담당하게 해줘.
ideation과 AGENTS는 책임이 바뀔 때만 수정하고 단순 참조는 수정으로 세지 마.
최초 결과를 보존하면서 CHG-01 검증 예정 영역을 분리하는 방법도 제안해줘.
아직 코드를 바꾸거나 다음 구현 단계를 시작하지 말고 승인을 기다려줘.
```

### 문서별 예상 판단

| 문서 | 이번 변경에서 다룰 내용 |
|---|---|
| `CHANGE_REQUEST.md` | 영향 분석 결론과 승인 결정 연결 |
| `PRD.md` | CHG-01 수용 기준과 기존 요구사항 유지 명시 |
| `TRD.md` | paused 상태, 시간 정지, 입력 해제, 단일 루프 설계 |
| `IMPLEMENTATION_PLAN.md` | 작은 변경 단위, 의존성, 변경 파일과 완료 조건 |
| `TEST_PLAN.md` | CHG-01 경계 테스트와 REQ-01~08 회귀 항목 |
| `TEST_RESULTS.md` | 최초 결과 유지, 개선 검증은 미실행으로 구분 |
| `ideation.md` | 초기 방향이 같다면 수정 불필요와 이유 |
| `AGENTS.md` | 기존 승인·검증 규칙이 충분하면 수정 불필요와 이유 |

“변경 없음” 결론은 변경 요청의 영향 분석 절에 남길 수 있습니다.
수정 불필요인 파일에 “이번에 수정하지 않음” 한 줄을 추가해서 변경을 만들지 않습니다.

### 설계에서 확인할 상태 전환

| 입력·상황 | 이전 → 이후 | 설계 조건 |
|---|---|---|
| 최초 P keydown | playing → paused | held keys 비우기, 게임 업데이트 중지 |
| 최초 P keydown | paused → playing | held keys 비우기, RAF 시간 기준 초기화 |
| 반복 P keydown | 상태 유지 | `event.repeat` 무시 |
| P | title/won/lost → 동일 상태 | 시작·재시작으로 해석하지 않음 |
| blur | 상태 유지 | held keys 비우기, 자동 pause 기능은 추가하지 않음 |

정지 화면을 그리는 것과 시뮬레이션을 업데이트하는 것은 다릅니다.
렌더 루프를 유지하더라도 게임 시간과 쿨다운은 증가하지 않아야 합니다.
키 상태를 비운 뒤 재개할 때는 새로 누른 입력만 반영하도록 설계합니다.

### 승인 후 문서 반영

분석표를 확인한 뒤 **Interactive**로 전환합니다.

```text
방금 검토한 CHG-01 영향 분석과 문서 수정 범위를 승인한다.
수정 필요로 합의한 문서만 갱신하고 수정 불필요 문서는 그대로 둬.
PRD의 요구사항 ID를 TRD·구현 계획·테스트 계획에 연결해줘.
paused 전환, 게임 시간/쿨다운 정지, held keys, RAF 기준 초기화,
단일 루프와 제목/종료 화면의 P 무시를 빠뜨리지 마.
TEST_RESULTS.md에는 개선 검증을 미실행으로 준비하고 최초 증거를 보존해줘.
CHANGE_REQUEST.md에 수정/미수정 문서와 이유를 남겨줘.
코드·테스트 코드·의존성·워크플로는 수정하지 마.
diff와 수용 기준 연결표를 보여주고 기다려줘.
```

### 예상 결과

영향 분석표와 필요한 문서의 diff가 생깁니다.
테스트 계획은 확장되지만 실제 통과 결과는 아직 늘어나지 않습니다.
“P 지원 완료” 대신 “CHG-01 설계 승인, 구현 예정”처럼 상태를 명확히 표시합니다.

## 4. 함께 점검·확인

- [ ] CHG-01의 모든 수용 기준에 설계·작업·테스트가 연결된다.
- [ ] 최초 버전 상태 설명과 개선 후 상태 설명이 서로 모순되지 않는다.
- [ ] REQ-01~08과 기존 수치·종료 조건을 유지한다.
- [ ] 쿨다운을 벽시계 시간만으로 계산해 정지 중 줄어드는 설계가 없다.
- [ ] 재개마다 새 RAF 루프를 시작하는 계획이 없다.
- [ ] 테스트 결과에 미래 테스트를 통과로 기록하지 않았다.
- [ ] `ideation.md`·`AGENTS.md`의 미수정 사유가 정직하게 기록되었다.

```text
수정된 문서만 읽고 CHG-01 기준별 누락·충돌·중복을 검토해줘.
REQ-01~08의 수용 기준이 약화되거나 삭제됐는지도 비교해줘.
충족/보완 필요/미확인을 근거와 함께 표시하고 추가 수정은 기다려줘.
```

## 5. 보완과 재확인

```text
방금 발견한 문서 불일치만 승인 범위에서 보완해줘.
PRD에 구현 세부가 과도하면 TRD로 옮기고 요구사항 ID로 연결해줘.
실행하지 않은 테스트 결과는 미실행으로 고치고 최초 결과는 보존해줘.
수정 불필요 문서를 형식적으로 바꾸지 마. 코드 작성은 하지 마.
수정 후 영향을 받은 수용 기준 연결을 다시 확인해줘.
```

## 6. 완료 승인

```text
CHG-01 영향 분석과 필요한 문서 변경을 승인한다.
승인 파일만 구체적인 한국어 제목과 본문으로 로컬 커밋해줘.
제목 예시: '07-02: 일시정지 영향 분석에 따라 설계와 구현·회귀 검증 계획 갱신'
본문에 단계 ID 07-02와 CHG-01, 변경 내용·이유, 수정 불필요 판단을 적어줘.
문서 정합성 검토 결과와 아직 미수행인 구현·테스트 등 미확인 범위를 명시해줘.
아직 구현·테스트 실행·푸시는 하지 말고 다음 실습을 기다려줘.
```
