# 03-02. 작업 지침 보완과 설계 승인

**3. 점검 · 구현 준비 기준 확정**

이전: [03-01 문서 점검](03-01-document-review.md) · [전체 목차](00-overview.md) · 다음: [04-01 구현 계획](04-01-implementation-plan.md)

## 1. 설명

기술 설계가 정해졌으므로 최소 지침에 실제 작업 경계와 검증 명령을 보완합니다.
`AGENTS.md`에는 PRD 전체를 복제하지 않고 **문서를 읽는 순서·승인·변경 범위·검증·보고 규칙**을 둡니다.
설계 승인은 구현을 한꺼번에 맡기는 허가가 아닙니다. 다음 단계에서도 작은 작업마다 승인을 받습니다.

이번 산출물은 보완한 `AGENTS.md`와 `TRD.md`의 설계 승인 기록입니다.
별도의 승인서 파일이나 Custom agent 설정은 만들지 않습니다.

## 2. 시작 상태

- [ ] 03-01 문서 점검을 마쳤고 구현을 막는 문제가 없다.
- [ ] `ideation.md`, `PRD.md`, `TRD.md`의 기준이 일치한다.
- [ ] 보류 사항이 있다면 이유와 확인 시점을 설명할 수 있다.
- [ ] 자신의 Copilot app 세션에서 **Plan** 모드를 선택했다.

## 3. 실행: 지침 수정안을 검토하고 승인 기록 남기기

### 3-1. Plan에서 보완안 받기

```text
AGENTS.md, ideation.md, PRD.md, TRD.md와 직전 문서 점검 결과를 읽어줘.
파일 변경·설치·구현·커밋·푸시 없이 구현 준비 상태를 검토하자.
AGENTS.md의 기존 규칙을 존중하면서 필요한 보완안만 변경 전후로 제시해줘.

다음 작업 규칙을 포함해줘.
- 시작 전 저장소·세션 브랜치·기존 변경을 확인하고 사용자 변경을 보호한다.
- AGENTS.md와 작업 관련 PRD/TRD/계획을 명시적으로 읽는다.
- Plan에서는 읽기 전용 논의, 승인 뒤 Interactive에서 지정된 파일만 변경한다.
- 작은 작업의 목표·REQ·변경 파일·검증·중단 지점을 먼저 제안한다.
- 미승인 기능, 대규모 재구성, 요구사항 완화, 자동 다음 단계 진행을 하지 않는다.
- 고정 스택은 Node24, vanilla ES modules/Canvas2D, Vite, node --test, Playwright다.
- npm test는 node --test tests/*.test.js, E2E는 npm run test:e2e로 분리한다.
- manifest 전 설치 금지, 최초 lockfile 생성 후에는 npm ci를 사용한다.
- Playwright 의존성 뒤 Chromium을 설치하고 서버는 127.0.0.1에 바인딩한다.
- 실제 수행한 검증만 통과/실패로, 실행하지 못한 검증은 미확인으로 보고한다.
- 커밋은 참가자 검토 뒤 승인된 변경만, 푸시·PR·병합·배포는 별도 승인받는다.
- 커밋 메시지는 항상 너무 짧지 않은 한국어 설명형 제목과 본문으로 작성한다.
  본문에는 단계 ID, 변경 내용과 이유, 실제 검증 결과와 미확인 범위를 포함한다.
- 토큰·개인정보·생성된 보고서의 민감 정보는 Public 저장소에 넣지 않는다.

AGENTS.md에 수치 전체나 테스트 결과를 복제하지 말고 PRD/TRD를 참조해줘.
이 파일은 Custom agent 정의가 아니며 자동 적용을 검증했다고 주장하지 마.
TRD.md 끝에 넣을 짧은 '설계 승인' 절도 대화에 제안해줘.
승인 범위 REQ-01~08, 최초 제외 범위, 설계 검토 상태,
보류 사항, 다음 허용 작업(구현 계획 작성), 실제 구현·테스트 미수행을 구분해줘.
참가자의 최종 승인 전에는 '승인됨'이라고 기록하지 마.
마지막에 진행 가능/보완 필요와 그 근거를 제시하고 기다려줘.
```

참가자는 지침이 기술 설계와 맞는지, 모든 작업을 자동 실행하도록 해석될 문장이 없는지 읽습니다.
기존 `AGENTS.md`의 승인 규칙이 더 엄격하면 검토 없이 완화하지 않습니다.

### 3-2. Interactive에서 지침과 승인 기록 저장하기

모든 준비 기준을 충족하면 모드를 바꾸고 입력합니다.

```text
문서 점검 결과, 방금 제안한 지침 보완안과 REQ-01~08 기술 설계를 승인한다.
AGENTS.md의 승인한 보완만 반영하고 TRD.md의 설계 승인 절만 추가·갱신해줘.
승인 기록에는 최초 버전 범위와 제외 범위, 남은 보류 사항을 적어줘.
승인일은 확인 가능한 현재 날짜를 사용하고 확인하지 못하면 추정하지 마.
아직 구현과 실행 테스트를 하지 않았으며 다음 단계는 구현 계획 검토라고 기록해줘.
PRD/아이디어/코드/패키지는 바꾸지 마.
수정 뒤 AGENTS.md를 명시적으로 다시 읽고 적용할 작업 규칙을 요약해줘.
diff를 보여준 뒤 멈추고 커밋·푸시·설치·구현은 하지 마.
```

`AGENTS.md`를 다시 읽게 하는 것은 지침을 대화에서 확인하는 절차입니다.
대상 app이 변경된 지침을 자동으로 로드하는지 확인한 결과로 해석하지 않습니다.

### 예상 결과

- 승인·검증·문서 참조 규칙을 보완한 루트 `AGENTS.md`.
- 설계 승인 범위와 실제 구현 미수행을 명시한 `TRD.md`의 짧은 기록.
- 다음 단계에서 할 일과 하지 않을 일을 구분한 응답.

## 4. 함께 점검·확인

| 점검 항목 | 충족 기준 |
|---|---|
| 지침 책임 | PRD의 게임 수치를 대량 복제하지 않고 기준 문서를 참조한다. |
| 승인 경계 | 구현 계획 승인과 실제 구현 승인을 구분한다. |
| 기술 정합성 | 스택·명령·설치 순서가 TRD와 같다. |
| 기록 정확성 | 설계 승인이지 게임 테스트 통과·배포 완료가 아니다. |
| 변경 범위 | `AGENTS.md`와 TRD의 승인 절만 바뀌었다. |

```text
Plan에서 두 파일의 diff와 PRD/TRD를 읽기 전용으로 검토해줘.
자동 구현으로 해석되는 문장, 명령 충돌, 거짓 완료 기록이 있는지 확인해줘.
각 항목을 충족/보완 필요/미확인으로 표시하고 근거를 제시해줘.
파일은 수정하지 말고 다음 구현을 시작하지 마.
```

## 5. 보완과 재확인

```text
AGENTS.md가 너무 길거나 요구사항을 복제하고 있어.
승인·범위·문서 참조·검증·보고 규칙만 남기는 보완안을 Plan에서 제시해줘.
더 엄격한 기존 보호 규칙은 유지하고 테스트 성공을 추정한 문장도 바로잡아줘.
파일 수정은 내가 승인할 때까지 기다려줘.
```

수정안을 승인한 뒤 Interactive에서 대상 절만 반영하고, `AGENTS.md`를 다시 읽도록 요청합니다.
설계 자체가 바뀌어야 한다면 03-01의 정합성 검토로 돌아가 승인 기록도 함께 갱신합니다.

## 6. 완료 승인

- [ ] 참가자가 최초 구현 범위와 후속 CHG-01을 구분할 수 있다.
- [ ] 지침 보완과 설계 승인 기록이 실제 파일로 저장되었다.
- [ ] 실제 테스트 결과는 아직 없다는 점을 확인했다.

```text
지침과 설계 승인 기록의 diff를 확인했다.
검토한 AGENTS.md와 TRD.md 변경만 커밋하고 결과를 알려줘.
메시지는 너무 짧지 않은 한국어 설명형 제목과 본문으로 작성하고,
본문에 03-02 단계 ID, 변경 내용과 이유, 지침·설계 검토 결과와 실행 검증 미수행 범위를 적어줘.
푸시하거나 구현하지 말고 다음 구현 계획 요청을 기다려줘.
```

변경이 없다면 빈 커밋을 만들지 않습니다. 다음 단계는 계획 문서 작성이지 게임 전체 생성이 아닙니다.
