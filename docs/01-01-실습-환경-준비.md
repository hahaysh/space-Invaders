# 01-01. 실습 환경 준비

[전체 목차](00-전체-실습-안내.md) · [다음: 개발 문서와 작업 규칙](01-02-개발-문서와-작업-규칙.md)

## 이번 실습

자신의 빈 Public 저장소를 GitHub Copilot App에 연결합니다.
게임 파일을 만들기 전에 저장소와 브랜치를 확인하면 다른 작업을 실수로 바꾸는 일을 줄일 수 있습니다.
샘플이나 안내서 파일을 참가자 저장소로 복사하지 않습니다.

## 시작 전

- GitHub 계정과 Copilot App 사용 권한이 있습니다.
- Git, 지원 중인 Node.js LTS, 최신 브라우저가 필요합니다.
- 공개 저장소에 올려도 되는 프로젝트 이름을 정합니다.
- App에서 프로젝트 추가와 새 세션 기능을 사용할 수 있는지 확인합니다.

## App에서 준비

GitHub 웹에서 새 **Public** 저장소를 만듭니다.
가능하면 README·라이선스·gitignore 자동 생성을 선택하지 않고 빈 상태로 시작합니다.
이미 생긴 파일이나 영어 `Initial commit`은 삭제·재작성하지 않습니다.
App에 해당 저장소를 프로젝트로 추가하고 **Plan** 세션을 엽니다.

```text
이 참가자 저장소에서 '우주 방어' 실습을 준비하려고 해.
저장소 주소, 작업 공간, 현재 브랜치, 원격 origin과 main 상태를 확인해 줘.
Git·Node·npm 버전과 App에서 실행 가능한 개발 환경도 확인해 줘.
파일 없는 저장소라면 main 기준 커밋을 만드는 최소 준비 방법을 제안해 줘.
App이 만든 메타데이터·기존 파일·Initial commit은 보존해 줘.
origin/main과 공통 이력이 있는 문서 작업용 새 세션/브랜치 경로를 제안하고,
아직 게임 파일 생성이나 설치·푸시를 실행하지 말아 줘.
```

App이 빈 원격 저장소 연결을 지원하지 않는다면 오류를 그대로 확인합니다.
권한이 있는 도구로 최소 기준 커밋을 만들고 main에 올리는 준비를 승인할 수 있습니다.
이때 게임 소스나 개발 문서를 미리 생성할 필요는 없습니다.
초기화·원격 등록을 반복해 이력을 갈라놓지 않습니다.

## 승인 후 실행

대상 저장소가 맞으면 **Interactive**로 전환합니다.

```text
확인한 이력을 보존하며 필요한 최소 초기 준비만 실행해 줘.
원격 main과 공통 이력을 확인한 뒤 App 관리 문서 작업 브랜치를 준비해 줘.
완료된 원격 작업과 현재 세션/base/브랜치를 알려 주고 멈춰 줘.
```

초기 main이 아직 없다면 이 단계의 원격 기준 생성만 승인합니다.
그 뒤 문서 작업은 main이 아닌 새 기능 세션에서 진행합니다.
예시 이름은 `docs-game-plan`이며 App 접두사가 붙어도 괜찮습니다.
버튼 이름이 다르면 App의 프로젝트·세션 메뉴와 공식 도움말을 확인합니다.

## 눈으로 확인

- [ ] GitHub의 Public 저장소 주소와 App의 프로젝트가 같습니다.
- [ ] 원격 main이 존재하고 현재 브랜치와 공통 이력이 있습니다.
- [ ] 현재 세션은 문서 작업용 브랜치이며, 기존 작업이 보존됐습니다.
- [ ] Node·npm 실행 가능 여부와 실제 버전이 보고됐습니다.
- [ ] 게임 코드·샘플 복사·불필요한 설치가 없습니다.

## 막혔을 때만

```text
현재 오류와 저장소/브랜치 상태를 다시 확인해 줘.
삭제·재초기화·강제 푸시 없이 원인을 설명하고 최소 복구 방법을 제안해 줘.
권한이나 App UI에서 내가 해야 할 행동은 구분해서 알려 줘.
```

명령이 없거나 인증이 실패하면 해당 환경만 준비한 뒤 같은 확인을 반복합니다.
다른 저장소가 열려 있다면 그곳을 바꾸지 말고 올바른 프로젝트를 선택합니다.

## 완료

문서 작업 세션에서 main과 연결된 출발점을 확인했습니다.
아직 게임 구현이나 의존성 설치를 하지 않습니다.
다음 실습은 이 문서 세션을 그대로 사용합니다.
