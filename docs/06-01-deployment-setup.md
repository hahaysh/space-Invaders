# 06-01. Pages 설정과 공개 범위·권한 확인

**6. 배포 · 배포 준비**

이전: [05-02 결함 수정과 회귀 검증](05-02-fixes-and-regression.md) · [전체 목차](00-overview.md) · 다음: [06-02 Actions 워크플로](06-02-actions-workflow.md)

## 1. 설명

로컬에서 실행되는 게임과 인터넷에 공개된 게임은 다릅니다.
이번 단계에서는 **무엇을 공개하고 어떤 브랜치에서 배포할지** 먼저 결정합니다.
GitHub Pages에는 Vite가 만든 `dist`만 올립니다.
다만 Public 저장소의 소스·문서·커밋 이력은 이미 별도로 공개됩니다.
배포에서 문서를 제외했다고 저장소의 문서까지 비공개가 되는 것은 아닙니다.

기본 흐름은 작업 세션 브랜치 → PR → 검토·명시적 병합 → `main` 배포입니다.
세션 브랜치는 `main`과 같다고 가정하지 않습니다.
설정 변경, 푸시, PR 생성, 병합은 서로 다른 승인 대상입니다.
이 단계에서는 Pages 설정만 승인하며 실제 배포는 하지 않습니다.

## 2. 시작 상태

- [ ] 05-02에서 REQ-01~08 검증과 결함 수정이 승인되었다.
- [ ] `TEST_RESULTS.md`에 실제 결과와 남은 미확인 항목이 있다.
- [ ] 루트에 `package.json`, 잠금 파일, Vite 설정이 있다.
- [ ] Node.js 24 LTS와 개발·테스트·빌드 명령을 확인했다.
- [ ] Public 저장소 관리자 또는 Pages 설정 권한이 있다.
- [ ] 기존 작업 세션을 열고 **Plan** 모드를 선택했다.

권한이 없으면 저장소 관리자에게 이 단계의 설정만 요청합니다.
토큰을 대화에 붙여 넣거나 권한을 광범위하게 늘리지 않습니다.

## 3. 실행: 읽기 전용 준비 점검

```text
AGENTS.md, TRD.md, TEST_PLAN.md, TEST_RESULTS.md와 현재 빌드 설정을 읽어줘.
GitHub Pages 배포 준비만 점검한다. 파일과 원격 설정은 변경하지 마.
현재 저장소, 작업 공간, 브랜치, 원격 저장소, 실제 기본 브랜치를 확인해줘.
git 상태 조회는 허용하지만 fetch·설치·커밋·푸시·PR·병합은 하지 마.

다음을 충족/보완 필요/미확인으로 분류해줘.
- Node.js 24 LTS, npm ci용 잠금 파일
- npm test가 tests/*.test.js를 선택하며 e2e와 분리되는지
- npm run test:e2e, build, dev, preview 스크립트
- Vite base './', 빌드 출력 dist, 런타임 외부 CDN/에셋 의존성 없음
- 배포 산출물에 문서·테스트·샘플·비밀 정보가 들어가지 않는지
- REQ-08 정적 배포 기준과 공개 전 미해결 결함
Public 저장소 자체의 공개와 Pages 사이트 공개를 구분해 설명해줘.
기본 브랜치가 main이 아니면 임의 변경하지 말고 차이를 알려줘.
내가 GitHub 웹에서 수행할 설정과 필요한 권한을 제안하고 기다려줘.
```

### GitHub 웹에서 설정하기

1. 대상 저장소의 소유자와 이름을 확인합니다.
2. **Settings → Pages → Build and deployment**를 엽니다.
3. 공개될 내용과 권한을 검토한 뒤 **Source → GitHub Actions**를 선택합니다.
4. 제안된 자동 템플릿을 바로 커밋하지 않습니다. 다음 단계에서 작성합니다.
5. **Settings → Environments → github-pages**를 확인합니다.
6. 환경이 없다면 설정 권한으로 `github-pages` 환경을 만듭니다.
7. 배포 브랜치 규칙을 **Selected branches and tags**로 설정하고
   브랜치 규칙 `main`을 허용합니다. 같은 이름의 태그 허용은 추가하지 않습니다.
8. 필요한 환경 승인자가 있다면 승인 절차를 유지하고 대기 가능성을 기록합니다.

실제 기본 브랜치가 다르면 먼저 진행자와 기준을 통일합니다.
다른 환경이나 조직 보호 규칙을 삭제해서 해결하지 않습니다.
GitHub UI 문구는 버전에 따라 다를 수 있으므로 Source와 허용 브랜치 값을 확인합니다.
페이지 설정만으로 사이트가 배포되었다고 기록하지 않습니다.

### 예상 결과

| 항목 | 기대 상태 |
|---|---|
| 게시 소스 | GitHub Actions |
| 배포 환경 | `github-pages`, 배포 브랜치 `main` |
| 배포 내용 | `dist`의 HTML·CSS·JS 등 게임 실행 파일 |
| 공개 승인 | 참가자가 저장소와 사이트 공개 범위를 확인함 |
| 이번 산출물 | 설정 확인과 준비 점검 요약, 아직 배포 URL 증거 없음 |

## 4. 함께 점검·확인

- [ ] 저장소 설정을 실제로 확인했으며 추정으로 완료 표시하지 않았다.
- [ ] `dist`를 만들어 내는 Vite 입력에 실습 문서나 샘플이 포함되지 않는다.
- [ ] 민감 정보는 `.gitignore` 추가만으로 과거 이력에서 사라지지 않음을 이해한다.
- [ ] 설정 변경 승인과 외부 푸시 승인이 별도임을 이해한다.
- [ ] 배포 권한은 이후 배포 job에만 부여하기로 했다.
- [ ] 워크플로가 아직 없으므로 Actions 성공이나 공개 URL을 만들어 기록하지 않았다.

```text
내가 확인한 Pages Source와 환경의 허용 브랜치를 기준으로 준비 상태를 요약해줘.
실제 확인하지 못한 원격 설정은 미확인으로 남겨줘.
이번 설정만으로 게임이 배포된 것으로 표현하지 마.
파일 변경이 필요한 항목은 다음 단계의 승인 대상으로 분리하고 기다려줘.
```

## 5. 보완과 재확인

### 설정 메뉴가 없거나 권한 오류가 있는 경우

```text
Pages 설정을 완료하지 못했다. 현재 오류와 내 권한을 기준으로 원인을 구분해줘.
저장소 종류, 관리자 권한, 조직 정책 중 확인할 항목만 제안해줘.
토큰 입력이나 전체 쓰기 권한 부여, 보호 규칙 해제를 요구하지 마.
설정은 미확인 상태로 남기고 배포를 시작하지 마.
```

### 공개하면 안 되는 내용이 발견된 경우

```text
공개 준비를 중단한다. 민감한 값 자체는 출력하지 말고 해당 파일 경로만 알려줘.
로컬 미커밋 내용인지 이미 공개된 이력인지 구분해 대응안을 제안해줘.
이미 노출된 자격 증명은 폐기·교체 필요성을 안내해줘.
승인 없이 파일 삭제, 이력 재작성, 강제 푸시를 하지 마.
```

## 6. 완료 승인

```text
Pages 설정과 공개 범위 점검을 승인한다.
확인한 게시 소스, 환경 규칙, 공개 대상, 남은 준비 작업을 대화에 요약해줘.
파일 변경이 없다면 빈 커밋을 만들지 마.
워크플로 작성·푸시·배포는 아직 하지 말고 다음 실습 프롬프트를 기다려줘.
```

설정과 파일 변경은 별개입니다. 이번 단계의 원격 설정에는 Git 커밋이 생기지 않습니다.
설정 근거는 [Pages 게시 소스](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)와
[사용자 정의 워크플로](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)를 참고합니다.
