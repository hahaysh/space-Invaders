# 07-01. 일시정지·재개 요청과 수용 기준

**7. 개선 사이클 · 변경 요청**

이전: [06-03 최초 배포 확인](06-03-deploy-and-check.md) · [전체 목차](00-overview.md) · 다음: [07-02 영향 분석과 문서 수정](07-02-impact-and-document-update.md)

## 1. 설명

“잠깐 멈출 수 있으면 좋겠다”는 피드백을 바로 구현하면 중요한 조건이 빠집니다.
정지 중 적과 발사 대기시간도 멈추는지, 재개 시 눌린 키가 남는지 합의해야 합니다.
이번 단계는 **CHG-01: P 키 일시정지·재개**의 요청과 수용 기준만 작성합니다.
기존 REQ-01~08은 유지하고 최초 버전을 개선 전 비교 기준으로 남깁니다.

루트 `CHANGE_REQUEST.md`를 이 단계에서 **새 변경 산출물**로 추가합니다.
처음 정한 개발 문서가 부족했다는 뜻이 아니라 배포 후 요청을 추적할 필요가 생긴 것입니다.
기존 PRD의 변경 요청 절을 쓰는 방식도 가능하지만 이 실습은 별도 파일을 기본으로 합니다.
확정 요구사항은 다음 단계에서 PRD에 반영하고 요청 파일은 배경·결정 이력을 담당합니다.

## 2. 시작 상태

- [ ] 최초 버전의 배포 SHA·실제 공개 URL·검증 결과가 있다.
- [ ] 배포 확인 기록의 로컬 커밋과 미푸시 변경 위치를 알고 있다.
- [ ] 기존 작업 세션에서 **Plan** 모드로 시작한다.
- [ ] 병합된 옛 기능 브랜치에서 바로 다음 코드를 쓰지 않는다.

### 병합 후 작업 기준 맞추기

```text
읽기 전용으로 현재 브랜치, 작업 상태, main과의 관계를 확인해줘.
최초 PR의 병합 방식과 배포 후 TEST_RESULTS.md 기록 커밋 위치도 확인해줘.
이전 기능 브랜치를 그대로 재사용할 때의 위험과 안전한 동기화 계획을 제안해줘.
아직 fetch·checkout·merge·cherry-pick·파일 수정은 하지 마.
사용자 변경이나 기록 커밋을 버리는 reset, clean, 강제 푸시는 금지한다.
```

참가자가 보존할 커밋과 새 작업 브랜치 이름을 확인하고 **Interactive**로 바꿉니다.

```text
검토한 동기화 계획을 승인한다. 원격 fetch를 허용한다.
같은 세션 작업 공간에서 최신 origin/main을 기준으로 새 개선 브랜치를 만들어줘.
최초 배포 기록처럼 아직 main에 없는 필요한 로컬 커밋만 검토 후 보존해줘.
이미 병합된 커밋을 전부 다시 적용하지 마. 충돌하면 멈추고 내용을 보여줘.
브랜치 전환이 app에서 지원되지 않으면 임의로 우회하지 말고 알려줘.
푸시·PR·요구사항 작성은 아직 하지 마.
```

세션 내 전환이 어려우면 최신 `main` 기반 새 세션을 사용합니다.
새 세션에 `AGENTS.md`와 개발 문서, 배포 SHA·URL, 승인 요약을 명시적으로 전달합니다.
미반영 기록 커밋은 원래 작업 공간에 보존하고 검토한 변경만 옮깁니다.
세션 변경 자체가 이전 대화·작업 파일의 자동 전달을 보장하지 않습니다.

## 3. 실행: 요청 구체화

다시 **Plan** 모드를 선택하고 요구사항을 검토합니다.

```text
AGENTS.md, PRD.md, TRD.md, TEST_RESULTS.md를 읽어줘.
피드백: 플레이 중 자리를 잠깐 비울 때 게임을 멈추고 같은 상태로 돌아오고 싶다.
CHG-01 변경 요청을 제안하되 아직 파일·코드는 수정하지 마.

수용 기준은 다음을 포함한다.
- P는 playing과 paused 사이에서만 전환하고 title/won/lost에서는 무시한다.
- 키 자동 반복(event.repeat)은 무시하여 한 번 누를 때 한 번만 전환한다.
- 정지 중 플레이어·적·탄환·점수와 발사 쿨다운 등 게임 시간이 변하지 않는다.
- 일시정지 표시와 P로 재개한다는 안내를 보여준다.
- blur 및 상태 전환에서 held keys를 비워 이동·발사가 남지 않게 한다.
- 재개 시 RAF 기준 시간을 초기화하여 위치·시간이 한꺼번에 뛰지 않는다.
- 재개할 때 별도 애니메이션 루프를 추가하지 않는다.
- 기존 시작·종료·재시작 규칙과 REQ-01~08은 유지한다.
blur 자체의 자동 일시정지는 이번 범위에 넣지 마.
요청 배경, 목표, 제외 범위, 관찰 가능한 수용 기준, 기존 요구사항 관계를 제안해줘.
추가 버튼·적 탄환·목숨·사운드·모바일 조작은 넣지 말고 검토를 기다려줘.
```

수용 기준에 CHG-01-AC1처럼 식별자를 붙이면 설계와 테스트에서 연결하기 쉽습니다.
“재개가 자연스럽다” 대신 “장시간 정지 후 첫 프레임의 위치가 뛰지 않는다”로 씁니다.

### 승인 후 작성

**Interactive**로 바꾼 뒤 승인한 요청만 파일로 만듭니다.

```text
검토한 CHG-01 요청과 수용 기준을 승인한다.
루트 CHANGE_REQUEST.md만 새로 작성해줘.
배경, 최초 배포 기준 SHA, 범위/제외, 수용 기준 ID, 승인 상태를 기록해줘.
요청 승인이지 구현·테스트·배포 완료 승인이 아님을 명시해줘.
PRD·TRD·계획·테스트·코드는 아직 수정하지 말고 diff를 보여준 뒤 기다려줘.
```

### 예상 결과

`CHANGE_REQUEST.md`에 요청 배경, 기준 버전, P 동작, 경계 조건, 제외 범위가 있습니다.
게임은 여전히 최초 버전이며 P 기능이 동작한다고 기록하지 않습니다.

## 4. 함께 점검·확인

| 점검 | 충족 기준 |
|---|---|
| 전환 범위 | `playing ↔ paused`만 허용, 제목·종료 화면에서 무효 |
| 정지 범위 | 위치뿐 아니라 발사 쿨다운과 게임 시간이 정지 |
| 입력 | 반복 P 무시, blur·전환 시 held keys 제거 |
| 시간 | 재개 시 기준 시간 초기화, 하나의 RAF 루프 유지 |
| 회귀 | REQ-01~08을 변경 요청 때문에 삭제하지 않음 |
| 범위 | 자동 blur 일시정지·새 버튼·새 게임 규칙은 추가하지 않음 |

## 5. 보완과 재확인

```text
CHG-01의 모호하거나 검증하기 어려운 문장을 찾아 수정안을 제안해줘.
화면 관찰 기준과 내부 테스트 기준을 구분하고 기존 규칙과 충돌을 설명해줘.
승인한 요청 파일만 보완하고 구현이나 다른 문서 변경은 하지 마.
수정 후 수용 기준별로 확인 방법이 있는지 다시 보여줘.
```

브랜치나 기록 커밋이 불분명하면 기능 논의보다 보존·동기화 확인을 먼저 해결합니다.
최초 배포 증거를 새 버전 결과로 덮어쓰지 않습니다.

## 6. 완료 승인

- [ ] 안전한 개선 브랜치와 최초 배포 기준을 확인했다.
- [ ] 변경 요청에 기능·경계·제외 범위와 수용 기준 ID가 있다.
- [ ] 코드 변경 없이 요청만 승인했다.

```text
CHG-01 변경 요청 문서를 승인한다.
승인 파일만 구체적인 한국어 제목과 본문으로 로컬 커밋해줘.
제목 예시: '07-01: P 키 일시정지 변경 요청의 범위와 검증 가능한 수용 기준 정의'
본문에 단계 ID 07-01과 CHG-01, 변경 내용·이유, 문서 검토 결과를 적어줘.
구현·기능 테스트·재배포는 미수행임을 포함해 미확인 범위를 명시해줘.
푸시·문서 영향 반영·구현은 시작하지 말고 기다려줘.
```

세션 기준은 [app 세션 안내](https://docs.github.com/en/copilot/how-tos/github-copilot-app/agent-sessions)를 참고합니다.
