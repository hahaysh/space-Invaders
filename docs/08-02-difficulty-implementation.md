# 08-02. 난이도 구현·검증·재배포

**8. 선택 확장 · CHG-02 구현부터 공개 확인까지**

이전: [08-01 난이도 설계](08-01-difficulty-design.md) · [전체 목차](00-overview.md) · 다음: [09-01 목숨 3개 설계](09-01-lives-design.md)

## 1. 설명

설정값을 선언하는 것과 실제 게임에서 사용하는 것은 다릅니다.
이번에는 **난이도 설정 → 편대 이동 계산 → 선택 UI → 테스트**를 연결합니다.
보통이 이전 게임과 같다는 것, 쉬움·어려움의 실제 이동 거리가 다르다는 것을 따로 확인합니다.
기존 워크플로는 재사용하며, 난이도 개선을 먼저 마친 뒤 목숨 기능으로 넘어갑니다.

## 2. 시작 상태

- [ ] CHG-02 요청·PRD·TRD·계획·테스트 계획이 승인되었다.
- [ ] 기준 커밋과 CHG-01까지의 이전 결과를 보존했다.
- [ ] 참가자 게임 저장소의 승인된 새 작업 브랜치에 있다.
- [ ] **Plan** 모드를 선택했다.

## 3. 실행: 작은 단위로 구현

```text
AGENTS.md와 승인한 CHG-02 요청·PRD·TRD·구현 계획·테스트 계획, 관련 코드를 읽어줘.
실제 파일 경로를 근거로 다음 작업을 계획해줘.
A. 난이도 설정·상태 제한·편대 이동 연결과 Node 테스트.
B. label이 있는 select, 현재 난이도 표시·포커스 처리와 Playwright 테스트.
적 이동 거리와 벽 도달 시간 계산이 모두 선택한 속도를 사용하는지 포함해줘.
기존 생성·시작·재시작 API의 기본 보통 호환성과 P 동작을 유지해줘.
함수 이름·파일 위치는 기존 구조에 맞추고 새 프레임워크나 의존성은 추가하지 마.
아직 수정·설치·명령 실행·커밋은 하지 말고 승인을 기다려줘.
```

### A. 설정과 게임 규칙

계획을 확인하고 **Interactive**로 전환합니다.

```text
검토한 CHG-02 작업 A만 승인한다.
승인된 난이도 설정과 시작·재시작 시 적용, 플레이 중 변경 금지를 구현해줘.
easy 32, normal 64, hard 96 px/s가 이동과 벽 도달 시간 계산에 함께 쓰이도록 해줘.
승인 문서의 값이 다르면 이 제안값을 덮어쓰지 말고 먼저 차이를 확인해줘.
미지정 값은 보통, 지원하지 않는 값은 명시적인 오류로 처리해줘.
관련 Node 테스트를 추가하고 npm test를 실행해 실제 결과와 diff를 보여줘.
보통의 기존 게임 규칙·CHG-01은 유지하고 테스트를 삭제해 통과시키지 마.
B 구현·커밋·푸시·배포는 아직 하지 마.
```

### B. 선택 UI와 실제 연결

A의 결과를 확인한 뒤에만 다음 프롬프트를 입력합니다.

```text
작업 A를 승인하고 CHG-02 작업 B만 진행해줘.
승인된 label/select와 현재 난이도 표시를 연결해줘.
title/won/lost에서 선택 가능하고 playing/paused에서는 비활성화해줘.
게임 단축키가 select의 방향키·Enter 선택을 가로채지 않도록 해줘.
시작/재시작 버튼 뒤 실제 게임 조작이 가능한 포커스·입력 처리도 확인해줘.
Playwright는 실제 select와 시작·재시작 조작을 통해 설정 적용을 확인하게 해줘.
프로덕션 코드에 테스트 전용 전역 상태 변경 API는 추가하지 마.
npm test, npm run test:e2e, npm run build를 실행해줘.
의존성이 없을 때만 npm ci, Chromium이 없을 때만 브라우저 설치를 허용한다.
실패를 숨기지 말고 명령별 실제 결과와 diff를 보여줘.
커밋·푸시·배포는 하지 말고 참가자의 확인을 기다려줘.
```

## 4. 함께 점검·확인: 변경과 회귀

| 확인 | 기대 결과 |
|---|---|
| 최초 선택 | 보통, 시작 후 64 px/s 적용 |
| 수치 검증 | 벽과 멀고 충돌이 없는 같은 초기 상태에서 게임 시간 0.1초 동안 적의 x 이동량 3.2·6.4·9.6 px, 부동소수점 허용오차 명시 |
| 편대 경계 | 각 난이도에서 벽 도달 때 한 번 반전·24 px 하강, 수평 범위 이탈 없음 |
| 적용 시점 | 제목에서 어려움 선택 후 시작하면 어려움, 종료 후 쉬움 선택·재시작하면 쉬움 |
| 상태 제한 | playing/paused에서 UI·모델 모두 난이도 변경 금지 |
| 키보드 선택 | select에 포커스하고 방향키·Enter로 선택할 때 의도치 않은 시작·이동 없음 |
| P와 시간 | 모든 난이도에서 정지 중 상태·쿨다운 보존, 재개 점프·잔류 입력·중복 RAF 없음 |
| 보통 회귀 | 기존 시작·이동·발사·24개 적·점수·승패·재시작 유지 |
| 잘못된 설정 | 지원하지 않는 값에 명시적 오류, 조용한 보통 대체 없음 |
| 새로고침 | 저장 없이 보통으로 복귀, 기존 빌드·하위 경로 전달 유지 |

정확한 이동량은 제어 가능한 게임 시간의 모델 테스트로 검사합니다. 화면 표시가 “어려움”으로 바뀐 것만으로 적용 성공이라고 판단하지 않습니다.
브라우저 테스트도 같은 관찰 시간의 실제 Canvas 움직임 등 관측 가능한 결과로 설정 연결을 확인합니다. 임의의 긴 sleep만 사용하지 않습니다.

```text
CHG-02 전체 기준과 기존 REQ-01~08·CHG-01의 변경/회귀 대응표를 점검해줘.
이번 수정에서 의도적으로 달라진 적 속도 선택만 구분하고 기존 검사 누락을 찾는 것을 허용한다.
승인한 로컬 검증 범위에서 npm test, npm run test:e2e, npm run build를 실행해줘.
빌드 preview를 실행하고 응답하는 실제 주소를 확인해 알려줘.
TEST_RESULTS.md에 기준 커밋, 명령, 기대/실제 결과, 실패와 미확인 항목을 추가해줘.
이전 결과는 보존하고 수동 확인은 내가 보고한 내용과 도구 검증을 구분해줘.
IMPLEMENTATION_PLAN.md·CHANGE_REQUEST.md에는 실제 완료 범위만 기록해줘.
코드 추가 수정·커밋·푸시·배포 없이 결과를 보여줘.
```

참가자는 실제 preview에서 세 난이도를 선택하고 시작·P·종료 후 선택 변경을 확인합니다.
필수 로컬 항목에 실패·미확인이 있으면 공개 단계로 넘어가지 않습니다.

## 5. 보완과 재확인

```text
난이도 개선에서 실패한 항목의 기대/실제 차이와 재현 절차를 정리해줘.
표시만 바뀌었는지, 이동 계산에 옛 상수가 남았는지, 시작·재시작에서 값이 사라지는지,
select 포커스와 게임 단축키가 충돌하는지 구분하고 최소 수정안을 제안해줘.
승인 전 코드·테스트 기대값 변경, 푸시·배포는 하지 마.
```

수정안을 승인하면 재현 테스트와 관련 수정 후 전체 변경·회귀 테스트와 빌드를 다시 실행합니다.
단순히 어려움에서 실패한다는 이유로 테스트의 기대 속도를 낮추지 않습니다.

## 6. 완료 승인: 커밋·재배포·실제 확인

### 로컬 변경 승인

```text
CHG-02 구현·문서·테스트 diff와 필수 로컬 확인 결과를 승인한다.
승인 파일만 한국어 제목·본문으로 로컬 커밋해줘.
제목 예시: '08-02: 난이도 선택을 적 이동에 연결하고 기존 일시정지·게임 규칙 회귀 검증'
본문에 08-02, CHG-02, 변경 내용·이유, 실제 명령·검증 결과와 미확인 범위를 적어줘.
실제 원격 배포는 아직 미수행으로 표시하고 푸시하지 마.
```

### 공개 대상 점검과 PR 생성

먼저 **Plan**에서 다음을 확인합니다. 워크플로를 새로 만들 필요는 없습니다.

```text
CHG-02 공개 전 저장소·원격·브랜치·main 차이·미커밋 변경을 읽기 전용으로 점검해줘.
로컬 필수 검증과 기존 .github/workflows/pages.yml을 확인해줘.
PR은 검사만, main은 성공한 테스트·빌드 후 dist를 Pages에 배포하는 조건이 유지되는지 봐줘.
Pages Source와 github-pages 환경은 직접 확인한 정보/참가자 보고/미확인을 구분해줘.
검증 누락이나 원격 미배포 상태라면 06단계 준비 중 필요한 작업을 알려줘.
승인할 커밋과 PR 요약만 제시하고 파일·설정 변경·푸시·PR·병합은 하지 마.
```

필요한 설정은 [06-01](06-01-deployment-setup.md), 워크플로 누락은 [06-02](06-02-actions-workflow.md)에서 별도 승인 후 해결합니다.
원격 공개를 하지 않기로 했다면 이후 공개 프롬프트를 실행하지 않고 **로컬 완료·재배포 미수행**으로 마칩니다.

**Interactive**에서 대상 확인 후 PR 생성만 승인합니다.

```text
확인한 참가자 Public 게임 저장소에 CHG-02 승인 커밋을 푸시하고 main 대상 PR을 만들어줘.
한국어 PR 본문에 변경 이유, 수용 기준, 실제 검증 결과와 미확인 범위를 적어줘.
강제 푸시·main 직접 푸시·병합·설정 변경은 하지 마.
PR URL과 현재 CI 상태를 보고하고 기다려줘.
```

### 병합 승인과 공개 확인

PR diff와 마지막 head, 모든 필수 검사를 직접 확인한 뒤에만 입력합니다.

```text
방금 검토한 CHG-02 PR의 최종 head를 main에 병합하도록 승인한다.
새 변경·검사 실패/대기·미해결 리뷰가 있으면 멈추고 보호 규칙은 우회하지 마.
병합 메시지는 08-02, CHG-02, 변경 이유·검증·미확인을 담은 한국어 제목·본문으로 작성해줘.
실제 Actions 실행 URL, 배포 SHA, build/deploy 상태와 실제 page_url을 보고해줘.
진행 중·실패·환경 승인 필요·완료를 구분하고 필요한 승인 동작을 구체적으로 알려줘.
공개 게임 확인은 별도 수행 전까지 미확인으로 두고 추가 기능은 구현하지 마.
```

실제 URL에서 새로고침·JS/CSS 404·Console 오류를 확인하고 세 난이도 선택·실제 움직임·P·재시작을 점검합니다.
실패하거나 배포가 끝나지 않았으면 CHG-02의 공개 완료 처리를 보류합니다.
실행 URL·SHA·브라우저 증상으로 원인을 확인하고, [07-05의 공개 실패 대응](07-05-redeploy-and-wrap-up.md)처럼 수정 또는 복구 계획을 별도 승인합니다.
직전 정상 배포를 이번 성공 결과로 대신 기록하지 않습니다.

```text
CHG-02의 실제 배포 SHA·실행 URL·page_url과 확인한 공개 동작을 TEST_RESULTS.md에 추가해줘.
내 수동 관찰과 도구 확인, 미확인을 구분하고 이전 버전 결과를 보존해줘.
CHANGE_REQUEST.md와 계획에는 근거가 있는 완료 상태만 반영하고 diff를 보여줘.
추가 코드 변경·커밋·푸시는 하지 마.
```

결과 diff를 검토한 뒤 기록만 한국어 제목·본문으로 로컬 커밋하도록 별도 승인합니다.
배포 SHA와 이후 결과 기록 커밋은 다릅니다. 원격에도 남기려면 [07-05 결과 기록 절차](07-05-redeploy-and-wrap-up.md)의 기록 브랜치·PR·병합 승인을 각각 따릅니다.
문서 후속 배포마다 또 기록 PR을 만드는 순환은 필요하지 않습니다.

- [ ] 로컬 기능 완료와 공개 배포 완료를 구분했다.
- [ ] 난이도 선택과 기존 P 기능의 실제 증거를 연결했다.
- [ ] 다음 CHG-03의 기준 코드·기록 커밋을 보존했다.

```text
이번 CHG-02 사이클의 실제 완료 범위를 최종 요약해줘.
이 세션에서 시작한 개발 서버만 종료하고 추가 코드·커밋·푸시는 하지 마.
CHG-03은 다음 단계에서 별도 승인하므로 자동으로 시작하지 마.
```
