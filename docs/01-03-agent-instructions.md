# 01-03. AGENTS.md 작성과 작업 규칙 확인

**1. 준비 · 에이전트 작업 지침**

[이전: 문서 구조 정의](01-02-document-design.md) · [전체 목차](00-overview.md) · [다음: 아이디어](02-01-ideation.md)

## 1. 설명

`AGENTS.md`는 이 저장소에서 에이전트가 일할 때 따라야 할 규칙을 기록합니다. 반복해서 설명할 작업 경계와 승인 기준을 파일로 남기되, 게임 요구사항 전체를 넣지는 않습니다.

이번 단계에서는 처음으로 개발 문서를 생성합니다. 아직 존재하지 않는 파일을 이미 읽었다고 쓰거나, 확정하지 않은 실행 명령을 사실로 기록하지 않도록 합니다.

## 2. 시작 상태

- [ ] 01-02의 문서 역할·목차·작성 순서를 승인했다.
- [ ] 같은 실습 저장소와 작업 브랜치에서 진행한다.
- [ ] 게임 코드와 `AGENTS.md`가 아직 없다.
- [ ] 문서 구조 승인 요약을 현재 대화에서 참고할 수 있다.
- [ ] 처음에는 **Plan** 모드로 초안을 검토한다.

## 3. 실행: 작업 지침 초안

```text
앞 단계에서 승인한 개발 문서 구성을 참고해 AGENTS.md 초안을 제안해줘.
아직 파일은 만들지 마. 승인 요약을 찾을 수 없으면 먼저 요청해줘.

최소 지침에는 다음을 포함해줘.
- 한국어로 설명하고, 현재 단계/허용 파일/완료 조건을 확인한다.
- 존재하는 문서를 읽고, 없는 문서는 없다고 말한다.
- PRD는 요구사항 기준, TRD는 구현 설계 기준으로 참조한다.
- 문서 간 충돌이 있으면 임의로 우선순위를 정하지 말고 확인한다.
- Plan 단계에는 승인 없이 파일을 변경하지 않는다.
- 승인된 작은 단위만 구현하고 변경 내용과 확인 결과를 제시한다.
- 토큰/비밀정보를 코드·문서·로그에 남기지 않는다.
- 기존 사용자 변경을 지우거나 강제 푸시하지 않는다.
- 테스트 계획과 실제 결과를 구분하고 미수행은 미확인으로 기록한다.
- 실제 파일 변경은 단계별로 검토 후 로컬 커밋한다.
- 커밋 제목과 본문은 한국어로 작성하고 단계/변경 이유/확인 결과를 적는다.
- 커밋, 푸시, PR 병합, 공개 배포는 각각 승인 범위를 확인한다.
- 완료 후 다음 실습을 자동 진행하지 않는다.

실제 실행/빌드/테스트 명령은 구현 설정이 만들어진 후 확인하여 보완하도록 해줘.
현재 존재하지 않는 명령을 실행 가능하다고 적지 마.
불필요한 반복이나 게임 요구사항의 복제 없이 짧은 목차로 제안해줘.
```

초안을 읽고 승인 경계·기록 규칙이 적절한지 확인합니다. 코드 생성이나 모든 도구 실행의 무조건 허용 문구는 넣지 않습니다.

## 4. 실행: 승인 후 파일 생성

**Interactive**로 전환하고 다음을 입력합니다.

```text
방금 검토한 AGENTS.md 초안을 승인한다.
저장소 루트에 AGENTS.md 하나만 생성해줘.
기존 파일이 있으면 덮어쓰지 말고 먼저 알려줘.

다른 문서, 게임 코드, 설정 파일은 만들지 마.
설치·커밋·푸시도 아직 하지 마.
생성 후 실제 파일 내용을 읽고 초안과의 차이, 변경 파일 목록을 보여줘.
```

예상 결과는 루트의 `AGENTS.md` 한 개입니다. 실제 파일과 diff를 확인합니다.

## 5. 점검: 명시적 참조와 자동 적용을 구분

```text
현재 저장소의 AGENTS.md를 명시적으로 읽어줘.
이번 실습에서 지켜야 할 작업·승인·검증·커밋 규칙을 요약해줘.
아직 존재하지 않는 개발 문서와 명령이 무엇인지도 구분해줘.

파일을 읽었다는 사실과 자동 지침으로 로드되었다는 사실은 구분해줘.
자동 적용을 확인할 수 없으면 미확인이라고 말해줘.
확인을 위해 게임 코드나 시험용 파일을 만들지는 마.
```

[CLI 공식 문서](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions)는 `AGENTS.md` 지원과 활성 세션에서 변경 지침을 다시 적용할 때의 주의사항을 설명합니다. app에서도 생성 직후 자동 적용된다고 단정하지 않습니다.

app에서 지침 목록을 확인할 수 있다면 실제 표시를 점검합니다. 세션 재개가 필요하면 저장소·작업 브랜치·미커밋 파일을 먼저 확인합니다. 새 세션이 기본 브랜치에서 열리면 아직 그 브랜치에 없는 지침을 찾을 수 없으므로, 무조건 새 세션을 만들지 않습니다. 현재 과정은 각 프롬프트에서 명시적으로 `AGENTS.md`를 읽도록 하여 이어갈 수 있습니다.

- [ ] `AGENTS.md`가 정확한 대소문자로 루트에 있다.
- [ ] 요구사항 전체가 아니라 작업 지침이다.
- [ ] 없는 파일·명령을 완료된 것처럼 설명하지 않는다.
- [ ] 승인·개인정보·기존 변경 보존·검증·커밋 규칙이 있다.
- [ ] 에이전트가 읽은 규칙을 정확히 요약했다.
- [ ] 자동 적용 확인 여부를 별도로 구분했다.

## 6. 보완

```text
AGENTS.md에 현재 단계와 맞지 않는 지침이 있어.
없는 명령을 확정하거나 모든 작업을 자동 승인하는 문구,
PRD에 있어야 할 기능 명세가 중복된 부분을 찾아 수정안을 제시해줘.
확정되지 않은 명령은 추후 검증 후 보완한다고 표시해줘.
승인 전에는 파일을 수정하지 마.
```

수정안 승인 후 `AGENTS.md`만 고치고 실제 내용을 다시 읽게 합니다.

## 7. 완료 승인과 로컬 커밋

검토를 마친 뒤 다음을 입력합니다.

```text
AGENTS.md 내용을 승인한다.
현재 변경 목록을 확인하고 이번 단계의 AGENTS.md만 로컬 커밋해줘.
관련 없는 파일이 staged 상태라면 섞어 커밋하지 말고 알려줘.

한국어 제목과 본문으로 '01-03 작업 지침 작성'임을 명확히 하고,
추가한 규칙, 이유, 명시적 읽기 확인 결과, 자동 적용 확인 여부를 기록해줘.
작성자 설정이 없으면 임의로 설정하지 말고 나에게 요청해줘.
푸시하지 말고 커밋 해시와 변경 파일을 알려줘.
다음 실습은 시작하지 마.
```

완료 산출물은 `AGENTS.md`와 추적 가능한 로컬 커밋입니다. 다음 단계에서 게임 아이디어를 구체화합니다.
