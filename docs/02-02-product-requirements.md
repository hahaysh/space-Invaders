# 02-02. 요구사항과 수용 기준 작성

**2. 게임 설계 · `PRD.md` 작성**

이전: [02-01 아이디어](02-01-ideation.md) · [전체 목차](00-overview.md) · 다음: [02-03 기술 설계](02-03-technical-design.md)

## 1. 설명

PRD는 **무엇을 만들고 어떤 관찰 결과를 완료로 인정할지** 정하는 문서입니다.
“잘 움직인다” 대신 입력·상태·경계·결과를 적습니다. 요구사항 ID는 이후 설계·작업·테스트의 연결점입니다.
이번에는 코드를 만들지 않고 참가자 저장소 루트에 `PRD.md`만 작성합니다.

공통 수치는 아래 권장안을 기준으로 참가자가 승인합니다. 다른 규칙을 원하면 먼저 변경 영향을 검토합니다.
색상과 이름이 달라도 같은 요구사항을 만족하면 됩니다.

## 2. 시작 상태

- [ ] `AGENTS.md`와 승인한 `ideation.md`가 있다.
- [ ] 아이디어의 제외 범위와 PRD에서 결정할 사항을 읽었다.
- [ ] 자신의 작업 세션에서 **Plan** 모드를 선택했다.

## 3. 실행: 관찰 가능한 기준으로 바꾸기

### 3-1. Plan에서 요구사항 초안 검토하기

```text
AGENTS.md와 ideation.md를 읽고 PRD.md 초안을 대화에 제안해줘.
파일 변경·설치·구현·커밋·푸시는 하지 마.
목표, 사용자 흐름, 요구사항 ID/우선순위/수용 기준,
상태 전환, 제외 범위, 미결정 사항으로 구성해줘.

공통 실습의 최초 버전은 아래 REQ-01~08을 모두 필수로 한다.
REQ-01 시작: 초기 title, Enter 또는 시작 버튼으로 playing 전환, 점수 0.
REQ-02 이동: Canvas 800×600, 플레이어 40×20, 좌상단 y=550 고정.
  playing에서만 좌우 화살표 또는 A/D로 이동하고 x는 0~760으로 제한한다.
REQ-03 발사: playing에서만 Space로 위쪽 탄환을 발사한다.
  연속 발사 간격은 최소 0.2초이며 화면 밖 탄환은 제거한다.
REQ-04 적 편대: 3행×8열=24개, 수평 이동하다 경계에서 반전·하강한다.
REQ-05 충돌·점수: 탄환 하나는 최대 적 하나만 제거하고 즉시 소모된다.
  적 하나당 10점, 중복 점수 없음, 전멸 시 총점 240.
REQ-06 종료: 적 전멸 시 won, 살아 있는 적 하단이 y=520 이상이면 lost.
  종료 뒤 시뮬레이션·점수 갱신과 이동·발사는 멈춘다.
REQ-07 재시작: won/lost에서 R 또는 재시작 버튼으로 playing을 새로 시작한다.
  플레이어·적·탄환·점수·방향·입력·발사 대기시간 등 한 판의 상태를 초기화한다.
REQ-08 전달: 최신 데스크톱 브라우저에서 실행하는 정적 게임이다.
  시작/재시작 버튼, 상태와 점수를 DOM으로 읽을 수 있게 제공한다.
  상대 에셋 경로로 저장소 하위 경로에서 동작하며 외부 CDN/게임 엔진/
  이미지 서버 없이 실행한다. 나중에 배포할 대상은 dist 빌드 결과뿐이다.

최초 상태는 title/playing/won/lost만 둔다.
CHG-01 일시정지·재개는 후속 개선 후보일 뿐 현재 수용 기준에 넣지 마.
목숨·적 탄환·사운드·모바일·온라인 순위·여러 웨이브는 제외한다.

후속 실습과 동일한 기준을 쓰도록 나머지 수치도 다음 공통 제안으로 검토해줘.
- 플레이어 초기 좌상단 (380,550), 이동 속도 320 px/s.
- 탄환 4×12 px, 위로 600 px/s, 플레이어 윗변의 가로 중앙에서 발사.
- 적 40×24 px, 수평 속도 64 px/s, 최초 오른쪽 진행, 반전 때 하강 24 px.
- 적 초기 좌상단은 (112 + 열×72, 72 + 행×48), 행 0~2·열 0~7.
이 값은 아직 참가자 승인 전 제안이다. 다른 값을 추천한다면 차이와 후속 검사 영향을 설명해줘.
충돌 경계 포함 여부, 양 방향 동시 입력, Space 유지와 첫 발사,
종료 조건 동시 만족 우선순위, playing 중 Enter/R 무시 여부도 권장안을 제시해줘.
값은 단위와 좌표 기준을 적고 임의의 미결정 상태로 구현에 넘기지 않도록 해줘.
내가 선택해야 할 항목을 끝에 모아주고 기다려줘.
```

공통 수용 기준을 읽고 미결정 항목에 답합니다. 속도는 초당 픽셀, 시간은 초처럼 단위를 함께 승인합니다.
Space 유지 발사와 동시 종료 우선순위는 답이 하나로 정해진 문제가 아니지만, 구현 전에 하나로 정해야 합니다.
공통 경로의 적 속도 64 px/s·하강 24 px는 07의 회귀와 08의 기본 보통에 이어집니다.
다른 수치를 선택하면 이후 안내의 수치·테스트 기대값도 조정해야 하며, 에이전트가 후속 단계에서 조용히 표준값으로 되돌리지 않도록 기록합니다.

```text
공통 REQ-01~08을 채택한다. Space를 유지하면 0.2초 간격으로 발사하고
시작 직후 첫 발사는 즉시 가능하게 한다. 양 방향을 함께 누르면 이동하지 않는다.
playing 중 Enter/R은 무시하고 title에서 R도 무시한다.
충돌은 사각형의 면적이 겹칠 때로 하고 경계만 맞닿으면 충돌하지 않는다.
한 갱신에서 충돌을 먼저 처리한 뒤 살아 있는 적으로 종료를 판정하며,
패배 조건이 있으면 lost, 그렇지 않고 적이 없으면 won으로 정한다.
나머지 수치 권장안을 표로 다시 보여줘. 파일은 아직 쓰지 마.
```

### 3-2. Interactive에서 승인한 PRD 저장하기

수치 표까지 검토한 후 모드를 바꾸어 요청합니다.

```text
방금 검토한 수치 표와 수용 기준을 승인한다.
AGENTS.md를 읽고 저장소 루트 PRD.md만 작성해줘.
각 REQ의 정상·경계·금지 동작을 확인 가능한 문장으로 써줘.
아이디어와 충돌하면 조용히 덮어쓰지 말고 알려주고 멈춰줘.
미해결 결정이 있으면 질문으로 남기고 구현 가능하다고 선언하지 마.
다른 파일 수정·설치·구현·커밋·푸시 없이 diff를 보여주고 멈춰줘.
```

### 예상 결과

- ID가 고정된 필수 요구사항 8개와 구체적인 수치·수용 기준.
- 시작 → 플레이 → 승리/패배 → 재시작 흐름과 입력 허용 상태.
- 후속 개선 및 제외 범위를 구분한 `PRD.md`.

## 4. 함께 점검·확인

| 점검 항목 | 충족 기준 |
|---|---|
| 검증 가능성 | 각 REQ에 입력·전제 상태·예상 결과가 있다. |
| 수치 일관성 | 24개×10점=240점, 플레이어 x 상한 760, 패배 경계는 적 하단이다. |
| 상태 | title/won/lost에서는 이동·발사하지 않고 재시작으로 새 판을 만든다. |
| 중복 처리 | 탄환 하나가 여러 적을 제거하거나 같은 적으로 중복 득점하지 않는다. |
| 경계 결정 | 반전·하강, 충돌 경계, 동시 입력·종료 우선순위가 명시되어 있다. |
| 범위 | CHG-01이 현재 필수 요구사항으로 섞이지 않았다. |

```text
Plan에서 ideation.md와 PRD.md의 정합성을 읽기 전용으로 검토해줘.
REQ별로 정상/경계/금지 동작이 충분한지 충족·보완 필요·미확인으로 표시해줘.
모호한 수치나 서로 다른 해석이 가능한 기준은 문장과 수정안을 제시해줘.
실행하지 않은 기능을 통과로 표시하지 마. 파일은 수정하지 마.
```

## 5. 보완과 재확인

```text
Plan에서 '적이 아래에 오면 종료'처럼 검증할 수 없는 문장을 찾아줘.
좌표 기준·비교 연산·전제 상태·기대 결과를 포함하는 수정안을 제시해줘.
요구사항을 느슨하게 바꿔 모순을 감추지 말고, ID는 유지해줘. 아직 수정하지 마.
```

수정안을 승인하면 Interactive에서 `PRD.md`만 반영하도록 요청하고 diff와 해당 REQ를 다시 확인합니다.
변형 규칙을 채택했다면 `ideation.md` 수정 필요도 별도로 검토·승인한 뒤 진행합니다.

## 6. 완료 승인

- [ ] REQ-01~08의 수용 기준과 모든 필수 수치를 참가자가 승인했다.
- [ ] 정상 플레이 외에 경계·금지 동작을 설명할 수 있다.
- [ ] 미결정 사항이 구현을 막지 않으며 변경 범위를 확인했다.

```text
PRD.md를 승인한다. 검토한 PRD.md 변경만 커밋하고 결과를 알려줘.
메시지는 너무 짧지 않은 한국어 설명형 제목과 본문으로 작성하고,
본문에 02-02 단계 ID, 변경 내용과 이유, 검토 결과와 실행 검증 미수행 범위를 적어줘.
다른 변경을 포함하거나 푸시하지 마. TRD 작성은 다음 요청까지 기다려줘.
```
