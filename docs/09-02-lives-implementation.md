# 09-02. 목숨 구현·검증·재배포

**9. 선택 확장 · CHG-03 구현부터 공개 확인까지**

이전: [09-01 목숨 설계](09-01-lives-design.md) · [전체 목차](00-overview.md)

## 1. 설명

화면에 숫자 3을 표시하는 것으로 끝내지 않습니다.
적 도달 판정·상태 전환·재도전·입력·시간을 연결해 **3 → 2 → 1 → 0의 실제 플레이 흐름**을 만듭니다.
난이도와 P 기능은 유지하고, 승인된 패배 규칙 변경만 이전과 다르게 검증합니다.

## 2. 시작 상태

- [ ] CHG-03의 수동 재도전·점수 초기화 정책까지 승인했다.
- [ ] 문서·작업 지침의 목숨 제외 범위가 현재 승인과 충돌하지 않는다.
- [ ] CHG-02 기준 코드와 이전 검증 기록을 보존했다.
- [ ] 승인된 CHG-03 작업 브랜치에서 **Plan** 모드를 선택했다.

## 3. 실행: 모델과 화면을 나눠 구현

```text
AGENTS.md, CHG-03 요청·PRD·TRD·구현 계획·테스트 계획과 관련 코드를 읽어줘.
실제 파일 경로와 재사용할 코드를 근거로 두 작업의 세부 계획을 제시해줘.
A. 목숨·retry 상태, 충돌 후 단일 차감, 새 게임/재도전 초기화와 Node 테스트.
B. 목숨·재도전 안내/버튼, 입력 제한·난이도 선택 잠금·RAF 시간 처리와 Playwright 테스트.
기존 REQ-06·REQ-07 검사 중 승인된 기대값 변경과 그대로 유지할 검사를 구분해줘.
테스트 전용 전역 치트나 별도 RAF 루프·새 의존성을 추가하지 마.
아직 수정·실행·설치·커밋하지 말고 계획 승인을 기다려줘.
```

### A. 목숨 차감과 상태 전환

계획을 확인하고 **Interactive**로 전환합니다.

```text
검토한 CHG-03 작업 A만 승인한다.
새 게임 목숨 3, playing의 충돌 처리 후 살아 있는 적 도달 때 정확히 1 차감을 구현해줘.
남으면 retry, 0이면 lost이며 같은 프레임·서브스텝의 중복 차감을 차단해줘.
retry에서는 시뮬레이션을 멈추고 입력을 비워줘.
재도전은 목숨·현재 난이도를 보존하고 점수 0과 해당 시도의 상태만 초기화해줘.
종료 후 새 게임은 선택 난이도로 목숨 3부터 시작하도록 구분해줘.
마지막 적 제거는 차감 없이 won, 다른 살아 있는 적이 도달하면 도달 처리가 우선이다.
기존 REQ-06·REQ-07 테스트 기대값은 승인된 변경 ID와 이유가 있는 부분만 갱신해줘.
새 테스트로 3→2→1→0, 재도전·새 게임 초기화, 충돌 우선순위, P 정지를 확인해줘.
npm test를 실행하고 실제 결과와 diff를 보여줘.
B·커밋·푸시·배포는 시작하지 마.
```

### B. 입력·화면·시간 연결

A의 결과를 확인한 뒤 다음 작업만 승인합니다.

```text
작업 A의 결과를 승인하고 CHG-03 작업 B를 구현해줘.
목숨 텍스트, retry의 남은 목숨·실패 시도 점수·Enter/재도전 버튼 안내를 추가해줘.
retry에서 반복이 아닌 Enter 또는 버튼만 재도전시키고 R/P/이동/발사는 무시해줘.
난이도는 title/won/lost에서만 선택 가능하고 playing/paused/retry에서는 막아줘.
모든 상태 전환·blur에서 held keys를 비우고 paused/retry의 시간·쿨다운을 동결해줘.
재도전 직후 RAF 기준 시간을 초기화하고 루프는 하나만 유지해줘.
새 상태가 기존 select 키보드 조작, 시작·재시작·P에 영향을 주지 않도록 해줘.
Playwright에서 실제 입력·버튼·화면으로 목숨 감소와 재도전을 검사해줘.
실제 게임 시간은 제어하되 제품 코드에 테스트용 상태 변경 API를 추가하지 마.
npm test, npm run test:e2e, npm run build를 실행해줘.
의존성이 없을 때만 npm ci, Chromium이 없을 때만 브라우저 설치를 허용한다.
결과·diff를 보여주고 커밋·푸시·배포 없이 기다려줘.
```

## 4. 함께 점검·확인: 경계·변경·회귀

| 사례 | 기대 결과 |
|---|---|
| 새 게임 | 목숨 3·점수 0, 선택한 난이도 적용 |
| 첫째·둘째 도달 | 목숨 2·1, 각각 retry에서 멈춤 |
| 셋째 도달 | 목숨 0·lost, 추가 업데이트에도 음수나 중복 차감 없음 |
| 여러 적 동시 도달 | 차감은 정확히 1회, 서브스텝이 반복되어도 같음 |
| 방어선 경계 | 시간 진행 없는 판정에서 살아 있는 적 하단 520 미만이면 미차감, 520 이상이면 차감 |
| 마지막 적과 방어선 | 충돌로 마지막 적 제거 시 won·미차감, 다른 생존 적 도달 시 차감 |
| 재도전 | 목숨·난이도 보존, 적 24개·초기 위치·편대 방향·빈 탄환·0점·시간·쿨다운·입력 초기화 |
| 재도전 전 대기 | 실패 시도 점수 표시, 위치·탄환·시간·쿨다운 불변 |
| retry 입력 | R/P/방향키/Space 무효, 반복 Enter 무효, 새 Enter/버튼은 한 번만 재도전 |
| 종료 후 재시작 | R/버튼으로 목숨 3·점수 0, 종료 화면에서 새로 선택한 난이도 적용 |
| 점수 | 재도전 시 0, 최종 won/lost의 점수는 보존, 시도별 최대 240점 |
| P와 시간 | 모든 난이도에서 paused의 목숨·게임 시간 고정, 재개·재도전 때 점프·입력 잔류·중복 RAF 없음 |
| 기존 UI·배포 | select 키보드 조작, 시작·이동·발사·표시, 빌드·하위 경로 전달 정상 |

Node 테스트는 적 위치·목숨·시간을 제어해서 경계를 재현합니다.
브라우저에서는 게임 시작 후 발사하지 않고 제어된 시간으로 적 도달을 기다린 뒤 실제 Enter/버튼으로 재도전합니다.
셋째 도달까지 확인하고 P 및 난이도와 조합합니다. 단순히 목숨 숫자를 DOM에 주입해서 검증하지 않습니다.

### 과거 테스트와 충돌할 때

| 이전 검사 | 이번 처리 |
|---|---|
| 새 게임의 첫 적 도달이 즉시 lost | 승인된 REQ-06 변경에 맞춰 목숨 2·retry 검사로 갱신 |
| 목숨 1에서 적 도달 | 목숨 0·lost 검사 추가, 최종 패배 규칙 유지 |
| 종료 후 재시작 초기화 | 기존 검사를 보존·확장해 목숨 3·난이도 적용까지 확인 |
| 적 속도·발사·충돌 점수·P | 승인된 변경이 없으므로 기존 검사 유지, retry 조합 추가 |

과거 `TEST_RESULTS.md`의 결과나 최초·개선 샘플을 새 규칙에 맞춰 고치지 않습니다.
현재 테스트를 변경할 때만 요청 ID와 이유를 남깁니다. “기존 모든 테스트를 수정 없이 통과”가 이번 목표는 아닙니다.

```text
CHG-03 기준별 변경 검사와 REQ-01~08·CHG-01·CHG-02 회귀 대응표를 확인해줘.
승인된 로컬 전체 검증 범위에서 npm test, npm run test:e2e, npm run build를 실행해줘.
빌드 preview를 실행하고 실제 응답 주소를 확인해 알려줘.
TEST_RESULTS.md에 기준 커밋, 명령, 기대/실제 값, 실패·미확인과 증거를 추가해줘.
이전 기록은 보존하고 바뀐 테스트 기대값은 CHG-03·REQ-06/07과 연결해줘.
도구 결과와 참가자의 수동 관찰을 구분하고 요청·계획에는 실제 완료 범위만 반영해줘.
코드 추가 수정·커밋·푸시·배포는 하지 마.
```

참가자는 화면의 **3 → 2 → 1 → 0**, 재도전 시 점수 초기화, 종료 후 3으로 재시작을 직접 확인합니다.
쉬움·보통·어려움에서 P와 재도전을 함께 확인하고 아직 못 본 항목은 미확인으로 남깁니다.

## 5. 보완과 재확인

```text
CHG-03 실패 항목의 재현 절차와 기대/실제 차이를 정리해줘.
중복 차감, 목숨 자동 복구, 점수 누적, retry에서 R 우회, 입력 잔류,
재도전 시간 점프와 기존 난이도/P 회귀 중 원인을 구분해줘.
최소 수정과 재현 테스트를 제안하고 승인 전에는 코드를 수정하지 마.
테스트 삭제·조건 완화·성공한 재시도만 기록하는 방식은 금지한다.
```

수정안을 승인한 뒤 재현 테스트와 수정, 전체 변경·회귀 테스트·빌드를 다시 실행합니다.
실패→수정→재검증 이력을 남기고 필수 로컬 항목에 실패·미확인이 있으면 배포하지 않습니다.

## 6. 완료 승인: 세 번째 개선 공개

### 로컬 커밋과 공개 준비

```text
CHG-03 구현·문서·테스트 diff와 필수 로컬 확인 결과를 승인한다.
승인 파일만 한국어 제목·본문으로 로컬 커밋해줘.
제목 예시: '09-02: 목숨 3개와 재도전을 구현하고 난이도·일시정지 회귀 검증'
본문에 09-02, CHG-03, 변경 내용·이유, 의도적으로 바뀐 종료 규칙,
실제 검증 결과와 아직 미수행인 원격 배포를 명시해줘.
푸시는 하지 마.
```

**Plan**에서 공개 대상을 확인합니다.

```text
CHG-03 공개 전 저장소·원격·작업 브랜치·main 차이·미커밋 파일을 읽기 전용으로 점검해줘.
필수 로컬 검증 결과, 기존 .github/workflows/pages.yml과 공개 범위를 확인해줘.
PR은 검사만, main은 성공한 테스트·빌드 후 dist 배포라는 기존 조건이 유지되는지 봐줘.
Pages Source·github-pages 환경은 직접 확인/참가자 보고/미확인으로 나눠줘.
승인할 커밋과 PR 요약, 배포를 막는 항목을 제시해줘.
이 워크숍 안내서 저장소는 배포하지 않으며 파일·설정 변경·푸시·PR·병합은 아직 하지 마.
```

설정이 없으면 [06-01](06-01-deployment-setup.md)·[06-02](06-02-actions-workflow.md)의 준비를 별도로 승인합니다.
원격 공개를 생략하는 참가자는 이후 공개 프롬프트를 건너뛰고 **로컬 완료·재배포 미수행**으로 마칩니다.

### PR과 병합을 따로 승인

**Interactive**에서 승인한 대상만 공개합니다.

```text
확인한 참가자 Public 게임 저장소에 CHG-03 승인 커밋을 푸시하고 main 대상 PR을 생성해줘.
한국어 본문에 목숨·점수·재도전 정책, REQ-06/07 변경,
CHG-01·CHG-02 회귀 근거, 실제 검증 결과와 미확인 범위를 적어줘.
강제 푸시·main 직접 푸시·병합·설정 변경은 하지 마.
PR URL·현재 CI 상태를 보여주고 기다려줘.
```

참가자가 마지막 head와 diff, 필수 검사를 확인한 후 병합을 승인합니다.

```text
방금 검토한 CHG-03 PR의 최종 head를 main에 병합하도록 승인한다.
새 변경·실패/대기 검사·미해결 리뷰가 있으면 멈추고 보호 규칙은 우회하지 마.
병합 메시지는 09-02, CHG-03, 변경 이유·검증·미확인을 담은 한국어 제목·본문으로 작성해줘.
실제 Actions 실행 URL·배포 SHA·build/deploy 상태와 실제 page_url을 확인해 보고해줘.
진행 중·실패·환경 승인 필요·완료를 구분하고 필요한 승인 동작을 구체적으로 알려줘.
공개 게임 확인은 별도 수행 전까지 미확인으로 남겨줘.
```

### 공개 게임 확인과 회고

실제 URL을 열어 새로고침·JS/CSS 404·Console 오류를 보고, 목숨 3부터 재도전·최종 패배·재시작까지 확인합니다.
난이도 선택과 P도 함께 확인합니다. 내부 목숨 중복 차감·시간 정밀도는 자동 테스트 증거와 연결합니다.
배포 실패·대기 또는 공개 기능 오류가 있으면 CHG-03 완료를 보류합니다.
실제 실행·SHA·증상을 근거로 [07-05의 공개 실패 대응](07-05-redeploy-and-wrap-up.md)에 따라 수정·복구 계획을 별도 승인하고 재검증합니다.
보호 규칙을 끄거나 이전 배포 결과로 이번 실패를 숨기지 않습니다.

```text
CHG-03의 실제 배포 SHA·Actions URL·page_url과 공개 동작 확인 결과를 TEST_RESULTS.md에 추가해줘.
도구 결과·내 수동 관찰·미확인을 구분하고 이전 버전 기록은 보존해줘.
CHANGE_REQUEST.md·구현 계획은 검증 근거가 있는 범위만 완료 처리해줘.
CHG-01 시간·입력 변경, CHG-02 설정 변경, CHG-03 종료 규칙 변경의 차이를 회고로 정리해줘.
코드 수정·커밋·푸시는 하지 말고 문서 diff를 보여줘.
```

기록 diff 승인 후 해당 문서만 한국어 제목·본문으로 로컬 커밋하도록 요청합니다.
제목·본문에 09-02·CHG-03, 실제 배포 SHA·검증·미확인 범위를 적습니다.
