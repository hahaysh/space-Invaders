# 09-01. 목숨 3개와 재도전 규칙 설계

**9. 선택 확장 · CHG-03 요청과 영향 분석**

이전: [08-02 난이도 개선 완료](08-02-difficulty-implementation.md) · [전체 목차](00-overview.md) · 다음: [09-02 목숨 구현·검증·재배포](09-02-lives-implementation.md)

## 1. 설명

현재 게임은 적이 방어선에 도달하면 즉시 패배합니다. 적 탄환·피격·목숨 필드는 없습니다.
따라서 “목숨값을 3으로 바꿔줘”는 단순 상수 수정이 아니라 **패배 조건과 재도전 흐름의 변경**입니다.
이번에는 적 탄환을 새로 만들지 않고 방어선 도달을 목숨 차감 사건으로 사용합니다.

제안은 **3 → 2 → 1 → 0**, 남은 목숨이 있으면 참가자가 재도전을 선택하고, 0이면 패배하는 방식입니다.
자동으로 바로 재시작하지 않아 상태 변화와 목숨 감소를 눈으로 확인할 수 있습니다.
재도전은 같은 단일 웨이브의 새 시도이며 다음 레벨 진입이 아닙니다.

특히 **실패한 시도의 점수는 재도전 시작 때 0으로 초기화**하도록 제안합니다.
편대 전체를 복구하면서 이전 점수를 계속 더하면 같은 적을 반복해서 잡아 기존 최대 점수 240점을 넘길 수 있기 때문입니다.
다른 점수 정책을 원하면 아래 설계 승인 전에 변경하고 테스트 기대값까지 함께 맞춥니다.
기존 두 샘플에는 이 기능이 없으며 CHG-03 구현·실행 리허설은 아직 하지 않았습니다.

## 2. 시작 상태

- [ ] 08단계 난이도 선택과 CHG-01 P 기능의 필수 로컬 검증이 완료되었다.
- [ ] 직전 기준 코드·검증·배포 증거 또는 미배포 상태를 보존했다.
- [ ] 기존 `CHANGE_REQUEST.md`의 CHG-01·CHG-02 이력을 덮어쓰지 않는다.
- [ ] **Plan** 모드에서 새 작업 기준을 먼저 확인한다.

```text
참가자 게임 저장소의 브랜치·작업 상태·main 관계를 읽기 전용으로 확인해줘.
CHG-02가 반영된 기준 SHA와 아직 main에 없는 코드·검증·배포 기록을 식별해줘.
병합된 이전 브랜치를 그대로 재사용하지 않도록 CHG-03 작업 기준 준비 계획을 제안해줘.
로컬 전용 진행이면 그 기준을 명시하고 배포 이력을 지어내지 마.
변경을 버리는 reset·clean·강제 푸시는 금지한다.
아직 fetch·브랜치 전환·파일 변경은 하지 말고 승인을 기다려줘.
```

계획을 확인하고 **Interactive**에서 준비만 승인합니다.

```text
검토한 CHG-03 작업 기준 준비 계획만 승인한다. 필요한 원격 fetch를 허용한다.
승인한 CHG-02 기준에서 새 작업 브랜치 또는 app의 새 작업 세션을 준비해줘.
지원하지 않는 app 브랜치 작업은 우회하지 말고 필요한 참가자 동작을 알려줘.
미반영 코드·기록은 승인한 방식으로 보존하고 충돌하면 멈춰줘.
새 세션이면 AGENTS.md·개발 문서·기준 SHA와 승인 내용을 전달하도록 안내해줘.
요구사항·코드 수정·커밋·푸시는 아직 하지 마.
```

## 3. 실행: 목숨 규칙을 먼저 승인하기

다시 **Plan** 모드에서 다음 프롬프트를 사용합니다.

```text
AGENTS.md, ideation.md, PRD.md, TRD.md, IMPLEMENTATION_PLAN.md,
TEST_PLAN.md, TEST_RESULTS.md, CHANGE_REQUEST.md와 게임·입력·렌더·테스트를 읽어줘.
CHG-03 목숨 3개를 설계하되 아직 파일·코드는 변경하지 마.
현재 게임에 적 탄환이나 피격이 없다는 가정을 확인하고 다르면 차이를 먼저 알려줘.

아래 제안에 CHG-03-AC1부터 수용 기준 ID를 붙여 검토해줘.
- 새 게임과 won/lost에서 R 또는 재시작 버튼으로 시작할 때 목숨은 3이다.
- playing에서 탄환 충돌·점수 반영 후 살아 있는 적 하단이 y=520 이상이면
  목숨을 정확히 1 차감한다. 같은 프레임의 여러 적·서브스텝으로 중복 차감하지 않는다.
- 남은 목숨이 2 또는 1이면 retry 대기 상태, 0이면 lost이다. 음수가 되지 않는다.
- retry에서는 남은 목숨·실패한 시도의 점수와 재도전 안내를 보여준다.
  위치·탄환·점수·쿨다운·게임 시간은 멈추고 held keys를 비운다.
- retry에서 반복이 아닌 Enter 또는 재도전 버튼만 같은 웨이브를 다시 시작한다.
  R·P·이동·발사는 무시한다. 길게 누른 Enter 반복으로 재도전하지 않는다.
- 재도전은 남은 목숨과 현재 난이도를 보존하고 적 24개·플레이어 초기 위치·편대 방향,
  빈 탄환·0점·쿨다운·게임 시간·입력 등 해당 시도의 상태를 초기화한다.
  재개 시 RAF 시간 기준을 초기화하고 RAF 루프는 하나만 유지한다.
- 새 게임/종료 후 재시작은 선택한 난이도를 적용하고 목숨 3·점수 0으로 초기화한다.
- 모든 적을 제거하면 남은 목숨과 무관하게 won이다.
  마지막 적을 충돌로 제거했다면 차감하지 않는다.
  다른 살아 있는 적이 방어선에 남아 있으면 적 도달 처리가 우선이다.
- lost는 0목숨, won은 그때의 남은 목숨을 표시한다. 최종 시도의 점수는 유지한다.
- 목숨을 이미지 없이 '남은 목숨: 3' 같은 텍스트로 표시한다.
- 난이도는 title/won/lost에서만 선택한다. retry에서도 변경할 수 없다.
- P는 playing/paused에서만 동작한다. paused에서는 목숨·게임 시간도 변하지 않는다.
  모든 상태 전환·blur에서 입력을 해제하며 retry에서 오래 기다려도 재시작 점프가 없다.
- 적 속도 32/64/96, 적당 10점, 시도별 최대 240점, 발사 0.2초 등 나머지 규칙은 유지한다.
적 탄환·무적 시간·자동 부활 타이머·추가 목숨 획득·여러 웨이브·영구 저장은 제외한다.

REQ-06 즉시 패배 규칙 중 바뀌는 부분, REQ-07 새 게임과 재도전의 차이를 명시해줘.
CHG-01·CHG-02를 유지하면서 retry를 추가할 때 입력·UI·시간에 미치는 영향을 분석해줘.
문서별 수정 필요/불필요/추가 확인, 기준 → 상태 전환 → 파일 → 테스트를 연결해줘.
기존 테스트의 어떤 기대값이 승인된 규칙 변경 때문에 바뀌는지, 무엇은 그대로인지 설명해줘.
제안된 점수 초기화·수동 재도전 정책을 참가자가 승인하기 전에는 확정·구현하지 마.
```

### 함께 볼 상태 전환

| 사건 | 결과 | 남기는 값 / 초기화 |
|---|---|---|
| 새 게임 시작 | playing | 선택 난이도 적용, 목숨 3·시도 초기화 |
| 목숨 3에서 적 도달 | retry, 목숨 2 | 실패 시도 정지, 입력 해제 |
| 목숨 2에서 적 도달 | retry, 목숨 1 | 실패 시도 정지, 입력 해제 |
| retry의 Enter/버튼 | playing | 목숨·현재 난이도 유지, 점수 포함 시도 초기화 |
| 목숨 1에서 적 도달 | lost, 목숨 0 | 최종 점수 보존, 입력 해제 |
| 마지막 적 제거 | won | 남은 목숨·최종 점수 보존 |
| won/lost의 R/버튼 | playing | 선택 난이도 적용, 목숨 3·시도 초기화 |
| paused/retry의 시간 경과 | 그대로 | 시뮬레이션·목숨 변화 없음 |

`createGame()` 같은 새 게임 함수를 재도전에 그대로 쓰면 목숨까지 3으로 되돌릴 수 있습니다.
상태 초기화의 재사용은 권장하지만, **새 게임 초기화와 같은 게임의 재도전 초기화**의 책임을 구분해야 합니다.

### 승인 후 필요한 문서만 수정

**Interactive**로 바꾸고 정책과 변경 범위를 명시적으로 승인합니다.

```text
검토한 CHG-03 규칙을 승인한다. 특히 수동 재도전, 재도전 시 점수 0,
남은 목숨·난이도 보존, 목숨 0일 때만 패배 정책을 승인한다.
CHANGE_REQUEST.md에 CHG-03과 기준 SHA·수용 기준·승인 상태를 추가해줘.
CHG-01·CHG-02와 이전 검증·배포 기록은 보존해줘.
합의한 PRD·TRD·구현 계획·테스트 계획만 수정하고 REQ-06·REQ-07의 변경 이력을 남겨줘.
이전 규칙을 아무 설명 없이 지우거나 '기존 요구사항 모두 변경 없음'이라고 쓰지 마.
TEST_RESULTS.md에는 새 검증 영역을 미실행으로 준비하고 과거 결과는 고치지 마.
AGENTS의 '목숨 제외' 같은 작업 제한이 남아 있으면 승인된 CHG-03만 허용하도록 조정해줘.
ideation 등 나머지 문서는 수정 필요성이 있을 때만 변경하고 이유를 남겨줘.
코드·테스트 코드·의존성·워크플로는 변경하지 마.
diff와 기준별 설계·검증 연결표를 보여주고 기다려줘.
```

`AGENTS.md`를 바꿨다면 에이전트가 다시 읽고 허용 범위를 요약하도록 요청합니다.
이 명시적 읽기가 app의 자동 지침 재적용을 검증했다는 뜻은 아닙니다.

## 4. 함께 점검·확인

- [ ] 기존 목숨값 수정이 아닌 새로운 규칙·상태 추가라는 점이 명확하다.
- [ ] 한 번 도달에 한 번만 차감하고 0에서만 패배하도록 설계했다.
- [ ] 재도전과 새 게임의 목숨·난이도·점수 초기화 차이가 표와 문서에 일치한다.
- [ ] 점수 초기화 이유와 한 시도의 최대 240점을 이해하고 승인했다.
- [ ] retry에서 R로 목숨을 다시 채우거나 난이도를 바꾸는 우회가 없다.
- [ ] CHG-01 시간·입력 처리, CHG-02 선택 제한에 retry가 반영되었다.
- [ ] 이전 패배 테스트에서 의도적으로 변경할 기대값과 유지할 회귀 검사를 구분했다.

## 5. 보완과 재확인

```text
CHG-03 문서만 읽고 상태 전환·목숨 차감·점수·난이도·입력 정책의 불일치를 찾아줘.
동일 프레임 중복 차감, 재도전 때 목숨 3 복구, retry에서 R/P 처리,
충돌과 적 도달의 우선순위에 검증 공백이 있는지 확인해줘.
기준별 보완안을 제시하고 승인 전 수정·구현·테스트 실행은 하지 마.
```

보완안을 승인한 뒤 필요한 문서만 고치고 수용 기준 연결표를 다시 확인합니다.
