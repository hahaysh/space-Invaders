# 02-02. 요구사항 작성

[이전](02-01-게임-아이디어.md) · [전체 목차](00-전체-실습-안내.md) · [다음: 기술 설계](02-03-기술-설계.md)

## 이번 실습

아이디어를 “무엇을 하면 어떤 결과가 보여야 하는가”로 바꿉니다.
공통 수치는 이번 PRD에 한 번 정하고 이후 문서는 이 기준을 참조합니다.
코드의 함수 이름이나 내부 파일 구조를 요구사항으로 정하지 않습니다.

## 시작 전

- `AGENTS.md`와 승인한 `ideation.md`가 있습니다.
- App **Plan**에서 제품 기준을 검토합니다.
- 첫 버전에는 일시정지·난이도가 없고, 기본 피격을 위한 목숨 3개가 있습니다.

## 공통 기본값

좌표는 Canvas 왼쪽 위가 원점이고 사각형의 위치는 왼쪽 위입니다.
시간은 초, 속도는 px/s입니다. 행·열 인덱스는 0부터 시작합니다.
아래 표를 PRD의 기준표로 사용합니다.

| 항목               | 기본값                                                                 |
| ------------------ | ---------------------------------------------------------------------- |
| 화면·플레이어     | 800×600, 크기 40×20, 초기 위치 (380,550), 속도 320                   |
| 플레이어 탄환      | 4×12, 위쪽 속도 600, 발사 간격 0.2초, 화면 밖 제거                         |
| 적 탄환            | 4×10, 아래쪽 속도 220, 발사 간격 1초, 화면 밖 제거                           |
| 탄환 출발          | 플레이어 수평 중앙,**탄환 바닥 = 플레이어 위쪽**; 초기 (398,538) |
| 적 편대            | 3행×8열=24, 크기 40×24, 위치 (112+72×열,72+48×행)                  |
| 적 이동            | 초기 오른쪽, 속도 64, 가장자리에서 방향 반전과 24 하강                 |
| 점수·목숨·방어선 | 적 하나 10점, 최대 240점, 목숨 3개, 적 바닥이 y=520에 닿으면 패배      |

## 플랫폼과 입력 범위

이번 버전의 공식 지원 환경은 키보드를 사용할 수 있는 데스크톱 브라우저입니다.
시작·재시작 버튼과 키보드 입력을 필수 조작으로 정의하며, 모바일 터치 조작이나
가상 조작 버튼은 제공하지 않습니다. 작은 화면에서 Canvas가 비율을 유지해 보이는
것과 모바일에서 게임을 플레이할 수 있다는 것은 별개의 기준입니다.

모바일 브라우저의 터치 플레이, 화면 회전 대응, 모바일 전용 레이아웃과 터치 영역은
이번 요구사항과 완료 기준에서 제외합니다. 해당 환경에서 실제로 확인하지 않은 동작을
모바일 지원 완료로 기록하지 않습니다. 모바일 지원은 별도 후속 개선에서 다시 설계합니다.

## 참고 자료 전달과 요구사항 제안

1. 위 **공통 기본값 절의 좌표·단위 설명과 표 전체**, **플랫폼과 입력 범위 절**을 복사합니다.
2. 아래 Plan 프롬프트와 **같은 메시지**에 참고 자료로 붙여 넣어 전달합니다. 프롬프트만 보내지 않습니다.
3. 응답의 기준표가 전달한 표의 모든 항목을 포함하는지 대조한 뒤 같은 대화에서 작성을 승인합니다.

표는 PRD를 만들기 위한 입력 자료입니다. 승인 후에는 참가자 저장소의 `PRD.md`를 제품 기준으로
참조하며, 이후 구현 프롬프트에 수치를 다시 나열하지 않습니다.

**모드: Plan**

```text
AGENTS.md와 ideation.md를 읽고 우주 방어 PRD 구성을 제안해 줘.
함께 전달한 공통 기본값과 플랫폼·입력 범위를 먼저 확인해 줘.
자료가 없거나 일부가 빠졌으면 필요한 자료를 알려 주고 멈춰 줘.
기본값 전체를 PRD의 한 기준표로 두고 요구사항 ID와 관찰 가능한 완료 조건을 붙여 줘.
M1·M2 구현 시점과 관계없이 제공된 제품 수치는 지금 함께 정의해 줘.
기존 문서와 충돌하면 차이와 이 기준에 맞춘 최소 수정안을 제시하되 아직 수정하지 마.
title/playing/won/lost, 시작 버튼·Enter, 좌우 화살표·A/D, Space 발사를 정의해 줘.
playing에서는 플레이어 이동·발사와 적 편대 이동·하강·발사를 처리하고,
won/lost에서는 재시작 버튼·R로 새 게임을 시작해.
적 탄환이 플레이어에 맞으면 목숨을 1개 차감하고, 목숨이 남으면 현재 판을 즉시 초기화해
자동으로 다음 시도를 시작해. 목숨이 0이면 lost로 종료하며, 적 탄환 하나가 여러 번
피격을 만들지 않게 해. retry 화면·버튼·상세 안내는 후속 목숨 확장에서 추가해.
좌우 경계·동시 반대 입력·키 반복·포커스 이탈 시 입력 정리를 명확히 해 줘.
플레이어는 화면 좌우 경계를 벗어나지 않고, 반대 방향 동시 입력이면 이동하지 않아.
Space를 누르고 있으면 발사 간격을 지키며, 시작·재시작은 키 반복으로 중복 실행하지 않아.
게임 조작에 필요한 키의 기본 동작만 차단하고 포커스 이탈 시 입력을 비워 줘.
자동 일시정지는 추가하지 마.
충돌은 탄환 하나당 적 하나, 점수 중복 없이 처리하고 종료 후 진행을 멈춰.
한 번의 갱신에서는 플레이어 탄환과 적의 충돌을 먼저 처리해.
플레이어 탄환이 마지막 적을 제거하면 방어선 도달이나 적 탄환 피격이 동시에
발생해도 won으로 종료하고 목숨은 차감하지 마.
마지막 적이 남아 있을 때만 방어선 도달과 적 탄환 피격을 처리해.
피격 이벤트가 여러 개여도 한 갱신에서 목숨은 최대 1개만 차감해.
적이 남아 있는 상태에서 방어선 도달과 적 탄환 피격이 동시에 발생하면
방어선 도달을 우선해 즉시 lost로 종료하고 목숨 차감이나 자동 다음 시도는 하지 마.
재시작과 피격 후 자동 다음 시도는 점수·적·플레이어·탄환·시간·입력을 초기화하고,
새 게임은 목숨 3개로, 다음 시도는 남은 목숨을 보존해 시작해.
UI 안내·README·실제 검증을 필수로 하고 제외 범위는 유지해 줘.
공식 지원은 데스크톱 키보드·버튼 조작이며 모바일 터치·가상 버튼·회전 대응은 제외해 줘.
반응형 표시는 모바일 플레이 지원과 구분해 줘.
아직 파일이나 코드는 바꾸지 말고 모호한 결정만 짧게 알려 줘.
```

상반된 방향을 동시에 누르면 이동하지 않는 것을 기본으로 선택합니다.
시작·재시작 같은 단발 동작은 키 반복으로 여러 번 실행되지 않아야 합니다.
Space는 진행 중 누르고 있으면 간격에 맞게 발사하며, 페이지 스크롤을 방지합니다.
게임 키의 기본 동작 차단은 게임 조작에 필요한 범위로 제한합니다.
브라우저 포커스를 잃을 때 입력을 비우되 자동 일시정지는 추가하지 않습니다.

## 승인 후 작성

App을 **Interactive**로 전환합니다.

**모드: Interactive**

```text
앞 Plan에서 확인한 공통 기본값과 검토한 동작을 승인해. PRD.md를 작성해 줘.
전달된 자료나 합의 내용을 확인할 수 없으면 작성 전에 알려 주고 멈춰 줘.
각 요구사항의 완료 조건을 자동 검사와 실제 화면 확인에 연결할 수 있게 써 줘.
수치표는 한 곳에 유지하고 일시정지·난이도는 지금 구현하지 마.
작성 후 전달한 표의 각 항목이 PRD의 어느 기준 ID 또는 절에 반영됐는지 알려 줘.
누락·미정·충돌이 있으면 완료로 표시하지 말고 남은 항목을 보고해 줘.
```

## 눈으로 확인

- [ ] 표의 좌표·탄환 출발점·점수·패배선에 모순이 없습니다.
- [ ] 참고 자료 전체를 App에 전달했고 실제 PRD의 기준 ID·절과 대조했습니다.
- [ ] 공통 기본값 전체가 실제 PRD에 기재됐고 제공한 수치가 미정으로 남아 있지 않습니다.
- [ ] 모든 필수 동작에 관찰 가능한 수용 기준이 있습니다.
- [ ] 충돌·승패 우선순위와 종료 후 정지가 명확합니다.
- [ ] 재시작이 새 게임 상태를 만들고 입력이 남지 않습니다.
- [ ] 필요한 UI·README·검증이 범위에 포함됐습니다.
- [ ] 데스크톱 키보드 지원과 모바일 터치·가상 버튼·회전 대응 제외가 명확합니다.
- [ ] 반응형 Canvas 표시를 모바일 게임 지원으로 잘못 해석하지 않습니다.
- [ ] 적 탄환의 발사 주체·간격·속도와 피격 시 목숨 차감·자동 다음 시도·최종 패배가 명확합니다.
- [ ] 적 잔존 상태에서 방어선 도달과 피격이 겹치면 방어선 도달 우선으로 `lost` 처리합니다.

## 필요할 때만 보완

**모드: Plan**

```text
PRD와 앞서 전달한 참고 자료를 비교해 누락·미정·충돌과 관찰할 수 없는 조건을 찾아 줘.
기존 요구사항 ID를 보존하는 최소 수정안만 제안해 줘. 파일 변경이나 새 기능 추가는 하지 마.
```

## 완료

보완이 필요하면 자료를 다시 전달하고 Plan 검토·승인 후 작성을 반복합니다.
필수 수치가 미정인 상태에서는 다음 기술 설계로 넘어가지 않습니다.
`PRD.md`가 첫 버전의 공통 기준입니다.
다음 실습에서는 이 요구사항을 구현하고 검증할 기술을 정합니다.
