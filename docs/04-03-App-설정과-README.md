## 이번 실습

실제로 동작하는 명령을 App의 수동 버튼과 README에 연결합니다.
이것이 두 `.github` 커스터마이징 중 첫 번째이며, 기본 게임 M3 이슈의 작업입니다.
M2 PR이 main에 병합된 뒤 독립 세션에서 시작하고, 로컬 검토를 마친 결과를 M3 PR로
main에 병합하되 아직 배포 성공으로 부르지 않습니다.

## 시작 전

- M2 PR이 병합된 최신 main에서 시작한 M3 세션에 게임 코드와 실제 `package.json` scripts가 있습니다.
- 로컬 게임·검사·빌드가 동작하며 남은 문제를 알고 있습니다.
- App **Plan**으로 설정과 공개할 파일을 검토합니다.

## App 설정과 README 계획

[공식 저장소 설정](https://docs.github.com/en/copilot/reference/github-copilot-app-reference/repository-configuration)을 기준으로 합니다.
`.github/github-app.yml`의 `scripts`는 `{name, command}` 항목의 **목록**입니다.
`triggers`를 생략하면 수동 실행이며 `auto_open_in_browser`를 사용할 수 있습니다.
이번에는 자동 설치·삭제·세션 시작/종료 Hook을 넣지 않습니다.

**모드: Plan**

```text
M3 이슈·AGENTS.md·PRD.md·TRD.md·계획 표와 현재 package.json scripts·실제 실행 결과를 읽어 줘.
M2 PR의 실제 병합과 현재 base·브랜치의 M2 코드 반영을 확인하고 아니면 상태를 알려 주고 멈춰 줘.
.github/github-app.yml에 수동 Run과 필요하면 Test를 만드는 최소안을 제안해 줘.
scripts는 name/command 목록, triggers 없음, auto_open_in_browser 지원 형식을 써 줘.
실제 dev 명령과 5173을 사용하고 AGENTS 지침 본문을 복제하지 마.
README.md에는 우주 방어 제목·조작·적 탄환·피격·목숨 표시·재시작·설치·실행·검사·빌드 방법을 제안해 줘.
공개 URL은 아직 없으므로 배포 예정으로만 표시해 줘.
자동 설치/삭제·무조건 도구 승인·다른 .github 커스터마이징은 만들지 마.
```

## 승인 후 작성과 설정 신뢰

App을 **Interactive**로 전환합니다.

**모드: Interactive**

```text
승인한 App 설정과 README.md를 작성해 줘.
계획 표의 M1·M2 기록을 보존하고 승인한 M3 작업과 실제 확인 결과를 추가해 줘.
실제 명령이 manifest와 일치하는지 확인하고 M3의 로컬 검사·빌드를 실행해 줘.
설정 검토가 필요한 App 화면과 현재 diff를 알려 주고 병합 전에는 멈춰 줘.
```

에이전트가 파일을 쓰는 것은 App 설정 UI 바깥의 변경일 수 있습니다.
App이 표시한 설정 내용을 읽고 **review/accept**해야 현재 설정이 적용됩니다.
외부에서 공백·주석만 바뀌어도 다시 검토해야 하며, 미승인 상태에는 이전 설정이 사용됩니다.
명령은 GitHub 자격 증명을 상속할 수 있으므로 환경 변수·토큰을 출력하거나 저장하는 명령은 거절합니다.
수락 후 수동 **Run**을 눌러 실제 URL·응답·게임 화면을 확인합니다.
이미 같은 세션의 서버가 있으면 중복 실행하지 말고 그 서버만 정상 종료 후 확인합니다.

demo02에서는 파일·명령을 확인했지만 App UI 확인 도구가 안전 정책으로 거부됐습니다.
참가자는 위 수락·Run을 직접 확인하며, 도구로 확인할 수 없으면 우회하지 않고 UI 미확인으로 남깁니다.

## M3 PR 생성

diff와 로컬 결과를 확인한 뒤 아래 원격 작업을 승인합니다.

**모드: Interactive**

```text
M3 이슈의 완료 조건을 충족했는지 확인하고, 미충족이면 남은 항목을 알려 주고 멈춰 줘.
충족했다면 M3 완료 근거를 계획 표에 정리하고 검토한 파일만 한국어 커밋·푸시해 줘.
main 대상 M3 PR을 만들어 목표·변경·실제 검사·미확인을 적어 줘.
수용 기준을 충족한 M3 이슈만 Fixes로 연결하고 병합 전에는 멈춰 줘.
이 PR은 최초 배포가 아니라 기본 코드 병합이라고 명시해 줘.
```

## 검토 후 M3 병합

사람이 App PR 화면이나 GitHub 웹에서 base·diff·검사·비밀 유무를 확인하고 승인한 뒤에만 전달합니다.

**모드: Interactive**

```text
검토한 main 대상 M3 PR의 병합을 승인해. 해당 PR만 병합해 줘.
필수 검사·보호 규칙·권한 문제로 병합할 수 없으면 우회하지 말고 상태와 필요한 조치를 알려 줘.
실제 병합 여부와 원격 main의 게임·README·App 설정·계획 반영, M3 이슈 종료 여부를 확인해 줘.
아직 배포나 검증·배포 이슈 생성은 하지 마.
```

## 눈으로 확인

- [ ] README의 조작·명령이 실제 게임과 manifest에 맞습니다.
- [ ] 설정은 수동 scripts 목록이며 자동 설치·삭제나 지침 중복이 없습니다.
- [ ] App에서 현재 설정을 검토·수락하고 Run 동작을 확인했습니다.
- [ ] M3 PR의 대상이 main이며 M3 이슈 수용 기준과 로컬 근거가 있습니다.
- [ ] 병합된 원격 main을 확인했고 배포 완료로 표시하지 않았습니다.
- [ ] M3 이슈 종료를 확인했습니다.

## 필요할 때만 보완

```text
App이 실제 적용 중인 설정과 파일 내용을 비교해 줘.

```
