# 07-04. 새 기능·기존 기능 검증

**7. 개선 사이클 · 변경과 회귀 테스트**

이전: [07-03 변경 구현](07-03-change-implementation.md) · [전체 목차](00-overview.md) · 다음: [07-05 재배포와 회고](07-05-redeploy-and-wrap-up.md)

## 1. 설명

P가 동작한다는 사실만으로 개선 버전을 배포할 수는 없습니다.
공통 입력·시간 처리 변경이 시작, 발사, 종료, 재시작을 망가뜨렸을 수 있습니다.
**변경 테스트는 CHG-01을, 회귀 테스트는 기존 REQ-01~08을 확인**합니다.
자동 테스트와 브라우저 수동 관찰을 함께 기록하고 미실행 항목은 통과로 쓰지 않습니다.

## 2. 시작 상태

- [ ] CHG-01 구현과 관련 테스트가 승인·로컬 커밋되었다.
- [ ] 최초 버전 결과를 보존하고 개선 결과 영역을 분리했다.
- [ ] `TEST_PLAN.md`에 변경 기준과 전체 회귀 항목이 있다.
- [ ] **Plan** 모드에서 실행 범위와 현재 기준 커밋을 확인한다.

## 3. 실행: 검증 계획과 실행 승인

```text
AGENTS.md, CHANGE_REQUEST.md, PRD.md, TEST_PLAN.md, TEST_RESULTS.md를 읽어줘.
현재 개선 버전의 변경·회귀 검증 계획을 읽기 전용으로 점검해줘.
CHG-01 기준과 REQ-01~08 각각에 자동/수동 확인, 기대값, 증거 위치를 연결해줘.
정지 중 시간·쿨다운, 키 반복과 blur, 재개 dt, 중복 루프를 포함해줘.
실행 환경, 현재 커밋, 명령, 미확인 항목을 기록할 형식을 제시해줘.
파일 수정·테스트 실행·설치는 아직 하지 말고 기다려줘.
```

검증 계획을 확인한 뒤 **Interactive**로 전환합니다.

```text
검토한 변경·전체 회귀 검증 계획을 승인한다.
npm test, npm run test:e2e, npm run build를 실행해줘.
의존성이 없을 때만 npm ci, 브라우저가 없을 때만 Chromium 설치를 허용한다.
로컬 빌드 브라우저 확인을 위해 npm run preview를 실행하고 실제 주소를 알려줘.
각 실행의 종료 상태와 오류를 보존하며 실패를 무시하지 마.
TEST_RESULTS.md의 개선 검증 영역에 실제 결과만 기록해줘.
실패 원인 분석은 허용하지만 코드·테스트 기대값 수정은 별도 승인까지 하지 마.
푸시·PR·배포 없이 결과와 남은 수동 확인 항목을 보여주고 기다려줘.
```

### 변경 테스트: CHG-01

| 상황 | 기대 결과·증거 |
|---|---|
| playing에서 P 한 번 | paused와 안내 표시, 움직임 정지 |
| P를 누른 채 유지 | 반복 keydown 무시, 한 번만 상태 전환 |
| 정지 중 여러 업데이트 | 플레이어·적·탄환·점수·쿨다운 값 동일 |
| 정지 중 방향키·Space | 이동·발사 없음, 재개 후 잔류 입력 없음 |
| 이동·발사 중 P | 전환 시 held keys 비움, 키를 다시 눌러야 동작 |
| 창 포커스 이탈·복귀 | blur에서 키 상태 제거, 자동 pause는 요구하지 않음 |
| 긴 정지 후 P 재개 | 최초 프레임 위치 점프·즉시 쿨다운 만료 없음 |
| 10회 정지·재개 | 게임 속도 유지, RAF 중복 예약 없음 |
| title/won/lost에서 P | 화면과 상태 유지 |

쿨다운은 예를 들어 발사 후 게임 시간 0.1초 경과 상태에서 정지하여 확인합니다.
긴 실제 시간을 기다려도 재개 시 남은 0.1초가 보존되는지를 테스트합니다.
내부 검사는 제어된 시간으로 실행하고 임의의 긴 sleep에만 의존하지 않습니다.
RAF 중복은 속도 관찰뿐 아니라 예약 경로·콜백 개수에 대한 코드 또는 자동 검증도 봅니다.

### 기존 기능 전체 회귀

| 요구사항 | 유지되어야 하는 결과 |
|---|---|
| REQ-01 시작 | title에서 Enter 또는 시작 버튼으로 playing |
| REQ-02 이동 | 800×600, 플레이어 40×20·y=550, 방향키·A/D, 화면 경계 |
| REQ-03 발사 | Space, 0.2초 쿨다운, 화면 밖 탄환 정리 |
| REQ-04 적 | 3행×8=24개, 기존 편대 이동·하강 규칙 유지 |
| REQ-05 충돌·점수 | 적 한 개당 10점, 중복 가산 없음 |
| REQ-06 종료 | 모든 적 제거 시 승리, 적 하단 y=520 도달 시 패배 |
| REQ-07 재시작 | 종료 후 R/버튼, 점수·적·탄환·시간·입력 초기화 |
| REQ-08 정적 전달 | 빌드·preview 정상, 하위 경로 설계 유지, 외부 CDN/에셋 없음 |

최초 버전과 마찬가지로 단일 웨이브이며 적 탄환·목숨·사운드는 추가하지 않습니다.
실제 GitHub Pages 하위 경로 검증은 다음 단계의 공개 URL에서 다시 수행합니다.
로컬 preview 성공을 원격 배포 성공으로 기록하지 않습니다.

### 예상 결과

요구사항 ID, 실행 환경·커밋, 명령·절차, 기대값, 실제값, 판정, 증거가 남습니다.
자동 실패, 수동 미확인, 실행 환경 오류는 서로 구분합니다.
기존 결과를 지우지 않고 개선 버전의 재실행 이력을 추가합니다.

## 4. 함께 점검·확인

참가자가 preview의 실제 주소를 열고 변경 테스트 표를 따라 조작합니다.
게임을 시작한 뒤 P를 누르고 기다렸다가 재개하고, 키를 누른 채 창을 전환합니다.
자동 테스트가 확인한 종료·재시작도 가능한 범위에서 수동으로 비교합니다.

```text
내가 실제 관찰한 수동 결과만 개선 검증 기록에 반영해줘.
도구 실행 결과와 수동 관찰을 구분하고 재현하지 못한 항목은 미확인으로 남겨줘.
CHG-01과 REQ-01~08의 최종 판정표 및 배포를 막는 항목을 보여줘.
자동 테스트가 통과했다는 이유로 수동 미확인 항목을 통과로 바꾸지 마.
```

- [ ] 변경 수용 기준과 기존 요구사항에 빠진 행이 없다.
- [ ] 실패·미확인이 명시되고 실제 증거 없이 성공 표시가 없다.
- [ ] 쿨다운·RAF·키 상태를 화면 정지만으로 판단하지 않았다.
- [ ] 원격 배포 확인은 아직 미수행으로 남겼다.

## 5. 보완과 재확인

```text
실패 항목의 재현 절차, 기대/실제 차이, 원인 후보와 최소 수정안을 제시해줘.
관련 요구사항과 테스트를 연결하고 승인 전에는 코드를 수정하지 마.
단순 재시도로 성공한 결과만 남기거나 테스트를 삭제하지 마.
```

수정안을 승인한 뒤 아래 요청을 사용합니다.

```text
제안한 최소 수정과 재현 테스트 추가를 승인한다.
수정 후 해당 테스트뿐 아니라 npm test, npm run test:e2e, npm run build를 다시 실행해줘.
영향받는 수동 항목도 재확인 대상으로 제시하고 실패→수정→재검증 이력을 기록해줘.
모두 통과하기 전에는 재배포하지 말고 결과 검토를 기다려줘.
```

## 6. 완료 승인

필수 로컬 검증의 실패·미확인을 해결한 뒤 승인합니다.

```text
개선 버전 변경·회귀 검증 결과를 승인한다.
승인 파일만 구체적인 한국어 제목과 본문으로 로컬 커밋해줘.
제목 예시: '07-04: 일시정지 경계 조건과 기존 전체 요구사항의 회귀 검증 결과 기록'
본문에 단계 ID 07-04와 요구사항 ID, 변경 내용·이유, 실행 명령과 실제 결과를 적어줘.
수정이 있었다면 원인도 적고 아직 공개 재배포 전이라는 미확인 범위를 명시해줘.
변경이 없는 파일은 커밋에 넣지 말고, 푸시·배포는 다음 승인까지 기다려줘.
```
