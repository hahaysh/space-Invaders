# 08-01. 난이도 선택 요청과 변경 설계

**8. 선택 확장 · CHG-02 설계**

이전: [07-05 기본 과정 마무리](07-05-redeploy-and-wrap-up.md) · [전체 목차](00-overview.md) · 다음: [08-02 난이도 구현·검증·재배포](08-02-difficulty-implementation.md)

## 1. 설명

“조금 더 쉽게 또는 어렵게 플레이하고 싶다”는 피드백을 **시작 전 난이도 선택**으로 바꿉니다.
적 수·탄환·이동 속도를 한꺼번에 바꾸지 않고 **적의 수평 이동 속도 하나만** 바꿉니다.
그래야 실제 변경 효과를 수치로 확인하고, 설정을 추가하는 수정과 기존 기능의 회귀를 구분할 수 있습니다.

| 변경 요청 | 배우는 것 | 이번 범위 |
|---|---|---|
| CHG-01, 완료된 기준 | 입력·시간 처리 변경 | P 키 일시정지·재개 유지 |
| CHG-02, 이번 사이클 | 설정과 기본값, UI·모델 연결 | 쉬움·보통·어려움 선택 |
| CHG-03, 다음 사이클 | 상태와 종료 규칙 변경 | 목숨 3개·재도전, 지금은 구현하지 않음 |

여기서 난이도는 자동으로 상승하는 레벨이 아닙니다. 여러 웨이브나 적 탄환은 추가하지 않습니다.
아래 수치는 **승인할 제안값**입니다. 참가자가 다른 값을 원하면 구현 전에 PRD·설계·테스트 기대값을 함께 조정하고 승인합니다.
기존 참고 샘플은 CHG-01까지만 구현되어 있습니다. CHG-02는 아직 구현·실행 리허설을 하지 않은 실습 시나리오입니다.

## 2. 시작 상태

- [ ] 07단계 게임, P 동작, 기존 테스트가 동작하며 기준 커밋을 확인했다.
- [ ] 직전 배포 SHA·URL과 로컬 검증 결과를 보존했다. 원격 배포를 생략했다면 미배포라고 기록한다.
- [ ] 대상은 참가자의 게임 저장소이며 안내서 저장소나 참고 샘플 폴더가 아니다.
- [ ] Copilot app의 **Plan** 모드에서 시작한다.

### 새 변경의 작업 기준 준비

```text
현재 참가자 게임 저장소, 브랜치, 작업 상태와 main의 관계를 읽기 전용으로 확인해줘.
직전 CHG-01 코드·검증·배포 기록과 main에 없는 로컬 커밋 위치를 확인해줘.
최신 main에 CHG-01이 있는지 확인하고, 보존할 기록과 새 CHG-02 작업 기준을 제안해줘.
원격 배포를 생략했다면 성공으로 추정하지 말고 로컬 전용 경로로 표시해줘.
아직 fetch·브랜치 전환·파일 수정·커밋·푸시는 하지 마.
reset·clean·강제 푸시로 기존 작업을 버리지 말고 승인을 기다려줘.
```

계획과 보존할 파일을 확인한 뒤 **Interactive**에서 준비만 승인합니다.

```text
검토한 CHG-02 작업 기준 준비 계획만 승인한다. 필요한 원격 fetch를 허용한다.
승인한 기준에서 새 작업 브랜치 또는 app의 새 작업 세션을 준비해줘.
현재 세션에서 지원되지 않는 브랜치 작업은 임의 우회하지 말고 app에서 필요한 동작을 알려줘.
미반영 문서·코드·기록은 승인한 방식으로 보존하고 충돌하면 멈춰줘.
새 세션이 필요하면 기준 SHA, AGENTS.md, 개발 문서와 승인 내용을 전달할 목록을 제시해줘.
요구사항 작성·코드 수정·푸시·PR은 아직 하지 마.
```

## 3. 실행: 요청 구체화와 영향 분석

다시 **Plan** 모드로 전환합니다. 아래 프롬프트는 난이도 값을 포함하므로 안내서를 별도로 첨부하지 않아도 됩니다.

```text
AGENTS.md, ideation.md, PRD.md, TRD.md, IMPLEMENTATION_PLAN.md,
TEST_PLAN.md, TEST_RESULTS.md, CHANGE_REQUEST.md와 관련 코드를 읽어줘.
CHG-01은 유지하고 CHG-02 난이도 선택을 설계해줘. 아직 파일·코드는 수정하지 마.

다음 제안에 CHG-02-AC1부터 수용 기준 ID를 붙여 검토해줘.
- 쉬움/easy: 적 수평 속도 32 px/s, 보통/normal: 64 px/s, 어려움/hard: 96 px/s.
- 최초 기본 선택은 보통. title/won/lost에서만 난이도를 선택할 수 있다.
- 시작·재시작 시 선택값을 해당 게임의 고정 설정으로 적용한다.
- playing/paused에서는 선택 UI를 비활성화하고 모델에서도 변경을 막는다.
- 현재 난이도를 텍스트로 표시한다. 선택값은 브라우저 새로고침 시 보통으로 돌아온다.
- 보통은 이전 게임의 적 속도 64 px/s 및 기존 규칙을 유지한다.
- 적 24개, 하강 24 px, 적당 10점, 최대 240점, 발사 간격 0.2초,
  플레이어·탄환 속도, 방어선 y=520, 단일 웨이브는 바꾸지 않는다.
- P 정지·재개와 입력 해제, 단일 RAF, 재개 시간 초기화를 유지한다.
- label이 있는 기본 select를 사용하고 키보드로 선택할 수 있게 한다.
  select 조작을 게임의 방향키·Enter 단축키가 가로채지 않도록 설계한다.
- 미지정 난이도 기본값과 지원하지 않는 값 오류를 구분한다.
  잘못된 값은 기존 오류 처리 방식으로 명시하고 보통으로 조용히 대체하지 않는다.
목숨·적 탄환·여러 웨이브·자동 레벨 상승·저장 기능·새 의존성은 제외한다.

현재 구현과 위 가정이 다르면 차이를 보고하고 임의로 기존 규칙을 덮어쓰지 마.
선택 예정값과 현재 게임 설정을 어떻게 구분할지, 편대 이동의 거리·벽 도달 시간 계산이
같은 난이도 속도를 사용하도록 어떻게 연결할지 제시해줘.
REQ-04 등의 의도적 변경 부분과 REQ-01~08·CHG-01의 유지 부분을 구분해줘.
수용 기준 → 영향 파일 → 구현 단위 → 자동/수동 테스트를 연결해줘.
문서별 수정 필요/불필요/추가 확인과 이유를 제안하고 승인을 기다려줘.
```

### 함께 결정할 변경 경계

| 항목 | 제안 |
|---|---|
| `CHANGE_REQUEST.md` | CHG-01을 보존하고 CHG-02 요청·기준 SHA·승인 상태 추가 |
| `PRD.md` | 기본 보통, 선택 가능 상태, 난이도 수치와 유지 규칙 |
| `TRD.md` | 공통 난이도 설정, 시작 시 적용, 입력·포커스 처리 |
| `IMPLEMENTATION_PLAN.md` | A 모델·규칙 테스트, B 선택 UI·브라우저 테스트 |
| `TEST_PLAN.md` | 난이도별 수치, 상태 제한, 보통 회귀, P 유지 |
| `TEST_RESULTS.md` | 이전 증거 보존, CHG-02는 미실행 영역으로 준비 |
| `ideation.md`·`AGENTS.md` | 방향·작업 범위가 바뀔 때만 수정, 미수정 이유 기록 |

하드코딩된 기존 적 속도를 지우기만 해서는 충분하지 않습니다. 벽까지 걸리는 시간 계산에 옛 속도가 남으면 실제 이동과 하강이 어긋납니다.

### 승인 후 문서 반영

**Interactive**에서 요청과 문서 범위만 승인합니다.

```text
검토한 CHG-02 수용 기준과 영향 분석, 필요한 문서 수정 범위를 승인한다.
CHANGE_REQUEST.md에 CHG-02를 추가하고 CHG-01 요청·완료 증거는 덮어쓰지 마.
승인한 PRD·TRD·구현 계획·테스트 계획을 갱신하고 기준 ID로 연결해줘.
REQ-04의 난이도별 확장과 기본 보통의 호환성을 구분해줘.
TEST_RESULTS.md는 이전 기록을 유지하고 이번 결과는 미실행으로 표시해줘.
ideation·AGENTS는 책임 변화가 있을 때만 수정하고 이유를 남겨줘.
코드·테스트 코드·의존성·워크플로는 변경하지 마.
문서 diff와 수용 기준 연결표를 보여주고 기다려줘.
```

## 4. 함께 점검·확인

- [ ] 쉬움·보통·어려움의 수치와 최초 기본값이 명확하다.
- [ ] 시작·재시작 시점의 선택값 적용과 플레이 중 변경 금지가 모델·UI에 모두 설계되어 있다.
- [ ] select 키보드 조작이 게임 단축키와 충돌하지 않는다.
- [ ] 보통의 이전 규칙과 모든 난이도의 P 기능을 회귀 대상으로 남겼다.
- [ ] CHG-03 목숨 기능을 미리 구현할 계획이 없다.
- [ ] 변경 요청·PRD·TRD·테스트의 수치가 같고 결과는 아직 미실행이다.

## 5. 보완과 재확인

```text
CHG-02 문서에서 난이도 값, 적용 시점, 상태 제한, 기존 규칙과의 충돌을 읽기 전용으로 점검해줘.
기준별 충족/보완 필요/미확인을 표시하고 보완안을 제시해줘.
구현·테스트 실행이나 미승인 문서 수정은 하지 마.
```

보완안을 승인한 뒤 해당 문서만 수정하고 같은 표를 다시 확인합니다.

```text
CHG-02 요청·설계 문서의 최종 diff를 승인한다.
승인 파일만 한국어 제목·본문으로 로컬 커밋해줘.
제목 예시: '08-01: 난이도 선택의 수치·적용 시점과 변경·회귀 검증 기준 정의'
본문에 단계 08-01, CHG-02, 변경 내용·이유, 문서 검토 결과와 미확인 범위를 적어줘.

푸시·구현을 시작하지 말고 다음 실습 승인을 기다려줘.
```
