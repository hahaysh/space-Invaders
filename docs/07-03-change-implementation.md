# 07-03. 수정 계획 승인과 구현

**7. 개선 사이클 · 일시정지 구현**

이전: [07-02 영향 분석과 문서 수정](07-02-impact-and-document-update.md) · [전체 목차](00-overview.md) · 다음: [07-04 변경·회귀 검증](07-04-change-and-regression-testing.md)

## 1. 설명

승인한 문서를 실제 코드로 옮깁니다. 목표는 P 키 이벤트 한 줄이 아니라
**정지 전후의 게임 상태·시간·입력이 수용 기준대로 이어지는 것**입니다.
작은 단위로 구현·검증하고 다음 단위는 참가자가 따로 승인합니다.
이미 동작하는 게임을 전면 재작성하거나 새 프레임워크를 추가하지 않습니다.

## 2. 시작 상태

- [ ] CHG-01 요청과 영향 문서가 승인·로컬 커밋되었다.
- [ ] `IMPLEMENTATION_PLAN.md`에 변경 파일과 의존성이 있다.
- [ ] 최초 버전의 REQ-01~08 테스트를 실행할 수 있다.
- [ ] 개선 브랜치와 미커밋 작업을 확인하고 **Plan** 모드를 선택했다.

## 3. 실행: 작은 작업 계획 확인

```text
AGENTS.md와 CHG-01 관련 요구사항·설계·구현 계획·테스트 계획을 읽어줘.
현재 코드를 읽고 아래 두 작업 단위로 실행 계획을 구체화해줘.
A. 상태·시뮬레이션: paused 전환, 업데이트와 쿨다운 정지, 규칙 테스트.
B. 브라우저 입력·표시: P 반복 무시, held keys 정리, blur,
   RAF 시간 기준 초기화, 단일 루프 유지, 일시정지 안내와 e2e.
실제 파일 경로, 기준 ID, 기존 코드 재사용 지점, 검증 명령을 제시해줘.
게임을 전면 재작성하거나 의존성을 추가하지 마.
계획만 제시하고 파일 수정·설치·실행·커밋은 승인까지 기다려줘.
```

수정 파일이 예상보다 많으면 원인을 확인합니다.
상태 모델과 UI를 함께 바꿔야 하는 구조라면 최소 검증 가능한 경계로 조정합니다.
작업 단위 이름보다 승인 범위와 중단 지점이 명확한지가 중요합니다.

### A. 상태와 시간 처리

**Interactive**로 전환하고 첫 단위만 승인합니다.

```text
검토한 작업 A만 승인한다. 승인된 파일과 관련 Node 테스트를 수정해줘.
playing/paused만 P 전환 대상이며 title/won/lost는 무시하도록 모델링해줘.
paused 업데이트는 위치·탄환·적·점수·발사 쿨다운을 바꾸지 않아야 한다.
기존 REQ-01~08의 동작과 상수는 바꾸지 마.
npm test를 실행하고 실제 결과와 변경 diff를 보여줘.
브라우저 연결 등 작업 B나 커밋·푸시는 시작하지 말고 기다려줘.
```

정지 상태에 큰 시간 간격을 전달해도 상태가 보존되는 테스트를 봅니다.
객체 참조만 같다고 통과시키지 말고 위치·점수·쿨다운 값도 확인합니다.
게임의 난수·시간은 테스트에서 제어해 간헐적인 성공을 피합니다.

### B. 입력·렌더링·재개 연결

A의 diff와 결과를 확인한 뒤 다음 승인을 입력합니다.

```text
작업 A의 결과를 승인하고 검토한 작업 B 구현을 허용한다.
최초 P keydown만 처리하고 event.repeat은 무시해줘.
blur와 모든 상태 전환에서 held keys를 비우고 정지 중 게임 조작을 무시해줘.
재개 시 RAF 기준 시간을 초기화해 긴 정지 시간의 dt가 들어가지 않게 해줘.
RAF 루프는 하나만 유지하고 재개 때 중복 예약하지 마.
일시정지 표시와 P 재개 안내를 추가하되 새 조작 버튼은 추가하지 마.
기존 시작·종료·재시작 동작을 유지하고 관련 Playwright 테스트를 보완해줘.
npm test, npm run test:e2e, npm run build를 실행해줘.
브라우저가 없을 때만 Chromium 설치를 허용한다.
diff와 실제 결과를 제시하고 커밋·푸시·전체 검증 단계 진입은 기다려줘.
```

정지 중 P 외의 이동·발사 입력을 held keys에 쌓지 않아야 합니다.
특히 Space를 누른 채 정지·재개했을 때 자동 발사가 남지 않는지 봅니다.
시간 상한만으로 문제를 숨기지 말고 재개 프레임 기준을 실제로 초기화합니다.

### 예상 결과

| 산출물 | 확인할 내용 |
|---|---|
| 게임 코드 | `paused` 전환과 업데이트 차단, 기존 기능 유지 |
| 입력·화면 | 반복 P 무시, 키 상태 해제, 정지 표시 |
| 시간 처리 | 재개 점프 없음, RAF 루프 중복 없음 |
| 테스트 코드 | 상태·쿨다운·입력 경계에 대한 자동 검증 |
| 실행 결과 | 실제 명령별 성공/실패, 아직 공개 재배포는 없음 |

## 4. 함께 점검·확인

app의 변경 내역을 보면서 요구사항과 무관한 수정이 없는지 확인합니다.
로컬 브라우저를 사용할 때에는 app에 `npm run dev` 실행을 요청하고
실제로 반환된 주소를 엽니다. 포트 번호나 실행 성공을 추측하지 않습니다.

- [ ] 시작 후 P를 누르면 안내가 보이고 모든 게임 움직임이 정지한다.
- [ ] P를 길게 누르고 있어도 정지·재개를 빠르게 반복하지 않는다.
- [ ] 정지 중 이동·발사 입력이 재개 후 남지 않는다.
- [ ] 오래 정지한 뒤 재개해도 위치와 발사 시간이 뛰지 않는다.
- [ ] 제목·승리·패배 화면에서는 P가 아무 동작도 하지 않는다.
- [ ] 재시작 시 점수·적·탄환·키 상태가 초기화된다.
- [ ] 반복 정지·재개 후 속도가 빨라지지 않는다.

```text
CHG-01 기준별 구현 위치와 추가 테스트를 연결해 설명해줘.
단일 RAF 루프 보장과 재개 시간 초기화는 실제 코드 근거를 보여줘.
TEST_RESULTS.md에는 이번에 실행한 명령과 관찰한 결과만 기록해줘.
IMPLEMENTATION_PLAN.md의 완료 상태도 실제 작업에 맞게 갱신해줘.
전체 회귀 검증이나 공개 배포 완료로 표현하지 말고 기다려줘.
```

## 5. 보완과 재확인

```text
정지·재개에서 발견한 문제를 재현 조건과 함께 분석해줘.
키 상태 잔류, 벽시계 기반 쿨다운, 큰 dt, 중복 RAF 중 원인을 구분해줘.
최소 수정안과 실패를 재현하는 테스트를 먼저 제시하고 승인을 기다려줘.
기존 요구사항을 약화하거나 테스트 기대값을 오류에 맞추지 마.
```

수정안을 승인한 뒤 관련 테스트와 빌드를 다시 실행합니다.
로컬 서버 종료가 필요하면 해당 세션이 시작한 프로세스만 종료하도록 요청합니다.

## 6. 완료 승인

```text
CHG-01 구현 diff와 이번 단계 검증 결과를 승인한다.
승인 파일만 구체적인 한국어 제목과 본문으로 로컬 커밋해줘.
제목 예시: '07-03: 게임 시간과 입력 상태를 안전하게 보존하는 P 일시정지·재개 구현'
본문에 단계 ID 07-03과 CHG-01 기준 ID, 변경 내용·이유, 실제 테스트·빌드 결과를 적어줘.
전체 회귀 검증과 공개 재배포 등 아직 남은 미확인 범위도 명시해줘.
푸시·PR·병합·배포는 하지 말고 전체 회귀 검증 실습을 기다려줘.
```
