# 09-02. 목숨 구현과 재배포

[이전](09-01-목숨-설계.md) · [전체 목차](00-전체-실습-안내.md)

## 이번 실습

목숨과 재도전 흐름을 구현하고 달라진 규칙과 유지할 규칙을 함께 확인합니다.
제어 가능한 모델 시간으로 빠르게 검사할 조건과 실제 브라우저 입력으로 볼 조건을 나눕니다.
공개 확인과 원격 기록까지 마치면 선택 과정을 포함한 20개 실습이 끝납니다.

## 시작 전

- 같은 목숨 이슈 세션에 승인된 문서가 있습니다.
- 최신 난이도·P·기본 게임을 포함한 기능 브랜치입니다.
- App **Plan**에서 구현·기대값 전환·회귀 순서를 확인합니다.

```text
승인된 목숨 설계와 현재 코드를 기준으로 최소 구현 계획을 확인해 줘.
retry 상태·초기화·보존·입력 잠금과 바뀔 패배 검사 기대값을 보여 줘.
기존 경계 검증을 유지한 채 새 규칙을 검사하는 순서로 제안하고 멈춰 줘.
```

## 승인 후 구현과 Skill 검증

App을 **Interactive**로 전환합니다.

```text
승인 문서대로 목숨 3·한 번 차감·retry/최종 lost·다음 시도를 구현해 줘.
실패 시도 화면/점수 동결과 다음 시도의 초기화·보존을 정확히 반영해 줘.
retry의 반복 Enter·R/P/이동/발사 무시와 난이도 잠금, 승리의 목숨 보존을 지켜 줘.
README 조작과 표시 설명을 갱신하고 적 탄환은 추가하지 마.
game-check Skill로 목숨·충돌 우선순위와 기본 게임/P/난이도 전체 회귀·빌드를 검증해 줘.
기존 즉시 패배 기대는 새 수용 기준으로 바꾸되 경계 검사를 삭제해 숨기지 마.
모델 시간 검사와 실제 Enter/버튼/선택 입력 검사를 구분해 줘.
실제 결과와 Skill 호출 상태를 기록하고 PR 제출 전 diff를 보여 줘.
```

모델 검사에서는 여러 적이 동시에 방어선에 닿아도 하나만 차감하는지 확인합니다.
retry에 머무는 여러 갱신, 다음 시도, 세 번째 실패, 마지막 적 제거의 우선순위도 확인합니다.
브라우저에서는 재도전 안내와 Enter·버튼·잠긴 조작을 실제 입력으로 확인합니다.
필요한 경계에 빨리 도달하려고 제품에 전역 테스트 API나 치트 키를 심지 않습니다.
실제 브라우저로 확인하지 못한 경계는 모델 검사 근거와 함께 미확인 범위를 적습니다.

## PR·재배포

로컬 결과와 문서의 정합성을 확인한 뒤 제출을 승인합니다.

```text
검토한 변경을 커밋·푸시하고 main 대상 목숨 PR을 만들어 줘.
코드 수용을 완료한 이슈를 Fixes로 연결하고 바뀐 패배 기대와 실제 검사 결과를 적어 줘.
PR 검사 결과를 알려 주고 사람이 병합을 승인할 때까지 멈춰 줘.
```

App PR 화면 또는 GitHub 웹에서 사람이 검사·diff를 확인해 병합을 승인합니다.
main 배포와 필요한 환경 승인 이후 실제 공개 게임을 확인합니다.

```text
병합 커밋·Actions·실제 공개 URL의 응답과 게임을 확인해 줘.
목숨 표시·재도전·기본 조작을 실제 브라우저로 확인하고 자동 검사 근거와 구분해 줘.
공개 증거를 목숨 이슈 댓글에 남기고 실패나 미확인은 숨기지 마.
원격에 반영된 코드/문서와 남은 로컬 변경을 구분해 마무리 상태를 알려 줘.
```

## 눈으로 확인

- [ ] 한 번 차감·retry 유지·0이면 lost와 다음 시도 초기화를 검사했습니다.
- [ ] retry의 키 반복/잠금과 난이도 유지, 승리 시 목숨 보존이 맞습니다.
- [ ] 마지막 적 충돌 우선과 기존 경계 검사·P·난이도 회귀가 유지됩니다.
- [ ] PR/환경 승인 후 실제 공개 게임을 확인하고 원격 증거를 남겼습니다.
- [ ] README·결과 요약의 반영 상태와 남은 로컬 변경이 명확합니다.

## 실패했을 때만 복구

```text
실패한 목숨/재도전 동작의 재현 근거를 남기고 최소 수정해 줘.
기대값 변경이 승인한 규칙 때문인지 확인하고 관련 전체 회귀·공개 확인을 다시 수행해 줘.
병합 이후라면 최신 main 기반 새 수정 PR을 사용해 줘.
```

## 완료와 돌아보기

전체 20개 실습을 마쳤습니다. 문서·이슈·검사·PR·공개 URL이 서로 연결됐는지 돌아봅니다.
마지막 공개 결과는 이슈 댓글에 보존하고 사소한 기록 변경마다 재배포 PR을 만들지 않습니다.
[06-03에서 기록 PR은 한 번 완료](06-03-PR과-첫-배포.md)했으므로 최종 공개 증거도 이슈 댓글로 마무리합니다.
세션이 시작한 서버만 정상 종료하고 필요한 변경을 원격에 보존한 뒤 작업 공간을 정리합니다.
실행하지 않은 사람 UI나 자동 지침 로딩을 과정 완료 근거로 추가하지 않습니다.
