# 08-02. 난이도 구현과 재배포

[이전](08-01-난이도-선택-설계.md) · [전체 목차](00-전체-실습-안내.md) · [다음: 목숨 설계](09-01-목숨-설계.md)

## 이번 실습

설정 UI와 실제 적 속도를 연결하고 선택 잠금을 확인합니다.
기존 Skill로 새 기능과 일시정지·기본 게임을 함께 검증합니다.
성공한 로컬 결과와 실제 공개 결과를 서로 다른 근거로 남깁니다.

## 시작 전

- 같은 난이도 이슈 세션에 승인한 변경 문서가 있습니다.
- 현재 브랜치는 `feature-difficulty`와 같은 새 기능 브랜치입니다.
- App **Plan**에서 구현과 검사 범위를 확인합니다.

```text
승인한 난이도 문서와 현재 구조를 확인해 최소 구현 순서를 제안해 줘.
pending/current·select 입력·상태 잠금·오류 처리에 필요한 변경만 골라 줘.
새 검사와 기존 게임/P 회귀 범위를 보여 주고 아직 수정하지 마.
```

## 승인 후 구현

App을 **Interactive**로 바꿉니다.

```text
난이도 구현을 승인해. 승인 문서대로 설정·UI·게임 시작 연결을 구현해 줘.
README에 선택 방법과 현재 판에는 시작/재시작 때 적용됨을 설명해 줘.
game-check Skill을 사용해 세 속도와 pending/current, 상태 잠금, invalid 오류를 확인해 줘.
Playwright 실제 키 입력으로 select의 화살표/Space/Enter가 빼앗기지 않는지 검사해 줘.
새로고침 보통, 시작/재시작 적용, 기존 P와 전체 게임 회귀·빌드를 실행해 줘.
Skill 호출 여부와 자동/수동 결과를 구분하고 실제 결과만 문서·계획 표에 반영해 줘.
diff와 남은 문제를 보여 준 뒤 PR 생성 전에 멈춰 줘.
```

쉬움·어려움 선택이 화면 글자만 바꾸는지, 실제 속도가 달라지는지 확인합니다.
정확한 속도는 제어 가능한 모델 시간으로 검사합니다.
선택 UI와 키보드 연결은 실제 브라우저에서 확인합니다.
`paused`에서도 설정을 바꿀 수 없어야 현재 판의 규칙이 유지됩니다.

## PR과 공개 확인

결과를 검토한 뒤 원격 제출을 승인합니다.

```text
검토한 난이도 변경을 커밋·푸시하고 main 대상 PR을 만들어 줘.
수용 완료한 코드 이슈를 Fixes로 연결하고 실제 검사·미확인을 적어 줘.
PR 검사 결과를 알려 주고 사람이 병합을 승인할 때까지 멈춰 줘.
```

App PR 화면이나 GitHub 웹에서 사람이 검사·diff를 확인하고 병합을 승인합니다.
main 배포와 환경 승인을 거친 후 실제 공개 주소에서 새 기능을 확인합니다.

```text
병합 커밋·Actions·공개 URL을 확인하고 공개 게임의 난이도 선택과 P를 조작해 줘.
실제 응답·자산 로딩·선택/잠금/시작 동작 결과를 난이도 이슈 댓글에 남겨 줘.
모델 검사와 공개 조작, 사람 UI와 API 확인을 구분하고 남은 로컬 기록도 알려 줘.
```

공개 후 결과는 원격 이슈에 바로 보존합니다.
기능 PR에 담은 검증 문서와 README를 사소한 관찰마다 다시 PR로 수정하지 않습니다.
[06-03의 기록 정책](06-03-PR과-첫-배포.md)대로 공개 후 결과만을 위한 새 기록 PR은 만들지 않습니다.

## 눈으로 확인

- [ ] 세 속도의 실제 동작과 선택/현재 값 분리를 검사했습니다.
- [ ] title/won/lost 선택, playing/paused 잠금, 새로고침 보통이 맞습니다.
- [ ] select의 native 키보드 동작과 명시적 invalid 오류를 확인했습니다.
- [ ] 기존 게임·P 회귀와 PR 검사가 통과했습니다.
- [ ] 승인된 main 재배포 후 실제 공개 증거가 원격 이슈에 있습니다.

## 실패했을 때만 복구

```text
실패한 선택/속도/입력 동작을 재현하고 관련 부분만 수정해 줘.
기존 검사 기대값을 숨기지 말고 Skill 회귀와 공개 확인을 다시 수행해 줘.
병합 이후 수정은 최신 main의 새 수정 PR로 진행해 줘.
```

## 완료

난이도 선택 사이클을 마쳤습니다.
목숨을 추가하려면 이 변경이 병합된 최신 main에서 다음 이슈를 시작합니다.
