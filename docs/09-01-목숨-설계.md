# 09-01. 목숨 설계

[이전](08-02-난이도-구현과-재배포.md) · [전체 목차](00-전체-실습-안내.md) · [다음: 목숨 구현과 재배포](09-02-목숨-구현과-재배포.md)

## 이번 실습

방어선 도달 시 즉시 패배하던 규칙을 목숨·재도전 규칙으로 바꿉니다.
기존 패배 검사의 기대가 실제로 달라지는 변경이므로 문서와 테스트를 함께 수정합니다.
적 탄환이나 피격 시스템을 새로 만드는 실습은 아닙니다.

## 시작 전

- 난이도 기능이 최신 main에 병합되고 공개 확인을 마쳤습니다.
- 기존 게임·일시정지·난이도 검사와 Skill이 있습니다.
- App **Interactive**에서 새 이슈를 만듭니다.

```text
최신 main의 난이도 완료를 확인하고 '우주 방어 목숨과 재도전' 이슈를 만들어 줘.
목표·범위·완료 점검·관련 문서 링크를 짧게 구성해 줘.
새 게임 목숨 3, 방어선 도달 차감, 재도전, 회귀 검증·재배포를 포함해 줘.
적 탄환은 제외하고 아직 코드를 수정하지 마.
```

**My work → 목숨 이슈 → New session**에서 최신 main을 base로 선택합니다.
예시 브랜치는 `feature-lives`입니다. 현재 브랜치와 난이도·P·Skill 존재를 확인합니다.
App **Plan**에서 새 규칙을 검토합니다.

## 변경 기준

| 상황 | 결과 |
|---|---|
| 새 게임 / 최종 종료 뒤 재시작 | 목숨 3, 선택 난이도 적용, 점수 0으로 새 판 |
| 방어선 도달 | 같은 갱신에서 여러 적이 닿아도 정확히 목숨 1 차감 |
| 목숨이 남음 | retry 상태, 실패한 시도의 화면·점수 동결 |
| 목숨 0 | lost, 실패한 시도의 점수 유지 |
| retry에서 Enter(반복 제외) / 다음 시도 버튼 | 남은 목숨·현재 난이도 유지, 점수 0부터 새 시도 |
| retry 입력 | R/P/이동/발사 무시, 난이도 선택 잠금 |
| 모든 적 제거 | 남은 목숨 그대로 won, 충돌 우선으로 마지막 적 제거는 승리 |

```text
목숨 이슈와 현재 PRD/TRD/TEST_PLAN을 읽고 위 규칙의 변경안을 제안해 줘.
retry에서는 실패 시도의 화면·점수·시간을 멈추고 안내만 보여 줘.
다음 시도는 목숨·현재 난이도만 보존하고 점수/적/플레이어/탄환/cooldown/시계/입력을 초기화해.
새 게임과 다음 시도를 구분하고 repeat Enter·R/P/이동/발사는 retry에서 무시해.
난이도는 retry에서도 잠그고 승리 시 남은 목숨을 보존해 줘.
충돌을 방어선보다 먼저 처리해 마지막 적 제거와 도달이 겹치면 승리하게 해 줘.
기존 '방어선 도달 즉시 lost' 기대를 목숨 규칙으로 명시적으로 바꿔 줘.
기존 경계 검사를 삭제하지 말고 새 기대와 남은 회귀 범위를 설명해 줘.
문서 변경만 제안하고 적 탄환·코드 구현은 추가하지 마.
```

점수는 시도마다 0에서 시작하고 실패 직후에는 그 시도의 점수를 보여 줍니다.
목숨을 잃을 때마다 즉시 새 판을 열지 않고 사용자가 다음 시도를 선택하게 합니다.
한 번의 방어선 도달을 여러 프레임에서 중복 차감하지 않도록 상태 전환을 설계합니다.

## 승인 후 문서 작성

App을 **Interactive**로 전환합니다.

```text
목숨 설계를 승인해. PRD·TRD·TEST_PLAN과 계획 표를 필요한 만큼만 갱신해 줘.
이전 즉시 패배 조건이 무엇으로 바뀌는지 명시하고 이슈에 승인 범위를 남겨 줘.
아직 코드는 바꾸지 말고 문서 diff를 보여 줘.
```

## 눈으로 확인

- [ ] 최신 main 기반 새 목숨 이슈·기능 세션입니다.
- [ ] 차감은 한 번, 남으면 retry, 0이면 lost가 명확합니다.
- [ ] 화면/점수 동결과 다음 시도 초기화·보존 항목이 구분됐습니다.
- [ ] retry 입력 잠금·난이도 잠금과 승리 시 목숨 보존이 명확합니다.
- [ ] 기존 패배 경계를 삭제하지 않고 새 기대값으로 전환할 계획입니다.

## 필요할 때만 보완

```text
새 게임·실패 직후·다음 시도의 점수/목숨/난이도가 섞인 부분만 보완해 줘.
각 상태의 입력과 충돌 우선순위를 명확히 하고 새 기능은 추가하지 마.
```
