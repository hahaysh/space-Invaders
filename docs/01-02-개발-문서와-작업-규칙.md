# 01-02. 개발 문서와 작업 규칙

[이전](01-01-실습-환경-준비.md) · [전체 목차](00-전체-실습-안내.md) · [다음: 게임 아이디어](02-01-게임-아이디어.md)

## 이번 실습

문서를 쓰기 전에 각 문서가 답할 질문을 먼저 정합니다.
그 합의를 바탕으로 최소 `AGENTS.md`만 실제 생성합니다.
모든 내용을 한 지침 파일에 넣지 않고 제품 기준과 작업 규칙을 나누는 경험입니다.
참가자 저장소의 설명 문서는 한국어로 작성하는 것을 기본으로 하며, `AGENTS.md`도
한국어로 작성해도 됩니다. 코드 식별자·명령어·파일명·frontmatter의 고정 키워드는
변경하지 않고 원문 표기를 유지합니다.

## 시작 전

- 문서 작업 세션과 main 기준을 확인했습니다.
- 게임 코드가 없는 상태이며 기존 사용자 작업은 보존합니다.
- App **Plan**에서 시작합니다.

**모드: Plan**

```text
'우주 방어'의 개발 문서 역할을 위 구분으로 먼저 제안해 줘.
각 문서의 목적·짧은 목차·완료 기준·참조 관계를 표로 보여 줘.
제품 수치는 PRD, 기술 선택은 TRD에 두고 같은 규칙을 중복하지 말아 줘.
AGENTS에는 사용자 작업·비밀 보호, 기존 문서 준수, 작은 변경,
실제 실행에 근거한 검증 보고와 계획/실행/공개 경계만 제안해 줘.
참가자 저장소의 문서와 AGENTS.md는 한국어로 작성하되,
코드 식별자·명령어·파일명·frontmatter 고정 키워드는 원문 그대로 유지해 줘.
아직 파일은 만들지 말고 내가 역할을 검토할 수 있게 멈춰 줘.
```

문서의 이름보다 책임을 확인합니다.
예를 들어 점수 규칙은 PRD, 그 규칙을 확인하는 방법은 테스트 계획에 연결합니다.
규칙을 고칠 때 여러 복사본을 동시에 고쳐야 한다면 역할을 다시 나눕니다.

## 합의 후 AGENTS 생성

App을 **Interactive**로 바꾸고 아래 범위만 승인합니다.

**모드: Interactive**

```text
문서 역할을 승인해. 지금은 짧은 AGENTS.md만 작성해 줘.
기존 사용자 변경·비밀을 보호하고 관련 문서를 먼저 확인하도록 해 줘.
작은 변경, 실제 검증 결과와 미확인 구분, 원격 공개 전 검토를 포함해 줘.
AGENTS.md 본문은 한국어로 작성해 줘. 코드 식별자·명령어·파일명·frontmatter 고정 키워드는
영어 원문을 유지하고, 규칙의 의미가 바뀌지 않게 해 줘.
아직 없는 문서는 앞으로 작성할 참조로 구분해 줘.
AGENTS만 영구적으로 수정 가능하다는 제한이나 중복 제품 규칙은 넣지 마.
다른 문서·게임 코드·.github 설정은 만들지 말고 diff를 보여 줘.
```

이 단계의 “AGENTS만”은 **이번 작업 범위**이지 영구 규칙이 아닙니다.
뒤 단계에서는 승인한 문서와 코드도 수정할 수 있어야 합니다.
파일을 명시적으로 읽게 할 수 있지만, 그것은 자동 지침 로딩을 입증하지 않습니다.
App에서 지침 인식 상태를 확인할 수 없다면 “자동 로딩 미확인”으로 남깁니다.

## 눈으로 확인

- [ ] 파일 생성 전에 문서의 역할과 참조 관계를 검토했습니다.
- [ ] `AGENTS.md`가 실제 존재하고 짧은 작업 규칙만 담고 있습니다.
- [ ] `AGENTS.md`와 참가자 문서가 한국어이며, 코드 식별자·명령어·파일명·고정 키워드는 원문입니다.
- [ ] 사용자 작업·비밀 보호와 정직한 검증 보고가 포함됐습니다.
- [ ] 향후 구현을 막는 AGENTS 전용 영구 제한이 없습니다.
- [ ] 파일 읽기와 자동 적용을 같은 성공으로 표현하지 않았습니다.

## 필요할 때만 보완

**모드: Interactive**

```text
AGENTS에서 제품 세부 수치와 중복 설명을 빼고 해당 문서를 참조하게 해 줘.
이번 단계 제한이 향후 구현까지 막지 않게 고치고 바뀐 부분만 보여 줘.
```

모두 맞으면 추가 보완이나 별도 승인 문서를 만들지 않습니다.
