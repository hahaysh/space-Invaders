# 06-03. PR과 첫 배포

[이전](06-02-배포-워크플로.md) · [전체 목차](00-전체-실습-안내.md) · [다음: 일시정지 요청과 설계](07-01-일시정지-요청과-설계.md)

## 이번 실습

검증·배포 변경을 PR로 검토하고 main 병합 후 실제 공개 게임을 확인합니다.
초록색 Actions만으로 배포 성공을 선언하지 않습니다.
이번에는 원격 이슈 댓글을 즉시 기록 장소로 사용해 기록용 PR의 반복을 피합니다.

## 시작 전

- 검증·배포 이슈는 열려 있고 같은 기능 브랜치에 변경이 있습니다.
- 로컬 필수 검사와 Pages 설정·워크플로 검토를 마쳤습니다.
- 공개 승인 권한을 가진 사람이 PR과 배포 환경을 확인할 수 있습니다.

## App Plan: 공개 전 마지막 검토

```text
검증·배포 이슈와 현재 diff·실제 결과를 확인해 줘.
PR base main, 추적 파일, workflow 배포 조건, 남은 미확인을 검토해 줘.
공개 전 차단 문제가 없다면 커밋/푸시/PR과 공개 확인 순서를 짧게 제안해 줘.
배포 이슈는 공개 확인 전 자동으로 닫지 않도록 Related to로 연결해 줘.
아직 원격 작업이나 병합은 하지 마.
```

문제가 없으면 App **Interactive**로 전환해 원격 제출을 승인합니다.

```text
검토한 변경을 커밋·푸시하고 main 대상 PR을 만들어 줘.
실제 검사·미확인·설정 확인 방법과 배포 이슈 링크를 적어 줘.
배포 이슈에 Fixes/Closes를 쓰지 말고 PR 검사 결과를 확인해 알려 줘.
병합은 내가 diff와 결과를 확인한 뒤 승인할 때까지 기다려 줘.
```

## 사람의 PR·배포 승인

App PR 화면 또는 GitHub 웹에서 파일·base·검사 결과를 확인합니다.
PR 실행에 deploy가 없고 검사·빌드만 수행됐는지 확인합니다.
문제가 없으면 사람이 PR 병합을 승인합니다.
main 실행의 build·upload·deploy와 배포 대상 커밋을 확인합니다.
환경 reviewer 승인이 필요하면 해당 사람이 승인할 때까지 기다립니다.
보호 규칙을 지우거나 직접 main을 덮어써서 대기 상태를 우회하지 않습니다.

## 실제 공개 확인

```text
병합된 main 커밋과 Actions run, Pages의 실제 배포 URL을 확인해 줘.
공개 URL을 직접 요청해 응답과 저장소 하위 경로 자산 로딩을 확인해 줘.
그 URL에서 제목·시작·이동·발사·적·점수·재시작을 실제 브라우저로 확인해 줘.
승패 경계의 자동 검사 근거와 공개 화면 확인을 구분하고 오류도 보고해 줘.
결과를 배포 이슈 댓글에 커밋·run 링크·URL·확인 방식·미확인과 함께 남겨 줘.
실제 공개 확인이 끝난 경우에만 이슈 종료를 제안해 줘.
```

사람도 공개 주소를 열어 `우주 방어`와 주요 조작을 확인합니다.
자동 브라우저 실행과 사람이 확인한 항목을 구분합니다.
정적 HTTP 응답만 확인했다면 게임 조작까지 성공했다고 쓰지 않습니다.
승패 전체를 직접 플레이하지 않았다면 해당 근거는 기존 자동 검사로 표시합니다.

## README와 결과 기록

이번 첫 배포 사이클의 끝에서 **한 번의 기록 PR**으로 README와 결과를 정리합니다.
배포 세션의 변경이 모두 보존됐는지 확인하고 App에서 최신 main 기반 기록용 세션/브랜치를 엽니다.
선택 base와 실제 파일을 확인한 뒤 **Interactive**에서 다음을 요청합니다.

```text
원격 배포 이슈의 실제 공개 증거를 읽고 README에 확인된 실제 URL을 추가해 줘.
TEST_RESULTS에는 날짜·커밋·확인 방식의 짧은 요약과 이슈 링크만 반영해 줘.
게임 코드는 바꾸지 말고 diff를 보여 줘. 승인 후 커밋·푸시하고 기록 PR 하나를 만들어 줘.
```

사람이 기록 diff와 검사를 확인해 병합합니다. 아직 로컬에만 있던 문서가 원격 main에 들어갔는지 확인합니다.
그 PR이 재배포를 일으키면 **동일한 게임 코드**의 공개 응답·자산·기본 시작 동작을 재확인합니다.
이 결과는 원격 이슈 댓글에만 남기며 또 기록 PR을 만들지 않습니다.
07~09에서는 기능 설명·직전 공개 근거를 기능 PR에 함께 반영하고, 병합 뒤 공개 근거는 이슈 댓글에 보존합니다.
각 관찰마다 TEST_RESULTS를 다시 수정하거나 마지막에 또 기록 PR을 만드는 순환은 하지 않습니다.
종료 시 원격에 반영한 파일과 아직 로컬에만 있는 변경을 명시합니다.

## 눈으로 확인

- [ ] PR 검사 통과를 확인한 사람이 main 병합을 승인했습니다.
- [ ] main의 배포가 완료됐고 환경 보호를 우회하지 않았습니다.
- [ ] 실제 공개 URL의 응답·자산·게임 조작을 확인했습니다.
- [ ] 커밋·Actions·공개 확인 증거가 원격 이슈 댓글에 보존됐습니다.
- [ ] 실제 URL을 담은 README와 결과 요약이 기록 PR로 main에 반영됐습니다.

## 실패했을 때만 복구

```text
실패한 PR 검사/배포/공개 동작 중 어느 단계인지 실제 로그로 구분해 줘.
최소 수정안을 제시하고 승인 후 관련 검사부터 공개 URL까지 다시 확인해 줘.
배포 이슈는 열린 채로 두고 설정 보호를 완화하지 마.
```

원격 캐시·빌드·경로 문제를 추측으로 확정하지 않습니다.
병합 후 수정이 필요하면 최신 main 기반 새 수정 브랜치와 PR로 처리합니다.

## 완료

공개 확인과 원격 증거가 확보되면 검증·첫 배포 이슈를 닫습니다.
07은 이 병합된 최신 main에서 새 일시정지 이슈·세션으로 시작합니다.
