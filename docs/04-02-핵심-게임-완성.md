# 04-02. 핵심 게임 완성

[이전](04-01-첫-게임-구현.md) · [전체 목차](00-전체-실습-안내.md) · [다음: App 설정과 README](04-03-App-설정과-README.md)

## 이번 실습

M1 PR이 main에 병합된 뒤 **기본 게임 M2 이슈와 독립 세션**에서
적·적 탄환·충돌·점수·피격·목숨·승패·재시작을 연결합니다.
새 코드를 추가하면서 M1의 이동·발사가 그대로 동작하는지 함께 확인합니다.
최초 게임의 완성 기준은 예쁜 화면보다 PRD의 모든 필수 동작입니다.

## 시작 전

- M1 PR이 병합된 최신 main에서 시작한 M2 기능 브랜치와 `IMPLEMENTATION_PLAN.md`가 있습니다.
- M1의 실제 실행 결과를 확인했습니다.
- App **Plan**에서 M2 범위를 확인합니다.

## 변경 계획

**모드: Plan**

```text
기본 게임 M2 이슈와 계획 표, PRD·TRD, 현재 main의 M1 코드를 확인해 줘.
M1 PR의 실제 병합과 현재 base·브랜치에 M1 코드가 포함됐는지 확인하고 아니면 상태를 알려 주고 멈춰 줘.
M2에서 적 이동·하강·적 탄환·충돌·점수·피격·목숨·승패·재시작을 추가할 계획을 제안해 줘.
PRD의 기본값과 충돌 우선순위를 참조하고 새 수치를 임의로 만들지 마.
모델 규칙과 실제 브라우저 입력의 검사 범위를 나눠 줘.
M1 회귀 검사와 종료 후 정지·재시작 초기화를 포함해 줘.
일시정지·난이도는 추가하지 말고 계획에서 멈춰 줘. 목숨은 3개 기본값으로 구현해.
```

승패를 “화면에 글자만 보임”으로 확인하지 않습니다.
종료 후 적·탄환·점수가 변하지 않고 재시작이 새 판을 만드는지도 확인합니다.
모델/UI 분리는 도움이 되지만 정해진 파일명이나 함수명을 강제하지 않습니다.

## 승인 후 구현

App을 **Interactive**로 전환합니다.

**모드: Interactive**

```text
M2 계획을 승인해. 현재 구조를 활용해 핵심 게임을 완성해 줘.
IMPLEMENTATION_PLAN.md의 M1 기록을 보존하고 승인한 M2 계획을 추가한 뒤 구현해 줘.
탄환 하나가 여러 적을 중복 제거하거나 점수를 중복 올리지 않게 해 줘.
각 열의 가장 아래 적이 일정 간격으로 적 탄환을 발사하게 해 줘.
적 탄환이 플레이어에 맞으면 목숨을 한 번 차감하고, 남은 목숨이 있으면 현재 판을
초기화해 자동으로 다음 시도를 시작해 줘. 0개면 lost로 전환해 줘. 탄환 하나의
중복 피격과 한 번의 방어선 중복 차감을 막아 줘.
적이 남아 있는 상태에서 방어선 도달과 적 탄환 피격이 동시에 발생하면 방어선 도달을
우선해 즉시 lost로 종료하고 목숨 차감이나 자동 다음 시도를 하지 않게 해 줘.
마지막 적 충돌을 방어선 판정보다 먼저 처리하고 종료 상태를 유지해 줘.
재시작은 PRD대로 전체 상태·시간·입력을 초기화하게 해 줘.
관련 Node·Playwright 검사와 빌드를 실제 실행해 줘.
모델 시간 조작과 실제 키 입력의 확인 결과를 구분해 줘.
계획 표에 완료 근거와 남은 작업을 기록하고 diff를 보여 준 뒤 멈춰 줘.
```

테스트 도구가 없다는 실행 오류가 나면 manifest와 설치 상태부터 확인합니다.
필요한 Playwright Chromium 설치는 승인해 실행할 수 있습니다.
브라우저에 비공개 모델 조작 API나 테스트 전용 치트 키를 추가하지 않습니다.
검사에서 실제 결함을 발견하면 재현 → 최소 수정 → 관련 회귀 검사 순서로 처리합니다.

## 눈으로 확인

- [ ] 적 편대가 이동·하강하고 맞힌 적과 점수가 PRD대로 변합니다.
- [ ] 모든 적 제거는 승리, 방어선 도달은 패배이며 종료 후 멈춥니다.
- [ ] 마지막 적 제거와 방어선 판정의 우선순위를 실제 검사했습니다.
- [ ] 적 탄환 발사, 피격 1회 처리, 목숨 차감·자동 다음 시도·최종 패배를 실제 검사했습니다.
- [ ] 적 잔존 상태에서 방어선 도달과 피격 동시 발생 시 방어선 도달 우선 `lost`를 실제 검사했습니다.
- [ ] 재시작 후 이동·발사·점수·적 배치가 새 게임으로 돌아옵니다.
- [ ] M1 회귀·M2 검사·빌드를 실제 실행했고 누락은 미확인으로 남겼습니다.

## 필요할 때만 보완

**모드: Interactive**

```text
확인한 결함을 재현하는 검사를 보존하거나 추가하고 최소 수정해 줘.
관련 검사와 기존 시작·이동·발사·재시작을 다시 실행해 결과를 알려 줘.
실패 검사를 삭제하거나 기대값을 근거 없이 바꿔 통과시키지 마.
```

관찰하지 않은 전체 승리 플레이를 수동 통과로 기록하지 않습니다.
자동 모델 검사가 담당한 조건은 그 방식대로 기록하면 됩니다.

## M2 PR 생성

M2 범위의 diff와 실제 결과를 확인한 뒤 원격 작업을 승인합니다.

**모드: Interactive**

```text
M1 기록을 보존하고 M2 완료 근거와 M3 미구현 범위를 계획 표에 정리해 줘.
M2 이슈의 완료 조건을 충족했는지 확인하고, 미충족이면 남은 항목을 알려 주고 멈춰 줘.
충족했다면 검토한 파일만 한국어 커밋으로 남기고 현재 기능 브랜치에 푸시해 줘.
main 대상 M2 PR을 만들고 M1 회귀·M2 검사·빌드의 실제 결과와 미확인을 적어 줘.
M2 이슈만 Fixes로 연결하고 PR 링크를 알려 줘. 병합 전에는 멈춰 줘.
M3 구현이나 배포는 하지 마.
```

## 검토 후 M2 병합

사람이 PR의 base·diff·검사·비밀 유무를 검토하고 승인한 뒤에만 전달합니다.

**모드: Interactive**

```text
검토한 main 대상 M2 PR의 병합을 승인해. 해당 PR만 병합해 줘.
필수 검사·보호 규칙·권한 문제로 병합할 수 없으면 우회하지 말고 상태와 필요한 조치를 알려 줘.
실제 병합 여부와 원격 main의 M2 코드·계획 문서 반영, M2 이슈 종료 여부를 확인해 줘.
M3 이슈는 닫지 말고 이 세션에서 다음 구현을 시작하지 마.
```

## 완료

- [ ] M2 PR의 실제 병합과 원격 main 반영, M2 이슈 종료를 확인했습니다.

병합이 확인된 뒤 App **My work → M3 이슈 → New session**에서 최신 main을 선택합니다.
새 M3 기능 브랜치에서 04-03을 시작합니다. 아직 Pages에 배포하지 않습니다.
M2 서버가 남아 있으면 해당 세션에서 소유한 서버만 정상 종료합니다.
