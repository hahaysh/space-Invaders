# 04-02. 핵심 게임 완성

[이전](04-01-첫-게임-구현.md) · [전체 목차](00-전체-실습-안내.md) · [다음: App 설정과 README](04-03-App-설정과-README.md)

## 이번 실습

같은 기본 게임 이슈의 M2로 적·충돌·점수·승패·재시작을 연결합니다.
새 코드를 추가하면서 M1의 이동·발사가 그대로 동작하는지 함께 확인합니다.
최초 게임의 완성 기준은 예쁜 화면보다 PRD의 모든 필수 동작입니다.

## 시작 전

- 같은 기능 브랜치에 M1과 `IMPLEMENTATION_PLAN.md`가 있습니다.
- M1의 실제 실행 결과를 확인했습니다.
- App **Plan**에서 M2 범위를 확인합니다.

## 변경 계획

```text
기본 게임 이슈와 계획 표, PRD·TRD, 현재 M1 코드를 확인해 줘.
M2에서 적 이동·하강·충돌·점수·승패·재시작을 추가할 계획을 제안해 줘.
PRD의 기본값과 충돌 우선순위를 참조하고 새 수치를 임의로 만들지 마.
모델 규칙과 실제 브라우저 입력의 검사 범위를 나눠 줘.
M1 회귀 검사와 종료 후 정지·재시작 초기화를 포함해 줘.
일시정지·난이도·목숨·적 탄환은 추가하지 말고 계획에서 멈춰 줘.
```

승패를 “화면에 글자만 보임”으로 확인하지 않습니다.
종료 후 적·탄환·점수가 변하지 않고 재시작이 새 판을 만드는지도 확인합니다.
모델/UI 분리는 도움이 되지만 정해진 파일명이나 함수명을 강제하지 않습니다.

## 승인 후 구현

App을 **Interactive**로 전환합니다.

```text
M2 계획을 승인해. 현재 구조를 활용해 핵심 게임을 완성해 줘.
탄환 하나가 여러 적을 중복 제거하거나 점수를 중복 올리지 않게 해 줘.
마지막 적 충돌을 방어선 판정보다 먼저 처리하고 종료 상태를 유지해 줘.
재시작은 PRD대로 전체 상태·시간·입력을 초기화하게 해 줘.
관련 Node·Playwright 검사와 빌드를 실제 실행해 줘.
모델 시간 조작과 실제 키 입력의 확인 결과를 구분해 줘.
계획 표에 완료 근거와 남은 작업을 기록하고 diff를 보여 준 뒤 멈춰 줘.
```

테스트 도구가 없다는 실행 오류가 나면 manifest와 설치 상태부터 확인합니다.
필요한 Playwright Chromium 설치는 승인해 실행할 수 있습니다.
브라우저에 비공개 모델 조작 API나 테스트 전용 치트 키를 추가하지 않습니다.
검사에서 실제 결함을 발견하면 재현 → 최소 수정 → 관련 회귀 검사 순서로 처리합니다.

## 눈으로 확인

- [ ] 적 편대가 이동·하강하고 맞힌 적과 점수가 PRD대로 변합니다.
- [ ] 모든 적 제거는 승리, 방어선 도달은 패배이며 종료 후 멈춥니다.
- [ ] 마지막 적 제거와 방어선 판정의 우선순위를 실제 검사했습니다.
- [ ] 재시작 후 이동·발사·점수·적 배치가 새 게임으로 돌아옵니다.
- [ ] M1 회귀·M2 검사·빌드를 실제 실행했고 누락은 미확인으로 남겼습니다.

## 필요할 때만 보완

```text
확인한 결함을 재현하는 검사를 보존하거나 추가하고 최소 수정해 줘.
관련 검사와 기존 시작·이동·발사·재시작을 다시 실행해 결과를 알려 줘.
실패 검사를 삭제하거나 기대값을 근거 없이 바꿔 통과시키지 마.
```

관찰하지 않은 전체 승리 플레이를 수동 통과로 기록하지 않습니다.
자동 모델 검사가 담당한 조건은 그 방식대로 기록하면 됩니다.

## 완료

검토한 M2를 한국어 커밋으로 남깁니다.
같은 세션에서 M3의 사용 설명과 App 수동 실행 설정을 추가합니다.
아직 Pages에 배포하지 않습니다.
