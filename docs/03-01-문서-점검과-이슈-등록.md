# 03-01. 문서 점검과 이슈 등록

[이전](02-03-기술-설계.md) · [전체 목차](00-전체-실습-안내.md) · [다음: 첫 게임 구현](04-01-첫-게임-구현.md)

## 이번 실습

승인한 문서를 **문서 PR로 main에 먼저 병합**한 뒤 기본 게임 M1~M3 이슈를 만듭니다.
이 순서가 있어야 main에서 시작하는 각 이슈 세션도 설계를 읽을 수 있습니다.
문서마다 이슈를 만들거나 승인 기록 파일을 여러 개 만들지 않습니다.

## 시작 전

- 문서 세션에 `AGENTS.md`, `ideation.md`, `PRD.md`, `TRD.md`가 있습니다.
- 현재 브랜치는 main과 공통 이력이 있는 문서 브랜치입니다.
- 02-02·02-03에서 기준 자료와 실제 PRD·TRD의 반영 위치를 대조했습니다.
- App **Plan**에서 문서 정합성과 공개 범위를 확인합니다.

## 먼저 문서 검토

같은 문서 대화에 전달한 02-02 공통 기본값·플랫폼 범위와 02-03 기술 선택 자료를 사용합니다.
새 대화이거나 자료를 확인할 수 없다면 해당 절들을 다시 복사해 아래 프롬프트와 함께 전달합니다.
문서 존재 여부만으로 완료를 판단하지 않고, 입력 자료와 실제 작성 내용을 대조합니다.

**모드: Plan**

```text
내 개발 문서의 누락·충돌·과도한 중복을 점검해 줘.
우주 방어의 기본 범위와 수용 기준이 일치하는지 확인해 줘.
전달한 공통 기본값·플랫폼 범위·기술 선택 자료와 실제 PRD·TRD를 항목별로 대조해 줘.
자료를 확인할 수 없으면 필요한 자료를 알려 주고 멈춰 줘.
PRD에 화면·개체 크기·위치·속도·발사 간격·편대·점수·목숨·방어선 수치가 확정됐는지 봐 줘.
불일치·미정 수치가 남아 있으면 해당 문서·절·요구사항 ID와 보완 항목을 알려 줘.
AGENTS가 이후 코드 작업을 막지 않는지, 비밀·사용자 작업 보호가 있는지 봐 줘.
필요한 최소 수정과 main 대상 문서 PR의 변경 범위를 제안해 줘.
아직 파일·코드·이슈 변경이나 원격 작업은 하지 마.
```

App **Interactive**로 전환해 필요한 수정만 실행하고 diff를 확인합니다.

**모드: Interactive**

```text
검토한 문서 보완안을 승인해. 승인된 수정만 실행하고 변경을 보여 줘.
필수 수치의 미정·누락이나 승인한 기술 선택과의 충돌이 남으면 PR을 만들지 말고 알려 줘.
검토된 문서만 한국어 커밋으로 남기고 원격 문서 브랜치에 푸시해 줘.
base가 main인 문서 PR을 만들고 링크를 알려 줘. 병합 전에는 멈춰 줘.
```

App의 PR 화면 또는 GitHub 웹에서 base·파일·비밀 유무를 확인합니다.
사람이 PR 내용을 검토해 병합해도 된다고 판단한 뒤에만 다음 프롬프트를 전달합니다.

**모드: Interactive**

```text
검토한 문서 PR을 지금 병합해 줘.
병합 대상이 base main인 문서 PR인지 다시 확인하고, 다른 PR이나 main의 직접 변경은 하지 마.
병합이 완료된 뒤 원격 main에서 내 문서가 실제 보이는지 확인해 줘.
검사나 보호 규칙으로 병합할 수 없으면 기다리지 말고 현재 상태와 필요한 조치를 알려 줘.
```

이 프롬프트를 실행한 뒤 병합 결과와 GitHub main의 문서 반영을 확인합니다.
검사나 보호 규칙이 있다면 그 결과를 확인합니다. 직접 main 덮어쓰기는 대안이 아닙니다.

## 그다음 기본 게임 이슈 등록

**모드: Interactive**

```text
앞 단계에서 문서 PR이 병합됐고 원격 main에 내 문서가 있는지 먼저 확인해 줘.
검토한 PRD·TRD가 원격 main에 반영됐고 필수 수치와 기술 선택이 확정됐는지 확인해 줘.
미정·누락이나 기술 충돌이 남으면 이슈 생성 전에 보완 항목을 알려 주고 멈춰 줘.
기존 '우주 방어 기본 게임' 또는 M1·M2·M3 이슈가 있으면 중복 생성하지 말고,
기존 링크·진행 상태와 재사용 또는 분할 방안을 알려 준 뒤 승인을 기다려 줘.
확인되면 아래 기본 게임 이슈 3개를 각각 만들어 줘.

1. '우주 방어 M1: 시작·이동·발사'
   - TRD의 화면 구현 방식과 title/playing 상태, 시작 버튼·Enter, 플레이어 이동·경계,
     Space 발사와 입력 정리를 다뤄 줘.
2. '우주 방어 M2: 적·전투·승패'
   - 적 편대, 적 이동·하강·발사, 플레이어·적 탄환 충돌, 점수,
     피격·목숨·자동 다음 시도, 승패·재시작을 다뤄 줘.
   - M1 이슈의 PR이 main에 병합된 뒤 시작해야 한다고 명시해 줘.
3. '우주 방어 M3: App 설정·README·로컬 검증'
   - App 설정, README, 로컬 실행과 실제 검증 결과를 다뤄 줘.
   - M2 이슈의 PR이 main에 병합된 뒤 시작해야 한다고 명시해 줘.

각 이슈 본문은 목표·범위·완료 점검·main의 관련 문서 링크·선행 이슈를 포함해
간단히 구성해 줘. 각 이슈는 독립된 작업 범위와 PR로 진행한다고 명시해 줘.
PRD의 요구사항 ID와 관찰 가능한 완료 조건을 각 이슈 범위에 연결해 줘.
M2에는 생성된 M1 이슈 링크를, M3에는 M2 이슈 링크를 넣고 세 링크·번호를 알려 줘.
배포는 다음 이슈에서 진행한다고 명시하고 template 파일은 만들지 마.
아직 구현·PR 생성·병합은 하지 마.
```

실제 이슈 3개의 생성 결과와 링크·번호를 확인합니다.
먼저 M1 이슈를 열고 App **My work → 해당 issue → New session**으로 세션을 엽니다.
선택된 base는 문서가 병합된 **최신 main**이어야 합니다.
예시 기능 브랜치는 `feature-game-m1`이며 App이 접두사를 붙일 수 있습니다.
세션이 자동 시작되면 첫 요청에서 구현 전에 base·문서 확인 후 멈추게 합니다.
M1 PR이 main에 병합된 뒤 M2 이슈를 열고, M2 PR이 main에 병합된 뒤 M3 이슈를 엽니다.
각 단계는 **한 이슈·한 세션**에서 진행하며, 이전 단계의 병합 전에는 다음 단계로 넘어가지 않습니다.

## 눈으로 확인

- [ ] 문서 PR이 병합됐고 원격 main에서 네 파일을 볼 수 있습니다.
- [ ] 기준 자료와 PRD·TRD의 반영 위치를 대조했고 필수 수치의 미정·기술 불일치가 없습니다.
- [ ] 기본 게임 M1·M2·M3 이슈의 링크가 main 문서를 가리킵니다.
- [ ] 새 세션의 선택 base·현재 브랜치·문서 내용이 맞습니다.
- [ ] M1·M2·M3가 각각 독립 이슈로 등록되어 있습니다.
- [ ] 각 이슈의 완료 조건과 선행 이슈 링크를 확인했으며, 기존 이슈를 중복 생성하지 않았습니다.
- [ ] 배포 완료나 게임 구현 완료를 아직 주장하지 않았습니다.

## 이미 생성된 문서의 기준 복구

PRD에 미정 수치가 남거나 TRD의 렌더링 선택이 실습 자료와 다른 경우, M1 구현을 보류합니다.

1. 현재 코드·문서·커밋·미커밋 변경을 보존합니다. 문서 수정은 최신 main을 기준으로 한 별도 문서 브랜치·세션에서 진행합니다.
2. [02-02 공통 기본값과 플랫폼 범위](02-02-요구사항-작성.md#공통-기본값),
   [02-03 기술 선택](02-03-기술-설계.md#기술-선택) 절을 복사해 아래 Plan 프롬프트와 함께 전달합니다.
3. 기존 요구사항 ID와 유효한 결정을 보존한 수정안을 검토합니다. 원래 자료로 결정할 수 없는 항목은 별도로 확인합니다.

**모드: Plan**

```text
AGENTS.md·PRD.md·TRD.md와 기존 M1 이슈를 읽고 함께 전달한 실습 기준 자료에 대조해 줘.
자료나 문서를 읽을 수 없으면 필요한 자료를 알려 주고 멈춰 줘.
누락·미정·불일치별로 문서·절·요구사항 ID와 최소 수정안을 보여 줘.
기존 ID·유효한 게임 규칙·작업 이력은 보존하고, 기준 자료로 확정할 수 없는 항목은 따로 알려 줘.
기존 M1 이슈에도 보완이 필요한지 구분해 줘.
문서 보완 승인·PR 검토·병합 후 M1 계획을 재개하는 순서만 제안해 줘.
아직 파일·코드·이슈 변경, 설치, 커밋·푸시·PR·병합은 하지 마.
```

4. 승인한 문서 수정은 위 **문서 보완·PR 생성 → 사람 검토 → 병합 승인** 프롬프트로 진행합니다.
   이슈 수정은 별도로 검토·승인하며, 기존 이슈를 삭제하거나 3개 이슈 등록을 반복하지 않습니다.
5. 보완 PR의 실제 병합과 원격 문서 반영을 확인한 뒤, 최신 main을 포함하는 M1 세션에서
   [04-01의 Plan](04-01-첫-게임-구현.md#구현-계획)을 다시 실행합니다. 기존 작업을 강제로 덮어쓰지 않습니다.

## 세션 기준이 맞지 않을 때

**모드: Plan**

```text
이슈 세션의 base와 현재 문서가 최신 main에 해당하는지 다시 확인해 줘.
오래된 세션이면 작업을 보존하고 App에서 올바른 새 세션을 여는 방법을 알려 줘.
강제 전환·브랜치 이름 변경·강제 푸시는 하지 마.
```

## 완료

설계는 원격 main에, 구현 요청은 이슈에 보존됐습니다.
새 M1 이슈 세션에서 04-01을 시작합니다.
