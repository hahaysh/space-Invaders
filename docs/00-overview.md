# 00. 전체 실습 안내

[저장소 안내](../README.md) · [참고 자료](../REFERENCES.md)

> **확인 범위:** 문서와 로컬 실행 검증, 실제 app 조작, 원격 배포는 구분합니다. 최신 완료 상태는 [저장소 안내](../README.md)와 샘플 검증 기록을 확인하세요.

## 학습 목표

GitHub Copilot app으로 Space Invaders를 만들면서 다음 과정을 경험합니다.

1. 개발 문서의 역할을 정의하고 실제 파일로 작성합니다.
2. 모호한 아이디어를 확인 가능한 요구사항과 기술 설계로 바꿉니다.
3. 구현 전에 설계를 점검하고 작은 작업 계획을 승인합니다.
4. 게임을 구현하고 요구사항에 따라 테스트합니다.
5. GitHub Actions로 GitHub Pages에 배포합니다.
6. 사용자 피드백으로 일시정지·재개를 추가하고 다시 검증·배포합니다.

원본과 문장이나 코드가 같은 결과를 만드는 것이 목표가 아닙니다. **합의한 수용 기준을 충족하고 그 근거를 설명할 수 있어야 합니다.**

## 시작점과 작업 환경

- 참가자는 GitHub에서 새 **Public** 저장소를 만듭니다.
- README, `.gitignore`, 라이선스 파일을 자동 생성하지 않고 프로젝트 파일 없는 상태를 목표로 합니다.
- 이 저장소를 Copilot app에 프로젝트로 추가합니다. 실습 안내 저장소를 복제하지 않습니다.
- 초기 커밋 없는 저장소의 app 연결 절차는 리허설 전입니다. 지원을 가정하지 않으며, 01-01에서 실제 동작과 필요한 최소 준비 절차를 안내할 예정입니다.
- 기본 작업 환경은 로컬 Copilot app 세션입니다. Cloud agent, CLI, VS Code 사용은 필수가 아닙니다.
- GitHub 웹에서 저장소 생성·Pages 설정·권한 등을 확인하고, 게임 확인에는 app의 브라우저 미리보기 또는 일반 브라우저를 사용합니다.
- 기본 과정은 같은 작업 세션에서 진행합니다. 세션을 바꾸어야 한다면 변경 파일이 있는 브랜치와 작업 공간을 먼저 확인합니다.

필요한 준비 사항은 GitHub 계정, Copilot app 사용 권한, Git, Node.js 24 LTS, 최신 브라우저와 네트워크입니다. 실제 버전·명령 확인은 01-01에서 수행합니다.

## 공통 게임과 기술 경로

| 구분 | 기본 경로 |
|---|---|
| 게임 화면 | HTML·CSS·JavaScript, Canvas 2D |
| 실행·빌드 | Vite 개발 서버와 정적 사이트 빌드 |
| 테스트 | Node 내장 테스트로 게임 규칙 확인, Playwright로 브라우저 동작 확인 |
| 배포 | GitHub Actions에서 테스트·빌드 후 GitHub Pages 배포 |
| 최초 버전 | 시작, 좌우 이동, 발사, 적 편대 이동·하강, 충돌, 점수, 승리·패배, 재시작 |
| 개선 버전 | P 키 일시정지·재개, 정지 중 상태 유지, 재개 시 시간·입력 처리 |
| 기본 범위 밖 | 온라인 순위, 로그인, 모바일 조작, 사운드, Community Hub 연결 |

정확한 점수·속도·적 수·종료 조건은 PRD에서 결정하고 테스트 가능한 수치로 기록합니다. 테마와 색상은 선택할 수 있지만, 기본 경로의 기능·기술을 크게 변경하면 이후 절차도 조정해야 합니다.

Vite와 테스트 도구는 개발용 의존성입니다. 배포된 게임은 외부 게임 엔진, CDN 스크립트, 이미지 서버 없이 실행하도록 설계합니다. Pages의 저장소 하위 경로에 대응하며 배포 아티팩트에는 게임 빌드 결과만 포함합니다.

## 한 단계의 진행 방법

1. 설명을 읽고 시작 상태를 확인합니다.
2. 안내한 모드를 선택하고 프롬프트를 입력합니다.
3. 질문이 나오면 참가자가 답합니다. AI가 중요한 결정을 임의로 확정하지 않도록 합니다.
4. 문서·diff·게임 화면·테스트 결과를 직접 확인합니다.
5. 보완할 점을 요청하고 다시 확인합니다.
6. 완료 기준을 충족한 경우 승인합니다. 에이전트가 다음 단계를 자동 실행하지 않게 합니다.

Plan은 계획 검토용, Interactive는 승인한 문서·코드 작업용으로 사용합니다. 모드 선택만으로 모든 행동이 제한된다고 가정하지 않고 프롬프트에도 변경 범위와 중단 지점을 적습니다. 초보자 기본 과정에서는 Autopilot을 사용하지 않습니다.

`AGENTS.md`의 자동 적용·갱신은 대상 app에서 확인해야 합니다. 생성 또는 수정한 직후에는 명시적으로 해당 파일을 읽고 규칙을 요약하게 합니다. 이는 자동 지침 로딩이 확인되었다는 뜻은 아닙니다.

## 기록·공개·검증 원칙

- 요구사항 ID를 설계·구현 작업·테스트와 연결합니다.
- 참가자도 단계별 변경을 검토한 뒤 한국어 제목·본문의 커밋을 남깁니다. 단계 번호, 변경 내용·이유, 확인 결과와 미확인 사항을 적습니다. 파일 변경이 없는 논의 단계에는 불필요한 빈 커밋을 만들지 않습니다.
- 로컬 커밋과 원격 푸시는 다릅니다. Public 저장소에 게시할 내용과 대상 브랜치를 확인하고 푸시합니다.
- 세션 브랜치의 변경은 PR로 검토하고 `main`에 병합한 뒤 배포하는 흐름을 사용합니다. 최초 저장소 부트스트랩 절차는 별도로 다룹니다.
- API 키, 토큰, 개인 정보는 프롬프트 예시·문서·코드·로그에 넣지 않습니다.
- 테스트 통과, 로컬 브라우저 확인, 공개 URL 확인은 별도 항목입니다. 수행하지 않은 확인은 `미확인`으로 남깁니다.

## 참고 샘플

최초·개선 버전의 상태와 실행 방법은 [샘플 안내](../src/game-samples/README.md)를 확인합니다. 샘플은 문서 기준으로 수행한 자동 산출물 리허설이며, 참가자가 모든 프롬프트를 입력하고 app UI에서 승인한 과정까지 재현했다는 의미는 아닙니다.

샘플은 정답이나 시작 템플릿이 아닙니다. 참가자가 막혔을 때 문서와 구현의 연결을 살펴보고, 두 번째 사이클에서 무엇이 달라졌는지 비교하는 참고 자료입니다.
