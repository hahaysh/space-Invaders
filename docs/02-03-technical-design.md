# 02-03. 구현과 검증을 위한 기술 설계

**2. 게임 설계 · `TRD.md` 작성**

이전: [02-02 제품 요구사항](02-02-product-requirements.md) · [전체 목차](00-overview.md) · 다음: [03-01 문서 점검](03-01-document-review.md)

## 1. 설명

TRD는 PRD의 요구사항을 **어떤 구조와 처리 순서로 구현하고 검증할지** 설명합니다.
이번에는 기술을 비교하느라 범위를 늘리지 않고 공통 스택을 사용합니다.
브라우저·입력 처리와 순수 게임 규칙을 분리하면, 기다리거나 화면을 조작하지 않고도 규칙을 테스트할 수 있습니다.

## 2. 시작 상태

- [ ] `AGENTS.md`, `ideation.md`, 승인한 `PRD.md`가 있다.
- [ ] REQ-01~08과 수치·상태 전환에 구현을 막는 미결정이 없다.
- [ ] Node.js 24 LTS 준비 상태를 확인했다. 이번 단계에서는 도구를 설치하지 않는다.
- [ ] Copilot app의 **Plan** 모드를 선택했다.

## 3. 실행: 설계 검토 후 문서화

### 3-1. Plan에서 구조 제안받기

```text
AGENTS.md, ideation.md, PRD.md를 읽고 TRD.md 초안을 대화에 제안해줘.
파일 변경·패키지 설치·코드 구현·커밋·푸시 없이 설계만 한다.
각 설계 항목을 REQ-01~08에 연결하고 PRD 수치를 임의로 바꾸지 마.

기술은 Node.js 24 LTS, vanilla HTML/CSS/ES module JavaScript, Canvas 2D,
Vite dev/build/preview, node --test, Playwright로 고정한다.
런타임 CDN·게임 엔진·외부 에셋 서버는 쓰지 않는다.
파일 책임과 데이터 흐름은 다음 경로로 설계해줘.
- index.html: Canvas, 접근 가능한 시작/재시작 버튼·상태·점수 DOM
- src/game.js: DOM·RAF·실시간 시계 없는 순수 시뮬레이션
- src/main.js: DOM 연결, 키 입력, Canvas 렌더링, 단 하나의 RAF 루프
- src/styles.css: 화면 스타일
- tests/game.test.js: 결정적인 dt·입력·상태를 사용하는 Node 테스트
- e2e/game.spec.js, playwright.config.js: 사용자 입력과 DOM 관찰 테스트
- vite.config.js: base './'로 하위 경로 에셋 지원
- package.json, package-lock.json, .gitignore: 스크립트·의존성·생성물 관리

package.json은 ES module 방식으로 한다.
scripts는 dev: vite, build: vite build, preview: vite preview,
test: node --test tests/*.test.js, test:e2e: playwright test로 설계한다.
Node 테스트의 명시적 선택자로 e2e 자동 탐색을 피하고 Windows에서도 같은 명령을 쓴다.
최초 npm install은 package.json 작성 뒤, lockfile 생성 후 재현 설치는 npm ci다.
개발 의존성은 Node24 호환 안정 버전을 확인해 정확히 고정하며 latest를 안정판으로 가정하지 않는다.
Playwright 의존성 설치 뒤에만 npx playwright install chromium을 실행한다.
아직 어떤 명령도 실행하거나 의존성을 설치하지 마.

TRD에는 상태·입력·갱신·충돌·종료·재시작의 처리 순서와 의사코드를 적어줘.
입력은 playing에서만 이동·발사에 반영하고 blur와 상태 전환에서 눌린 키를 비운다.
RAF timestamp에서 초 단위 dt를 구하고 상한값을 정해 긴 프레임의 점프를 제한한다.
시작·재시작·포커스 복귀 때 이전 시간을 초기화하며 RAF를 추가 생성하지 않는다.
이동/발사 대기시간은 시뮬레이션 dt만 사용하고 벽시계나 setInterval에 의존하지 않는다.
큰 dt·빠른 탄환이 적을 통과하지 않도록 dt 상한과 세부 갱신 또는 충돌 설계를 설명해줘.
한 탄환은 적 하나만 제거하며 여러 탄환이 같은 적을 중복 득점하지 않게 한다.
재시작은 초기 상태 생성 함수를 재사용해 모든 판 상태를 초기화한다.
최초 버전에는 paused 상태나 P 키 기능을 구현 대상으로 넣지 마.
후속 CHG-01의 별도 참고에는 P로 playing/paused만 전환, 키 반복 무시,
정지 중 시뮬레이션·발사 대기시간 동결과 재개 시 시간·입력 초기화를 적어줘.

순수 테스트의 함수 경계와 브라우저 테스트의 관찰 지점을 정해줘.
운영 코드에 window 상태 조작·즉시 승리 같은 테스트 전용 치트를 노출하지 않는다.
승패 경계는 순수 상태 테스트로, 실제 브라우저 사용자 흐름은 UI로 확인한다.
Playwright webServer가 127.0.0.1:5173 또는 :4173 서버를 관리하고
baseURL과 같은 포트를 사용하게 한다. 기존의 모르는 서버를 종료하거나 재사용하지 않는다.
서버 명령·포트 충돌 대응·종료 책임도 적어줘.

나중에 배포하는 것은 dist뿐이다. 상대 base는 에셋 경로를 위한 설정이다.
단계 06에서 작업 브랜치 PR을 main에 병합하고 Actions의 main push 또는
workflow_dispatch로 배포한다. PR에서는 검사만 하며 기능 브랜치 push가 배포는 아니다.
지금 워크플로 파일을 만들지 마.
미결정 사항과 설계상 위험을 정리하고 내 검토를 기다려줘.
```

참가자는 제안된 함수 이름을 외우기보다 “어느 함수가 브라우저 없이 실행되는가?”를 확인합니다.
dt 상한·세부 갱신 간격은 숫자와 근거까지 검토합니다. PRD의 발사 간격을 다른 값으로 바꾸면 안 됩니다.

### 3-2. Interactive에서 TRD 작성하기

```text
방금 검토한 기술 설계를 승인한다.
AGENTS.md를 읽고 저장소 루트 TRD.md만 작성해줘.
REQ별 설계 연결, 파일 책임, 상태·시간·입력·충돌 처리,
테스트 전략, 명령과 설치 순서, 정적 배포 제약을 포함해줘.
명령은 향후 실행 계획으로 적고 실제 설치·테스트 성공이라고 기록하지 마.
다른 파일 작성·코드 구현·설치·커밋·푸시 없이 diff를 보여주고 멈춰줘.
```

### 예상 결과

- 구현 파일별 책임과 데이터 흐름이 명확한 `TRD.md`.
- 재시작·프레임 지연·입력 해제·충돌 경계 설계.
- 순수 테스트와 브라우저 테스트, 이후 배포 절차를 구분한 검증 전략.

## 4. 함께 점검·확인

| 점검 항목 | 충족 기준 |
|---|---|
| 추적 가능성 | 모든 REQ가 하나 이상의 설계·검증 항목으로 이어진다. |
| 순수 규칙 | `src/game.js`가 DOM·RAF·현재 시각 없이 실행 가능하다. |
| 시간과 입력 | 초 단위 dt, 긴 프레임 제한, blur/전환 시 키 해제, 단일 RAF가 있다. |
| 재현성 | manifest → 최초 설치 → lockfile → 이후 npm ci 순서다. |
| 테스트 분리 | Node 선택자가 `tests/*.test.js`이며 E2E는 Playwright로만 실행한다. |
| 정적 전달 | `base: './'`, `dist` 전용 배포, 외부 런타임 의존성 없음이 명시되어 있다. |

```text
Plan에서 PRD.md와 TRD.md를 읽기 전용으로 대조해줘.
REQ별 설계 누락과 수치 충돌, 시간·입력·중복 충돌 위험을 근거와 함께 평가해줘.
충족/보완 필요/미확인으로 구분하고, 설계 검토를 실행 테스트 통과로 쓰지 마.
```

## 5. 보완과 재확인

```text
Plan에서 순수 게임 규칙에 DOM이나 실시간 시계가 섞인 설계를 분리해줘.
RAF가 중복 생성되거나 포커스 복귀 시 점프하는 경로도 찾아 수정안을 제안해줘.
기술 스택과 PRD는 유지하고 TRD의 수정 대상 절만 보여줘. 아직 파일은 수정하지 마.
```

승인한 수정안은 Interactive에서 `TRD.md`에만 반영한 뒤 같은 기준으로 재검토합니다.
PRD 자체를 바꿔야 한다면 설계로 몰래 덮지 말고 요구사항 변경부터 별도 승인합니다.

## 6. 완료 승인

- [ ] 설치나 실행을 하지 않았고 TRD 변경만 확인했다.

```text
TRD.md를 승인한다. 검토한 TRD.md만 커밋하고 결과를 알려줘.
메시지는 너무 짧지 않은 한국어 설명형 제목과 본문으로 작성하고,

```
