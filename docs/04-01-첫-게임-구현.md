# 04-01. 첫 게임 구현

[이전](03-01-문서-점검과-이슈-등록.md) · [전체 목차](00-전체-실습-안내.md) · [다음: 핵심 게임 완성](04-02-핵심-게임-완성.md)

## 이번 실습

기본 게임의 **M1 이슈와 독립 세션**에서 `IMPLEMENTATION_PLAN.md`를 먼저 만듭니다.
그다음 M1의 시작·이동·발사만 구현해 실제 브라우저에서 확인합니다.
M1에는 아직 적이 없으므로 승패와 점수를 완료했다고 기록하지 않습니다.

## 시작 전

- 기본 게임 M1 이슈에서 연 새 세션이며 문서가 병합된 main이 base입니다.
- 현재 기능 브랜치에서 내 개발 문서가 보입니다.
- 03-01에서 PRD의 필수 수치와 TRD의 기술 선택을 확정하고 문서 간 정합성을 확인했습니다.
- App **Plan**에서 구현 순서를 정합니다.

## 구현 계획

제품 수치·동작은 참가자 저장소의 `PRD.md`, 기술 선택은 `TRD.md`를 기준으로 합니다.
M1 프롬프트와 계획 문서에 같은 기준을 다시 정의하지 않습니다.
실습 기준의 누락이나 잘못된 기술 선택은 02-02·02-03·03-01에서 문서를 보완할 문제이며,
구현 프롬프트로 문서를 덮어쓰거나 다른 결정을 강제하지 않습니다.

**모드: Plan**

```text
기본 게임 M1 이슈와 관련 개발 문서를 읽어 줘.
현재 base/브랜치가 승인 문서를 포함하는지 먼저 확인해 줘.
M1 시작/이동/발사의 요구사항 ID·문서 참조·예상 변경·실제 확인 방법을 짧은 표로 제안해 줘.
IMPLEMENTATION_PLAN.md를 먼저 작성한 뒤 M1만 구현하는 순서로 계획해 줘.
M2·M3는 후속 이슈로 남겨 줘.
진행을 막는 문서 누락·충돌이나 base 문제가 있으면 해당 근거를 보고하고 멈춰 줘.
아직 파일 변경·설치·원격 작업은 하지 마.
```

누락·충돌이 보고되면 아래 구현 프롬프트로 넘어가지 않고
[03-01의 기준 복구 절차](03-01-문서-점검과-이슈-등록.md#이미-생성된-문서의-기준-복구)로 문서를 먼저 보완합니다.

계획은 초보자가 화면에서 확인할 수 있는 단위면 충분합니다.
M1에서 적·일시정지·선택 확장을 한꺼번에 구현하는 제안은 줄입니다.
구현 계획의 상태는 예정·진행·실제 완료를 구분합니다.

## 승인 후 M1 실행

App을 **Interactive**로 바꿉니다.

**모드: Interactive**

```text
계획을 승인해. IMPLEMENTATION_PLAN.md를 먼저 만들고 M1만 구현해 줘.
단, 문서의 필수 수치·기술 선택에 미정·누락·충돌이 남아 있으면 변경·설치 전에 알려 주고 멈춰 줘.
TRD에서 확정한 렌더링·실행 방식으로 title에서 시작해 이동·발사되게 해 줘.
PRD의 크기·좌표·탄환 출발점·간격·경계·입력 규칙을 사용해 줘.
호환되는 안정판 의존성과 실제 scripts를 package.json에 먼저 정의한 뒤 설치해 줘.
lockfile을 남기고 생성물·node_modules는 추적하지 않게 해 줘.
TRD의 규칙 검사와 실제 브라우저 확인을 실행하고 미구현 범위는 구분해 줘.
dev 서버는 TRD의 포트로 시작하고 해당 세션이 관리하며 URL·PID·응답을 확인해 줘.
적이나 승패는 아직 넣지 말고 diff와 실행 결과를 보여 준 뒤 멈춰 줘.
```

App이 제시한 설치·실행 명령을 읽고 필요한 권한만 승인합니다.
서버가 “시작됨”이라고만 하지 않고 실제 URL이 응답하는지 확인합니다.
화면은 App 브라우저나 일반 브라우저로 열고 버튼·키를 직접 사용합니다.
탄환은 플레이어 위에서 출발해 위로 이동해야 합니다.

## 눈으로 확인

- [ ] PRD·TRD·M1 이슈의 기준을 참조했으며 수치·기술을 다시 정의하지 않았습니다.
- [ ] 계획 파일이 구현 전에 작성됐고 M1 범위와 후속 이슈 경계가 적혀 있습니다.
- [ ] 제목 화면에서 시작 버튼·Enter로 게임이 시작됩니다.
- [ ] 좌우 입력·경계·Space 발사가 PRD대로 동작합니다.
- [ ] manifest·lockfile이 있으며 실제 검사 결과와 미구현 항목이 구분됩니다.
- [ ] 실행 중인 서버의 세션·포트·URL을 알고 있으며 적은 아직 없습니다.

## 필요할 때만 보완

**모드: Interactive**

```text
방금 확인한 M1의 실패 동작을 재현하고 관련 부분만 수정해 줘.
실제 검사를 다시 실행하고 결과를 계획 표에 반영해 줘. M2는 시작하지 마.
```

포트 충돌이면 소유자를 확인합니다. 모르는 프로세스를 종료하지 않습니다.
테스트가 통과했다면 실패를 일부러 만들거나 테스트 수를 맞추지 않습니다.

## M1 PR 생성

M1 범위의 diff와 실제 결과를 확인한 뒤 원격 작업을 승인합니다.

**모드: Interactive**

```text
M1 완료 근거와 M2·M3 미구현 범위를 IMPLEMENTATION_PLAN.md에 기록해 줘.
M1 이슈의 완료 조건을 충족했는지 확인하고, 미충족이면 남은 항목을 알려 주고 멈춰 줘.
충족했다면 검토한 파일만 한국어 커밋으로 남기고 현재 기능 브랜치에 푸시해 줘.
main 대상 M1 PR을 만들고 실제 검사·미확인을 적어 줘.
M1 이슈만 Fixes로 연결하고 PR 링크를 알려 줘. 병합 전에는 멈춰 줘.
M2·M3 구현이나 배포는 하지 마.
```

## 검토 후 M1 병합

사람이 PR의 base·diff·검사·비밀 유무를 검토하고 승인한 뒤에만 전달합니다.

**모드: Interactive**

```text
검토한 main 대상 M1 PR의 병합을 승인해. 해당 PR만 병합해 줘.
필수 검사·보호 규칙·권한 문제로 병합할 수 없으면 우회하지 말고 상태와 필요한 조치를 알려 줘.
실제 병합 여부와 원격 main의 M1 코드·계획 문서 반영, M1 이슈 종료 여부를 확인해 줘.
M2·M3 이슈는 닫지 말고 이 세션에서 다음 구현을 시작하지 마.
```

## 완료

- [ ] M1 PR의 실제 병합과 원격 main 반영, M1 이슈 종료를 확인했습니다.

병합이 확인된 뒤 App **My work → M2 이슈 → New session**에서 최신 main을 선택합니다.
새 M2 기능 브랜치에서 04-02를 시작합니다. 기존 M1 세션이나 브랜치를 재사용하지 않습니다.
M1 서버가 남아 있으면 해당 세션에서 소유한 서버만 정상 종료하고 새 세션의 서버와 혼동하지 않습니다.
